# 首页三栏设计规范

> 适用版本：**V1.3.0 起** ｜ 关联规划：`V1.3.0-业务深度与新模块.md` §6.1
> 本文定义首页「工作组 / 生活组 / 知识组」三栏的栅格、配色、卡片与数据刷新契约，作为 V1.4+ 视觉重构与卡片接口变动的**唯一基准**。

---

## 1. 设计目标

- 把「工作 / 生活 / 知识」三组的最小可用集在首页一次性呈现，用户打开即见全局进度。
- 旧版首页的「今日计划 / 明日计划 / 备忘 / 快捷入口」4 卡片布局已**彻底移除**，不再保留兼容层。
- 三栏视觉上彼此区分（标题 + 图标 + 浅色背景条），数据由各模块列表接口汇聚，不各自维护副本。

---

## 2. 三栏布局与配色

| 栏位 | 分组 | 图标 | 背景色变量 | 语义色 |
| --- | --- | --- | --- | --- |
| 左栏 | 💼 工作组 | 💼 | `--color-work-bg` | 蓝（工作专注） |
| 中栏 | 🌱 生活组 | 🌱 | `--color-life-bg` | 绿（生活节律） |
| 右栏 | 📚 知识组 | 📚 | `--color-knowledge-bg` | 紫（知识沉淀） |

- 三组背景色均为**浅色半透明条**（基于 Liquid Glass 令牌），叠在背景墙上透出底色，不与栏内卡片玻璃冲突。
- 具体色值以 `frontend/css/*.css` 中的 CSS 变量为准；修改配色只允许改令牌，不允许在组件内硬编码 hex。

---

## 3. 栅格断点

| 视口宽度 | 布局 |
| --- | --- |
| `≥ 1280px`（桌面） | 三栏**等宽并排**，栏间 24px |
| `< 1280px`（窄屏 / 平板） | 三栏**垂直堆叠**，整页滚动，单栏内卡片仍可横向留白 |

- 断点变量集中定义，禁止在组件写死 `1280` 以外的媒体查询。
- 折叠 / 展开态下三栏顺序固定：工作 → 生活 → 知识。

---

## 4. 卡片规范

### 4.1 数量与高度

- 每栏固定 **3–5 张卡片**；数据不足时用**空态占位卡片**补齐到最少 3 张，避免栏高塌陷。
- 同一栏内卡片**高度对齐**：以最高卡片撑满，其余卡片底部留白（非拉伸内容）。
- 卡片内容超出时**折叠 + 「查看全部」**，点击跳转到对应模块列表页（`URL` 带筛选参数，复用 `useSearchParams`）。

### 4.2 间距

| 位置 | 间距 |
| --- | --- |
| 栏内卡片间距 | `16px` |
| 栏与栏之间 | `24px` |
| 卡片内边距 | `16px`（与全局 `--space-card` 对齐） |

### 4.3 视觉

- 卡片复用 Liquid Glass 令牌（`.htp-card` 玻璃化），标题区带分组图标 + 浅色背景条。
- 状态点 / 进度条复用 `StatusDot` / `HtpProgress`，色值读 CSS 变量，不内联。

---

## 5. 空态占位卡片样式

- 当某模块无数据时，渲染与正常卡片**同尺寸同圆角**的占位卡，内容两段式：
  - `title`：如「还没有进行中的项目」
  - `actionText`：如「去项目页新建一个？」
- 占位卡不可点击跳转（或跳转至新建页），不显示虚假数字。
- 占位卡背景比正常卡更淡（玻璃透明度更低），明确区分「无数据」与「有数据」。

---

## 6. 数据来源映射

| 栏位 | 卡片 1 | 卡片 2 | 卡片 3 | 卡片 4（可选） | 卡片 5（可选） |
| --- | --- | --- | --- | --- | --- |
| 工作栏 | 今日任务进度（已完成 N / 总数 M 进度条） | 明日待安排计数 | 进行中项目 3 个（名称 + 阶段色点） | 会议纪要（最近 2 次主题 + 时间） | 凭据 7 天内到期 N 条 |
| 生活栏 | 今日待打卡习惯 3 个（名称 + 未打卡状态点） | 连续打卡最长天数 N 天 | 今日番茄钟（已完成 K / 目标 L） | 本月财务净流入（收入-支出，带方向箭头） | — |
| 知识栏 | 本周沉淀 N 条（草稿 / 已沉淀分类计数） | 充电学习中 3 个（名称 + 进度%） | 推荐待写沉淀 3 条（见沉淀模块设计 §首页推荐算法） | — | — |

- 每张卡片的数据来自对应模块的 **list / summary / stats** 接口（后端已提供：`finance.getMonthlySummary`、`habit.getStats`、`timeBlock.getStats`、`meeting.list`、`vault.list` 等）。
- 卡片不缓存业务数据，统一经由首页聚合接口或并行调用各模块列表接口获取。

---

## 7. 数据刷新时机

1. **打开首页**：进入首页路由时刷新一次全量三栏数据。
2. **后台静默刷新**：首页驻留时每 **5 分钟** 静默重新拉取（不弹 Toast、不打断操作），刷新失败静默忽略。
3. **离开即停**：路由切走时清除刷新定时器，避免后台空转。
4. **写后即时**：用户在对应模块完成新增 / 删除后返回首页，下次进入按规则 1 重新拉取（不依赖长连接）。

---

## 8. 对账一致性规则

- 首页卡片数字 **必须等于** 对应模块列表接口的计数（允许 ±1 的显示延迟，如「今日任务进度」与「今日计划页总数」在写操作瞬间最多差 1）。
- 对账不一致时以**模块列表接口为准**，首页数字为派生展示；禁止首页维护独立计数源。
- 「查看全部」跳转后，目标页的筛选结果与首页卡片点击前展示的数字须可对应（如首页「本周沉淀 5 条」→ 跳转后列表显示 5 条）。

---

## 9. 验收清单（首页三栏）

- [ ] 桌面 1920×1080 下三栏并排，每栏卡片 ≤5 张，高度对齐（最高卡片撑满）
- [ ] 刷新页面后三栏数据正确对应各模块（今日任务数 = 今日计划页总条目数，对账一致）
- [ ] 「查看全部」点击跳转对应模块，URL 正确带筛选参数
- [ ] 1100px 窄屏截图：三栏堆叠滚动不超出视口
- [ ] 三栏背景色与 CSS 变量 `--color-*-bg` 完全一致（取色器比对）
