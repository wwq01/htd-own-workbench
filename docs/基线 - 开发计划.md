# 荒天帝工作台 第一版可执行开发计划

## 一、开发计划总览

### 1.1 计划说明

本计划基于「Node.js 24 LTS + Express + Prisma + SQLite」后端架构、「Vue 3 无构建运行时」前端架构制定，严格对齐 PRD 功能范围与视觉设计规范，所有任务按依赖关系排序，可逐阶段落地执行，每个阶段均设置可量化的验收标准。

### 1.2 总工期预估

单人开发总周期约 **10 个工作日**，核心业务模块优先交付，可根据实际进度灵活调整各阶段时长。

### 1.3 核心开发原则

1. **分层解耦**：严格遵循后端分层架构、前端组件化规范，模块间高内聚低耦合，修改单模块不影响全局
2. **数据优先**：先定义数据模型、落地接口能力，再开发前端页面，保证数据驱动开发
3. **逐模块验收**：完成一个模块、验收一个模块，避免问题集中堆积
4. **纯离线可用**：所有依赖本地引入，无外部 CDN、无联网接口，全程本地运行
5. **扩展预留**：代码架构预留扩展位，支持后续平滑升级桌面端、工程化、加密等能力

### 1.4 最终交付物

1. Windows 平台单可执行文件：`荒天帝工作台.exe`
2. 配套使用说明文档

### 1.5 当前执行状态（更新于 2026-08-10）

> 本计划中的 **阶段 0 ~ 阶段 7 已全部完成并通过验收**：后端 15 个路由模块、前端 10 个页面（PRD 9 模块 + 系统设置）全部实现，无占位空壳；测试套件 20 个文件、184/184 通过；Windows 单 exe 已构建（`build/荒天帝工作台.exe`），脱离 Node 亦可启动。本版仅交付 Windows 产物，未提供 macOS 包。本计划作为历史交付记录保留，后续迭代请另起新计划。

## 二、分阶段详细开发任务

### 阶段 0：项目初始化与基础底座搭建

**开发周期**：1.5 天
**核心目标**：搭建前后端工程骨架，封装所有通用底层能力，为业务模块开发提供完整支撑
**具体任务**：

#### 后端开发任务

1. **工程初始化**
   - 按规范创建后端目录结构，初始化 `package.json`，配置 ES 模块规范
   - 安装核心依赖：express、prisma、@prisma/client、zod、winston、cors、multer
   - 配置脚本命令：开发启动命令、数据库迁移命令、打包命令
2. **配置与通用支撑层**
   - 编写 `config/` 配置模块：自动识别操作系统，获取用户目录下的数据存储路径；配置默认端口、运行环境
   - 实现 `common/logger.js`：基于 winston 封装分级日志，支持控制台输出与本地日志文件落盘
   - 实现 `common/error.js`：自定义业务错误类、全局错误码定义
   - 实现 `common/utils/` 工具集：日期处理、文件操作、跨平台打开浏览器、端口检测与自动顺延
3. **数据库层搭建**
   - 编写 `prisma/schema.prisma`：定义全量数据表结构
     - 通用基础字段：id、createdAt、updatedAt、deletedAt（软删除）
     - 业务表：memos（全局备忘）、todos（待办事项）、projects（项目主表）、project\_milestones（项目里程碑）、project\_tasks（项目任务）、dev\_projects（开发项目）、dev\_snippets（代码片段）、dev\_issues（开发问题）、entertainments（娱乐内容）、study\_records（学习记录）、study\_pendings（待学清单）、reviews（复盘记录）、secrets（凭据信息）、deployments（部署记录）
   - 封装 Prisma 客户端单例：`database/prisma.js`，保证全局唯一数据库连接
   - 实现 `database/base.repository.js`：通用 CRUD 抽象基类，封装增删改查、筛选、排序通用方法
   - 执行数据库初始化与迁移，生成本地数据库文件
4. **全局中间件与路由框架**
   - 实现 `middleware/response.js`：统一响应格式化中间件，全局返回 `{code, msg, data}` 标准结构
   - 实现 `middleware/errorHandler.js`：全局异常捕获中间件，捕获同步 / 异步错误，统一返回错误响应
   - 实现 `middleware/requestLog.js`：请求日志中间件，记录所有接口请求信息
   - 搭建路由总入口：`app.js` 中注册中间件、挂载 `/api/v1` 前缀路由、托管前端静态资源目录
5. **启动引导与服务入口**
   - 编写 `bootstrap.js`：启动自检逻辑，校验数据目录、初始化数据库、执行迁移
   - 编写 `server.js`：端口监听逻辑，启动成功后自动调用系统默认浏览器打开应用地址
   - 主入口文件：整合启动流程，增加异常兜底处理

#### 前端开发任务

1. **工程骨架搭建**
   - 按规范创建前端目录结构，建立 css、js、assets 目录
   - 本地化引入核心依赖：将 `vue.global.prod.js`、`pinia.iife.prod.js` 放入 `assets/lib/` 目录
   - 编写入口 `index.html`：搭建左侧导航 + 顶部工具栏 + 主内容区的全局布局，引入所有依赖文件与入口 JS
2. **基础能力封装**
   - 编写 `js/api.js`：基于原生 fetch 封装统一请求方法，统一处理响应、错误提示，支持 GET/POST 请求
   - 编写 `js/router.js`：实现极简 Hash 路由，定义 10 个页面（PRD 9 模块 + 系统设置）的路由映射，支持路由参数传递、路由切换渲染
   - 编写 `js/store/` 状态管理：注册 Pinia，创建 appStore（导航状态、全局配置）、dataStore（公共数据缓存）
   - 编写 `js/app.js`：创建 Vue 应用实例，注册 Pinia，初始化路由，挂载全局布局
3. **通用 UI 组件开发**
   - `HtdButton`：主按钮、次按钮、危险按钮、文字按钮四种类型，支持 hover、禁用态
   - `HtdModal`：通用弹窗，支持标题、内容插槽、底部操作按钮、确认 / 取消回调
   - `HtdCard`：卡片容器，支持标题、内容插槽
   - `HtdInput` / `HtdTextarea`：输入框、文本域，对齐视觉规范
   - `HtdSelect`：下拉单选框，支持选项配置
   - `HtdTag`：状态标签，支持多种语义颜色
   - `HtdCheckbox`：复选框，支持勾选状态切换
   - `HtdEmpty`：空状态提示组件
4. **全局样式落地**
   - `css/global.css`：CSS 重置、全局 CSS 变量（完整对齐视觉规范的色值、字号、间距、圆角）、栅格工具类、通用布局类
   - `css/components.css`：所有通用组件的样式实现
   - `css/pages.css`：通用列表、表单布局样式，预留各页面专属样式空间

#### 本阶段验收标准

1. 执行启动命令后，服务正常启动，自动打开浏览器，页面显示完整基础布局
2. 数据库文件自动生成在系统用户目录，表结构完整无缺失
3. 调用测试接口，统一响应格式正常，全局错误捕获机制生效
4. 前端 10 个页面路由切换正常，页面无控制台报错
5. 所有通用组件可正常渲染，样式完全符合视觉规范
