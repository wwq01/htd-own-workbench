## 五、下次开发必查注意事项（踩过的坑汇总）

### 🔴 日期时间（最易踩坑）
- **绝对禁止**：`.toISOString().split('T')[0]` 格式化本地日期。在东八区（UTC+8）会偏移 1 天！
- **必须使用**：`formatDate(date)`（`backend/src/common/utils/date.js`），它使用 `getFullYear/getMonth/getDate` 本地时间方法。
- 涉及「本周/本月」范围的所有统计（system / study-record / 其他新增）都要仔细核对。

### 🔴 后端启动
- 用 `npm run dev`（或 `npm start`，二者等价）直接启动 `node src/server.js`，**无热重载**。
- 修改代码后需手动重启进程（Ctrl+C 后重跑 `npm run dev`）。
- 启动后日志应显示「荒天帝工作台已启动」+ 端口 17388。

### 🔴 前端组件
- **HtpModal 弹窗不显示**：必须同时传 `:visible="true"` + 使用 `@cancel` 事件（组件内部 emit 的是 `cancel`，不是 `close`）。
- **Vue 3 全局构建版限制**：模板中 slot 内容不能用可选链 `?.`，要封装到 setup() 函数里再在模板调用。
- **新增组件**：记得在 `index.html` `<script>` 引用，且顺序在使用它的组件/页面之前。

### 🔴 前端请求与缓存
- fetch 请求已统一加 `cache: 'no-store'`，若新增请求封装请勿删除，否则统计类接口会返回旧缓存。
- 刷新页面测试时建议用 `Ctrl + F5` 硬刷新，避免浏览器缓存旧 JS 文件。

### 🔴 数据验证
- 新模块后端记得写 Zod schema 校验（参考现有模块 `*.schema.js`），防止脏数据写入。
- 二次确认删除：所有高风险删除操作前端必须二次确认弹窗（参照 `delConfirm` 模式）。

### 🔴 数据清理
- 验收后清理测试数据：临时脚本按外键依赖顺序删（子表 → 父表），模型名参考 `prisma/schema.prisma` 中的 `model` 名称（注意大小写，Prisma JS client 用 camelCase）。
- 清理完毕**删除临时脚本文件**，保证仓库干净。

### 🔴 数据库与文件系统权限
- 沙箱可能禁止访问 `D:\荒天帝工作台\` 下的 `*.db-journal`、`*.log`、`*.db`（backup），需要写入数据库时请用 `dangerouslyDisableSandbox: true`。
- 新模块数据路径必须指向 `D:\荒天帝工作台\data\workbench.db`，不要写相对路径。

### 🔴 PowerShell 执行 curl
- Windows PowerShell 中 `curl` 是 `Invoke-WebRequest` 别名，必须用 `curl.exe` 才能像 Linux 一样用。
- POST 请求体避免引号转义麻烦，先写入临时 JSON 文件，再用 `--data "@文件路径"` 方式传。

### 🔴 开发规范 · 测试强制要求（已纳入开发流程）
- **每完成一个阶段，必须新增对应模块测试 + 运行完整测试套件**：`cd backend && npm test`（Vitest 全部执行）
- **测试失败必须先定位修复**，不允许带着失败进入下一阶段
- Zod schema 中 `.default(x)` 后**绝对不能**加 `.optional()`，否则默认值不生效（空值会变成 undefined 而非 x）
- 新模块测试文件命名：`src/modules/<模块名>/<模块名>.test.js`
- 测试模式约定：Schema 校验 describe（纯函数）+ Service 集成 describe（真实数据库，`TEST_` 前缀隔离，beforeEach/afterEach 清理）
- 若 Service 层存在 JSON.stringify 存储的数组字段，create/update 返回前必须 normalize 还原为数组（参考 Project / DevProject 的 `_normalizeXxx()`）
