# 模块挂载点规范（V1.3 实际落地版）

> **重要说明（规划 vs 现状）**：V1.3 规划文档（`docs/产品迭代/V1.3.0-业务深度与新模块.md` §6.9.3）设想了 `meta.js` 三件套 + 路由自动注册 + 导航/卡片自动渲染，目标是 V1.4+「≤30 分钟挂一个新模块」。
> **但 V1.3 实际并未实现 `meta.js` 自动注册**，新模块采用**四触点手动挂载**。本文件记录**现状的真实机制**（换 AI 能照着挂模块），并把规划中的 `meta.js` 规范作为 §5「未来目标形态」保留，供 V1.4 实现参考。

---

## 1. 真实挂载机制：四触点手动注册

一个新模块要在前端完整可用，必须改 **4 个文件**（以「会议纪要」为例）：

| # | 文件 | 触点 | 作用 |
| --- | --- | --- | --- |
| ① | `frontend/js/router.js` | `registerRoute(...)` | 注册 hash 路由 |
| ② | `frontend/index.html` | `<script>` 标签 | 加载页面组件定义 |
| ③ | `frontend/js/app.js` | `NAV_ITEMS` + `pageComponents` | 侧边栏导航项 + 模块 key→组件 映射 |
| ④ | `frontend/js/store/dataStore.js` | action 方法 | 暴露 CRUD / 业务动作 |

> 后端（路由/service/controller/schema/repository + `prisma` model + migration）独立一套，不在本前端挂载规范内，但同样必需。

### 1.1 ①路由器 `router.js`

在 `initRouter()` 内追加一行（其余路由见 `router.js:125~140`）：

```js
function initRouter() {
  registerRoute('/', { title: '首页总览', module: 'home' });
  // ...既有路由...
  registerRoute('/meeting', { title: '会议纪要', module: 'meeting' });   // ← 新增
  // ...
}
```

`module` 字段是**关键桥梁**：它必须等于 ③ 中 `pageComponents` 的 map key，否则路由命中后渲染不出页面。

### 1.2 ②入口脚本 `index.html`

在「业务页面模块」区（`index.html:80~85`）按字母/分组顺序追加 `<script>`，**必须排在 `js/app.js` 之前**（app.js 挂载 Vue 时需要已定义好的页面组件全局变量）：

```html
<script src="js/modules/MeetingPage.js"></script>
<script src="js/modules/HabitPage.js"></script>
<script src="js/modules/TimeBlockPage.js"></script>
<script src="js/modules/FinancePage.js"></script>
<script src="js/modules/VaultPage.js"></script>
<script src="js/modules/RecycleBinPage.js"></script>
<!-- ===== 应用入口 ===== -->
<script src="js/app.js"></script>
```

> 顺序陷阱：若把新模块 `<script>` 放在 `app.js` 之后，Vue `createApp` 时 `MeetingPage` 等全局变量尚未定义，`pageComponents['meeting']` 会是 `undefined` → 白屏。

### 1.3 ③应用壳 `app.js`（两处）

**a) 侧边栏导航项** —— 在 `NAV_ITEMS` 数组（`app.js:7~24`）按分组插入：

```js
const NAV_ITEMS = [
  { path: '/', label: '首页总览', icon: '...' },
  // ...
  { path: '/meeting', label: '会议纪要', icon: 'M17 20h5v-2a4...' },   // ← 新增（icon 为 SVG path 字符串）
  // ...
];
```

`icon` 是内联 SVG `d` 路径字符串（非 emoji，遵守 P0-1 语义图标红线）。导航项按数组顺序渲染，可通过调整数组位置控制侧边栏分组顺序。

**b) 模块组件映射** —— 在 `pageComponents` 对象（`app.js:60~77`）加一条 key→组件：

```js
const pageComponents = {
  home: HomePage,
  // ...
  meeting: MeetingPage,   // ← 新增；key 必须与 ① 的 module 一致
  habit: HabitPage,
  'time-block': TimeBlockPage,
  finance: FinancePage,
  vault: VaultPage,
  'recycle-bin': RecycleBinPage,
};
```

`currentPage` 计算属性据此 `pageComponents[route.module] || pageComponents.home` 解析当前页组件。

### 1.4 ④状态层 `dataStore.js`

为每个新模块暴露 action 方法（统一经 `htdApi` 调后端 + `showToast` 反馈）。V1.3 六个新模块的真实方法名：

| 模块 | 新增 action（节选） |
| --- | --- |
| 会议纪要 | `createMeeting` / `updateMeeting` / `deleteMeeting` / `generateMeetingReview` |
| 习惯打卡 | `createHabit` / `updateHabit` / `deleteHabit` / `checkInHabit` |
| 时间块 | `createTimeBlock` / `startTimeBlock` / `stopTimeBlock` / `deleteTimeBlock` |
| 财务速记 | `createFinance` / `updateFinance` / `deleteFinance` |
| 合同回款 | `createFinanceContract` / `updateFinanceContract` / `deleteFinanceContract` / `updateContractNode` |
| 沉淀 Vault | `createVaultItem` / `updateVaultItem` / `deleteVaultItem` / `autoRecommendVault` |

约定：列表用 `fetchXxx(query)`、新增 `createXxx(payload)`、改 `updateXxx(id, payload)`、删 `deleteXxx(id)`；业务特有动作（如 `checkInHabit`、`startTimeBlock`、`generateMeetingReview`）按语义命名。

### 1.5 V1.4 实战：一次性挂载 4 个模块（四触点汇总表）

V1.4 一次性新增 POC 跟踪 / 投标档案 / 漏洞跟踪库 / 应急响应记录，是「四触点手动挂载」最完整的范例。每个模块在 4 处各加 1 行，后端 5 层 + `app.js` 挂载独立一套。下表给出**真实落地的注册值**（换 AI 直接照抄即可）：

| 模块 | ① `router.js` `registerRoute` | ② `index.html` `<script>` | ③ `app.js` `NAV_ITEMS` + `pageComponents` | ④ `dataStore.js` action |
| --- | --- | --- | --- | --- |
| POC 跟踪 | `registerRoute('/poc', { title:'POC 跟踪', module:'poc' })` | `<script src="js/modules/PocPage.js"></script>` | `{ path:'/poc', label:'POC 跟踪', icon:'<svg d>' }` + `'poc': PocPage` | `fetchPocs`/`createPoc`/`updatePoc`/`deletePoc`/`changePocStatus` |
| 投标档案 | `registerRoute('/bid', { title:'投标档案', module:'bid' })` | `BidPage.js` | `'/bid'` + `'bid': BidPage` | `fetchBids`/`createBid`/`updateBid`/`deleteBid`/`changeBidStatus` |
| 漏洞跟踪 | `registerRoute('/vuln', { title:'漏洞跟踪', module:'vuln' })` | `VulnPage.js` | `'/vuln'` + `'vuln': VulnPage` | `fetchVulns`/`createVuln`/`updateVuln`/`deleteVuln`/`changeVulnStatus` |
| 应急响应 | `registerRoute('/incident', { title:'应急响应', module:'incident' })` | `IncidentPage.js` | `'/incident'` + `'incident': IncidentPage` | `fetchIncidents`/`createIncident`/`updateIncident`/`deleteIncident`/`changeIncidentStatus`/`addIncidentTimeline`/`addIncidentAction` |

导航 `icon` 全部取自 `frontend/js/utils/icons.js` 锁定 SVG 库（`flask`/`clipboard`/`warning`/`rocket` 等），**禁 emoji**（P0 红线）。后端挂载集中在 `backend/src/app.js` 四行 `app.use('/api/v1/{pocs,bids,vulns,incidents}', xxxRouter)`。

> 经验：4 模块批量挂载时，先一次性把 4 行写进 4 个文件，再逐个联调，避免漏挂导致白屏（`pageComponents[module]` 为 `undefined`）。

## 2. 首页三栏卡片：硬编码而非 meta 驱动

规划 §6.9.3 设想 `meta.homeSummaryCard` 让首页按 `group + order` 自动渲染卡片。实际落地（`frontend/js/modules/HomePage.js`）：

- 三栏（💼工作组 / 🌱生活组 / 📚知识组）卡片**直接写在 HomePage 模板里**（`.home-col` / `.home-card`）。
- 数据来自 `dataStore.homeSummary`，由后端 `/system/home-summary` **一次聚合**返回（`HomePage.js:7` 注释 + `:20` `Vue.computed(() => dataStore.homeSummary)`）。
- 新增模块的「首页摘要卡」目前需要**手动在 HomePage 模板加卡片 + 在后端 home-summary 聚合里加字段**，**不是**改个 meta 就能自动出现。

> ⚠️ 这是 V1.3 与规划的偏差之一。V1.4 做视觉多主题化时，建议顺带把首页卡片迁移到 `meta.homeSummaryCard` 驱动的声明式渲染，才能真正实现「挂模块即出卡片」。

## 3. 实战教程：30 分钟新增「漏洞跟踪」模块（按真实四触点）

> 以下步骤基于**当前真实机制**。后端（Prisma model + migration + route/service/controller/schema）假设你已就绪，这里只走前端挂载。

1. **`t=0` 写页面组件**：`frontend/js/modules/VulnPage.js`，默认导出一个 Vue 组件（`const VulnPage = { setup(){...}, template: '...' }`），列表页用 `<htp-empty>` 两段式空态兜底。
2. **`t=3min` 挂 ②**：`index.html` 业务页面区加 `<script src="js/modules/VulnPage.js"></script>`（放在 `app.js` 之前）。
3. **`t=8min` 挂 ①**：`router.js` 的 `initRouter()` 加 `registerRoute('/vuln', { title: '漏洞跟踪', module: 'vuln' })`。
4. **`t=12min` 挂 ③**：`app.js` 的 `NAV_ITEMS` 加 `{ path:'/vuln', label:'漏洞跟踪', icon:'<svg d>' }`，`pageComponents` 加 `'vuln': VulnPage`。
5. **`t=15min` 挂 ④**：`dataStore.js` 的 `actions` 加 `createVuln / updateVuln / deleteVuln / fetchVulns`（调 `/api/vulns/*`，`showToast` 反馈）。
6. **`t=20min` 联调**：刷新浏览器 → 侧边栏出现「漏洞跟踪」→ 点击路由正确、空态页正常渲染。
7. **`t=28min` 接入真实数据**：VulnPage 调 `dataStore.fetchVulns()` 渲染列表 + `HtpDynamicForm`（或手写 Modal）新建一条「CVE-2026-1234」成功出现在列表。
8. **验收**：以上 7 步 ≤ 30min 全部完成即通过。

## 5. 未来目标形态（规划 meta.js · V1.4+ 参考，本期未实现）

保留规划中的「三件套」设计，供 V1.4 落地自动注册时对齐：

### 5.1 `meta.js` 字段完整列表

```js
// frontend/src/modules/{key}/meta.js
export default {
  key: 'meeting',            // String，必填，唯一，== router module == pageComponents key
  name: '会议纪要',          // String，必填，导航/标题显示
  group: 'work',             // 'work' | 'life' | 'knowledge'，必填，决定侧边栏分组与首页栏
  icon: 'M17 20h5v-2a4...',  // String，必填，SVG path（非 emoji）
  route: '/meeting',         // String，必填，hash 路由
  view: () => MeetingPage,   // 组件引用，必填
  capabilities: {            // Object，可选，驱动 Capability-driven Tabs
    hasDetail: true, hasReview: false, hasDevLogs: false, hasFinance: false,
  },
  homeSummaryCard: {         // Object | null，可选；null=首页不出现
    column: 'work',          // 'work' | 'life' | 'knowledge'
    order: 4,                // Number，同栏内排序
    render: 'recentMeeting', // String，对应 HomePage 的渲染器 key
  },
  fields: [ /* §6.9.2 fields 数组，驱动 HtpDynamicForm 自动渲染 */ ],
};
```

### 5.2 路由自动注册（规划片段）

```js
// frontend/src/router/modules-auto.js（规划）
import.meta.glob('../modules/*/meta.js').then(mods => {
  for (const m of mods) {
    const meta = m.default;
    registerRoute(meta.route, { title: meta.name, module: meta.key });
    pageComponents[meta.key] = meta.view();
    NAV_ITEMS.push({ path: meta.route, label: meta.name, icon: meta.icon });
  }
});
```

### 5.3 首页卡片自动渲染（规划）

HomePage 读取所有 `meta.homeSummaryCard`，按 `column` 分栏、按 `order` 排序，调用 `render` 指定的渲染器输出卡片——实现「挂模块即出首页卡片」，消除 §2 的硬编码偏差。
