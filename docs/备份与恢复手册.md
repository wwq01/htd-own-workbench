# 荒天帝工作台 · 备份与恢复手册

> 适用版本：**V1.2.0+**
> 定位回顾：本工具是**本地优先 / 离线可用 / 数据自主**的单机 B/S 应用，全部数据存于本地 SQLite。
> 备份机制的设计目标——**任何误操作、损坏、版本错配都能回退，且绝不依赖网络或第三方云**。

---

## 1. 备份总览

| 项 | 说明 |
|---|---|
| 备份对象 | 整库 SQLite 文件（`workbench.db`），即 10 个模块的全部业务数据 |
| 备份目录 | `D:\荒天帝工作台\data\backups\`（与 `data/workbench.db` 同级） |
| 单份组成 | `workbench_*.db`（数据）+ `workbench_*.meta.json`（侧车元数据，防损坏/版本校验用） |
| 触发方式 | 自动每日备份 + 手动备份（数据页 / 命令面板 / 顶栏） |
| 恢复方式 | 数据管理页选择备份 → 二次确认 → 自动生成「恢复前快照」后覆盖 |

> 备份目录与数据库在同一块磁盘。若担心磁盘故障，可定期把 `data/backups/` 整个目录拷贝到移动硬盘 / 其他分区（纯文件复制即可，无需工具）。

---

## 2. 三种备份类型

| 类型 `type` | 文件名前缀 | 来源 | 是否自动清理 |
|---|---|---|---|
| `manual`（手动） | `workbench_manual-` | 用户在数据页 / 命令面板 / 顶栏主动触发；可带备注 `note` | **不自动清理**（长期保留，需手动删除） |
| `daily`（每日） | `workbench_daily-` | 后端定时触发（每日一份） | 自动保留最近 **30** 份，超出删最旧 |
| `pre-restore`（恢复前快照） | `workbench_pre-restore-` | 每次「恢复」操作前由系统自动生成 | 不自动清理（它本身就是你的安全网） |

### 命名规则

- 手动（带备注）：`workbench_manual-<备注>-<时间戳>.db`
  - 例：`workbench_manual-升级前-20260816-031200.db`
- 手动（无备注）：`workbench_manual-<时间戳>.db`
- 每日：`workbench_daily-<时间戳>.db`
- 恢复前快照：`workbench_pre-restore-<时间戳>.db`
- 时间戳格式：`YYYYMMDD-HHMMSS`（本地时间）
- 每份 `.db` 必带一份同名 `.meta.json`，内容如：
  ```json
  {
    "schemaVersion": 2,
    "type": "manual",
    "note": "升级前",
    "createdAt": "2026-08-16T03:12:00.000Z"
  }
  ```

## 3. 安全机制（为什么恢复不会把库搞坏）

1. **损坏拒绝**：恢复前校验 SQLite 文件头魔数 `SQLite format 3\0`（16 字节）。非 SQLite / 截断文件直接拒绝，不会覆盖现库。
2. **版本过高拒绝**：读取 `.meta.json` 的 `schemaVersion`。若 `schemaVersion > 2`（即未来更高版本备份），拒绝恢复并提示「备份版本高于当前程序，请先升级程序」，避免旧程序打开新结构导致混乱。
3. **路径穿越防护**：文件名强制匹配 `^workbench_[^/\\]+\.db$`，且必须 `path.basename === 自身`，杜绝 `../` 等越权路径。
4. **恢复非破坏性**：每次恢复**先**自动生成 `workbench_pre-restore-*` 快照，**再**覆盖现库。换言之——恢复本身也可被撤销（把 pre-restore 快照再恢复一次即可）。
5. **并发写保护（启动器）**：程序启动探测到默认端口已有同源实例时，直接复用已开浏览器、不另起进程，避免多进程同时写 SQLite 引发锁冲突。

---

## 4. 自动每日备份

- 触发：后端在运行期间按日触发（每日至少一份）。
- 保留：仅 `daily` 类型参与清理，固定保留最近 **30** 份；`manual` 与 `pre-restore` 永远保留，需手动删除。
- 状态可见：数据管理页「备份」区实时显示最近一次备份时间；顶栏状态点（蓝色）反映备份服务健康；若自动备份被暂停，数据页顶部出现红边警告条。

---

## 5. 如何手动备份

三种入口，效果完全一致（均走 `POST /api/v1/system/backups/manual`，可带备注）：

1. **数据管理页**：进入「数据」标签页 → 备份区 → 填写备注（可选）→ 点「创建备份」。
2. **命令面板**：按 `Ctrl/Cmd + K` 打开命令面板 → 输入「备份 / backup / bf」→ 选「立即备份」。
3. **顶栏手动保存**：顶栏「保存」按钮会广播 `ui:flush-all` 触发全量落盘（非生成备份文件，但保证内存数据已写入；需生成独立备份文件请用上述两者）。

> 建议：每次做大批量导入 / 清空 / 升级前，先手动建一份**带备注**的备份（如「升级 V1.2 前」），便于事后定位。

---

## 6. 如何恢复

1. 进入「数据」标签页 → 备份列表，找到目标备份（可按 `type` 标签与 `note` 备注筛选）。
2. 点该备份的「恢复」→ 弹出**二次确认**弹窗（防止误触）。
3. 确认后：系统先生成 `workbench_pre-restore-*` 快照，再将备份内容覆盖现库。
4. 恢复完成后页面提示成功；若想撤销，把刚生成的 `pre-restore` 快照再恢复一次即可。

> 注意：恢复会**覆盖当前全部数据**为备份时刻的状态。恢复前请确认当前未丢失重要新数据，或先手动备份当前状态。

---

## 7. 下载 / 删除备份

- **下载**：备份列表「下载」可将单份 `.db`（含其 `.meta.json` 需另行复制）导出到本地，用于异地归档或转移机器。
- **删除**：手动删除某份备份（含其 `.meta.json`）。`daily` 备份虽会自动清理，也可手动提前删除腾空间。`pre-restore` 快照建议保留至确认新状态稳定后再删。

## 8. API 速查表

所有接口前缀 `/api/v1/system`，需同源（已启用 `origin-guard` 中间件）。

| 方法 | 路径 | 说明 | 请求体 / 参数 |
|---|---|---|---|
| `GET` | `/backups` | 列出全部备份（含类型、备注、大小、时间、schemaVersion） | — |
| `POST` | `/backups` | 兼容旧接口，等价于创建手动备份 | 可选 `{ note }` |
| `POST` | `/backups/manual` | **创建手动备份**（推荐） | 可选 `{ "note": "升级前" }` |
| `POST` | `/backups/restore/:fileName` | 恢复指定备份（自动 pre-restore 快照） | `:fileName` 取自列表 |
| `GET` | `/backups/status` | 备份服务状态（最近备份时间 / 是否暂停 / 健康） | — |
| `GET` | `/backups/:fileName/download` | 下载单份备份 | `:fileName` |
| `DELETE` | `/backups/:fileName` | 删除单份备份（连同 `.meta.json`） | `:fileName` |

错误约定：`BackendError` 统一错误体；恢复被拒（损坏 / 版本过高 / 文件名非法）返回明确 `code` 与中文 `message`，前端以 Toast 提示。

## 9. 数据安全与故障应对

| 现象 | 原因 | 应对 |
|---|---|---|
| 恢复时报「文件不是有效的 SQLite 备份」 | 文件损坏 / 被截断 / 非数据库 | 换一份完好的备份；损坏文件已被拒绝，现库未受影响 |
| 恢复时报「备份版本高于当前程序」 | 该备份由更高版本程序生成（`schemaVersion > 2`） | 先升级程序到对应版本再恢复 |
| 自动备份长时间无新文件 | 自动备份被暂停（红条）/ 磁盘满 | 检查数据页红边警告条与磁盘空间 |
| 误恢复了一份旧备份 | 恢复前已自动生成 `pre-restore` 快照 | 把对应的 `pre-restore` 快照再次恢复即可回退 |
| 多开程序窗口数据不同步 | 理论上启动器已拦截多进程，但若手动多开 | 关闭多余实例，仅保留一个；备份机制保证单库写入安全 |
