## 2. 产品维度要点（许清楚 · pass）

- **定位**：从「职业工具」→「个人全场景工具」演进自洽，但目标用户画像实际退化为「作者本人」，PRD 缺「用户画像」章节，存在人设口径漂移。
- **IA 自矛盾（重点）**：演进计划同文档对「部署档案」归属给出相反结论（§0.1 工作组 ↔ §0.2 资产组），§14.4 又只列「部署命令片段」不列模块本体——落地前必须拍板。
- **归属模糊**：「备忘」在 10 模块与 6 组间计数错位，应明确「备忘=全局能力，不入组」。
- **版本路线**：战略层自洽；**V1.3 工期 8-12d 严重低估**（4 新模块体量≈V1.0 的 40%），建议拆 V1.3.0 / V1.3.1 各自可发布，并在 V1.3 前插入 V1.6 收口版再进 V2.0。
- **测试基线脆弱绿（高优先级，PM Addendum）**：「184/184 通过」建立在**直连用户生产库** `D:\荒天帝工作台\data\workbench.db` 上。PM 用 Grep 独立核实，`backend/src/modules/` 下 **14 个模块测试文件**（todo/review/project/task/milestone/memo/entertainment/dev-snippet/dev-project/dev-issue/study-record/deployment/study-pending/secret）第 9-16 行均硬编码该路径，`backend/vitest.config.js:3` 注释明写「使用真实数据库」。后果三维：① 跨平台失效——V1.4 规划 macOS+Windows runner、§7.6 验收「CI 全绿」，但 macOS/Linux 无 D 盘，测试整体挂掉，门禁成假绿；② 数据污染——测试中途崩溃把 `TEST_` 脏数据写进生产库、与运行期 App 抢 SQLite 锁，与 V1.2「数据安全兜底」底线直接冲突；③ 质量叙事漏洞——反复以「184/184」作质量证明但基线脆弱。须将「测试隔离化」列为 V1.4 CI 的 **blocker 级前置依赖**，最迟 V1.3 早期完成（认同架构师 P0，口径一致）。
- **差异化护城河**：本地优先 / 离线 / 数据自主 + 工作生活知识三组 + 售前安全字段 + 单 exe。风险：V2.0 路线近乎镜像 person_dashboard，有「沦为 PD-lite」稀释风险——Agent/图谱须以「售前方案沉淀 + 个人复盘」为唯一目的。
- **最大产品空白**：① 知识沉淀闭环在 V1.3→V2.0 间有空档（Vault 易沦为待写清单）；② 本地单机增长天花板（应写进定位文档显式声明）；③ 全文搜索排到 V1.5，模块膨胀期检索兜底缺失；④ 缺量化成功指标定义。

## 3. 技术维度要点（高见远 · pass）

- **分层架构（最强项）**：后端严格 6 层、单向依赖、Controller 薄层、Service 承载校验+事务，工程纪律到位。
- **错误处理债**：无 `toPublic()` 白名单（凭据 `content` 明文默认全返回）、CORS 全开无 Origin 校验——均被 V1.2 P0 覆盖。
- **数据访问**：Repository 软删除/分页封装完善；跨表事务靠各 Service 手写 `$transaction`，V1.3 状态机联动时暴露一致性风险。
- **前端无构建运行时**：取舍正确（服务离线零构建硬约束），代价是模板在 JS 字符串、window 全局耦合、无 TS 类型安全——当前阶段健康。
- **V1.2 五个 P0 可行性**：BackendError+toPublic（必要/低风险）、Observable 事件总线（必要/中风险，但 SSE 推送应推迟到 V1.3）、草稿 5 态机（纯前端/中风险，需后端保存响应带回 serverRevision）、双层 timer（低风险）、备份升级（中风险）。**最大风险是 Observable→SSE 被过度设计**。
- **V2.0 Tauri「业务代码 0 改动」**：可行，3 个接驳点（前端 API_BASE 改可配置绝对地址 / Prisma 引擎随 sidecar 打包 / 单实例端口由壳负责）均为壳与配置层，不侵入业务。
- **运行问题（node --watch 反复重启）**：已弃用；根因最可能是 watch 监听树误触运行期写文件或 IDE 临时文件。固化方案：dev 脚本去掉 --watch，或 `--watch-path=./src`。
- **测试基线脆弱绿（严重，PM 已独立核实扩展）**：184/184 连**真实用户库** `D:\荒天帝工作台\data\workbench.db`、硬编码绝对路径、非隔离、非跨平台——PM 用 Grep 核实 `backend/src/modules/` 下 **14 个模块测试文件**均硬编码该路径，`vitest.config.js` 注释明写「使用真实数据库」。V1.4 CI（macOS+Windows runner）与跨机回归无法复现，须先于 V1.2 改隔离临时库（复制 `prisma/template.db` 到 `os.tmpdir()` 生成独立 test.db + env 注入 datasourceUrl，绝碰 `D:\`）。

## 4. 设计维度要点（颜好看 · fail 条件性）

- **令牌贯通度≈70%**：缺 primitive 基础层（`--color-primary` 直接写字面值）；焦点环 `rgba(91,141,239,0.25)` 散落 ≥5 处；标签色双写未用 color-mix；警示色同语义多套硬编码（`#FCD34D`/`#34D399`/`--color-warning`）；背景墙裸 hex/裸 rgba 未令牌化；仍出现 `10/13/14/6/9/3px` 等禁用间距与 `font-size:13px`。
- **字体栈冲突（红线）**：全局 `--font-family` 为 Inter+雅黑，但规范定 Sarasa Gothic SC（禁 Medium），而 `--font-weight-medium:500` 被大量使用 → Sarasa 无 Medium，会回退伪粗破坏一致性。
- **玻璃态质量**：光影描边一致、背景墙分层+光斑成立（紫+青无粉，未触 P0-2）、@supports 实色回退覆盖较全；但 `.glass` 工具类未抽（≈25+ 处内联复制）、blur 值随组件漂移（20/28/12/8px）、全站 ≈25+ 同时 blur 有性能隐患。
- **组件三态缺口**：12 个 Htp* class 零增删改名（✓）；但 HtpButton 缺 Loading 态、HtpInput/HtpSelect 缺 Error 态、HtpEmpty 缺 CTA、缺骨架屏/indeterminate 进度、可点击件 focus-visible 环不全。
- **P0 硬违例**：① **Logo 渐变文字**（pages.css:56-59），且亮色下首字近白不可见；② **全站缺 `@media (prefers-reduced-motion)`**（违反 a11y 基线）。
- **V1.4 多主题前置**：当前 3 扁平 CSS + `:root`/`data-theme=light` 内联，**未实现 theme.json + tokens.css 架构**；所有硬编码泄漏必须在多主题前清零，否则 Notion 主题（去玻璃实色）下裸值不跟随切换直接破版。
- **Cmd+K 预研**：新增 `htp-command-palette` + `htp-cmd-*` 家族，复用 HtpInput（药丸玻璃搜索）+ HtpListItem（结果行）；浮层单层 blur + 遮罩 blur(8px)；role=dialog/aria-modal + listbox/option + aria-activedescendant；结果图标用 Lucide SVG 禁 emoji。
