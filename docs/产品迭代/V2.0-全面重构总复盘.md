## 4. 架构范式（换人可接手的核心）

### 4.1 后端：每个模块五层

```
schema(zod 校验) → repository(extends BaseRepository) → service → controller → router
```

- 挂载点固定：在 `src/app.js` 显式 `app.use(\`${appConfig.apiPrefix}/xxx\`, xxxRouter)`，`apiPrefix` 恒为 `/api/v1`（**不是 `/api`**，此坑已踩穿，见 §7.6）。
- `BaseRepository` 提供 `findById / findMany / create / updateById / softDeleteById`，新模块一律继承，禁止在 service 里裸写 Prisma 查询。
- 所有错误走 `BusinessError` + `ErrorCodes` 枚举，由 `errorHandler` 统一转 `res.success` 的 `{code,message,data}` 结构（约定：成功 `code:0`）。
- **状态机一律走配置平台**：`resolveStateMachine(scope, fallback)`，禁止 `createStateMachine({ ALLOWED_TRANSITIONS: ... })` 硬编码（否则配置平台改了不生效、形成双写）。

### 4.2 前端：注册单一数据源

- `frontend/js/registry.js` 的 `MODULE_META` 是**唯一数据源**，派生导航、路由、命令面板（Cmd+K）。
- 页面模块在 `frontend/src/entry.js` 顺序 `import`（触发 `window.XxxPage` 副作用）；`app.js` 通过 `buildPageComponents()` 延迟求值。
- **新增模块须注册四处**（规划中的 meta.js 自动注册 V1.3 未实现，仍手动）：
  1. `router.js` 的 `registerRoute`
  2. `index.html` 的 `<script>`
  3. `app.js` 的 `NAV_ITEMS` + `pageComponents`
  4. `dataStore.js` 的 action
  （注：当前实际以 `registry.js` 为派生源，新增模块改 `MODULE_META` + `entry.js` import 即可，`verify-registry.js` 门禁锁死一致性。）
- 首页三栏卡片由 `HomePage.js` 模板 + `dataStore.homeSummary` 硬编码，非 meta 驱动（约束 #7）。

### 4.3 Vite 构建不编译运行时模板

- 页面组件用字符串 `template`，Vite 构建**不编译**它们（约束 #13）。
- 改页面模板后必须用 `@vue/compiler-dom` 单独编译校验，否则语法错要等运行时才暴露。
- Vue 3 全局版模板**不支持可选链 `?.`**，需封装到 `setup()`。

### 4.4 测试隔离

- `backend/test-setup.js` 复制 `prisma/template.db` 到 `os.tmpdir()/htd-workbench-test/workbench.test.db`，注入 `HTD_TEST_DB_URL` / `DATABASE_URL`。
- 单例 `database/prisma.js` 与测试文件均读该环境变量，**绝不直连生产库**。
- `template.db` 由 `scripts/build-template-db.mjs` 按 prisma schema 用 sql.js 生成所有表，**DateTime 一律落 BIGINT**（全库 30+ 张表既有约定，新表必须对齐）。

## 6. 关键决策与权衡

### 6.1 S3 桌面壳为何搁置（D4 裁定）

- 原 V2.0 计划 Tauri 真 APP 化；S4 阶段决定**改服务端部署 + 浏览器访问**为主形态。
- 理由：① 本机无稳定 Rust 工具链（GitHub release 域名被沙箱限流、MinGW 续传失败）；② 服务端形态天然满足「业务代码 0 改动」与多端可访问；③ Tauri 强杀收不到退出信号会留运行期明文（与 V2-3 加密冲突）。
- 已落地的 S3 资产（骨架、`HTD_READY` 契约、图标、托盘/快捷键集成代码）保留在 `src-tauri/`，重启时取消 `s3-0-sidecar.test.js` 的 skip 即可复用。

### 6.2 本地 Agent 为何不联网、不调外部 LLM（V2-1 定位）

- V2-1 是**本地确定性 Agent**：在本机对本地数据做确定性逻辑（统计、提取、聚合），不调用外部 LLM、不联网、不上传数据。
- 理由：符合「本地优先/数据自主」底线；MVP 阶段用进程内同步 JobRunner，结构上预留异步队列扩展点；技能通过注册表零侵入扩展，后端零骨架新增。

### 6.3 状态机配置平台（而非硬编码）

- 8 个状态机域全部接入 `resolveStateMachine(scope, fallback)`：配置优先 + enums 兜底，硬编码 `ALLOWED_TRANSITIONS` 归零。
- 理由：避免「配置平台改了不生效」的双写陷阱。

### 6.4 数据库静态加密 V2-3（可选启用）

- 启用后磁盘只留 `workbench.db.enc`，运行期解密出明文、退出即回收（含 `process.on('exit')` 兜底）。
- 三条硬约束（见 `vault.js` 文件头）：绝不先删明文、覆盖前留 `.enc.prev`、口令错误不留半截明文；口令只认 `HTD_DB_PASSPHRASE` 或终端交互，**取不到即退出、绝不降级明文**。

## 7. 踩坑手册（红线清单，违反即回退）

> 以下条目是经过反复踩坑沉淀的硬约束，新增代码/改动前先对照。

1. **本地优先 / 离线可用 / 数据自主**是核心底线，优先级高于一切便利性。
2. 日期格式化**禁止** `toISOString().split('T')[0]`，必须用 `formatDate()`（本地时间）。
3. `HtpModal` 必须传 `:visible="true"` + 用 `@cancel` 事件（非 `@close`）。
4. Vue 3 全局版模板**不支持可选链 `?.`**，封装到 `setup()`。
5. `fetch` 必须 `cache: 'no-store'`。
6. Node.js **必须 24 LTS**（v22 有 Prisma 兼容问题）。
7. 新增模块须四处注册（见 §4.2），首页三栏硬编码非 meta 驱动。
8. **中文沟通**；先有技术选型 + 开发计划文档再写码；语义化版本；Git 提交 `type: description`；GitHub 用 **SSH** 推送；`.workbuddy/` 不入 Git。
9. 视觉-only 改动必须保住 CSS class 契约、不动 `.js`/后端；文件范围锁死 3 个 CSS。
10. **测试禁止直连生产库**：单例与测试均读 `HTD_TEST_DB_URL`（由 `test-setup.js` 注入 `template.db` 复制的临时库）。
11. **API 前缀是 `/api/v1` 不是 `/api`**。错前缀下 GET 命中静态 index.html 返回 200 HTML（非 JSON），只有写入类才 404，极具迷惑性。
12. 写入类接口受 `originGuard` 约束：只放行 127.0.0.1/localhost 固定端口白名单；脚本冒烟要**不传 Origin 头**（同源放行），带随机端口 Origin 直接 403。
13. **Vite 构建不编译运行时模板**：改页面 `template` 字符串后要用 `@vue/compiler-dom` 单独编译校验。
14. 状态机一律走配置平台，禁止 `createStateMachine({ ALLOWED_TRANSITIONS: ... })` 硬编码。
15. **文档状态栏不可信**：核对阶段进度必须查代码（状态栏空着可能已完成，或相反）。
16. **禁止用 shell 重定向（`cat >>`）向已有文件追加大段内容**：本环境会在错误偏移处写入，不只是追加。一律用 Edit 工具「锚点 + 追加」精确替换，写完立即 Read 验证行数。`.workbuddy/` 不入 Git 无法回滚，写坏即丢失。
17. **端口只能是 17388/17389/17390**：`findAvailablePort` 只在这三个里探测，全占用即拒绝启动；传其它值给 `HTD_PORT` 直接启动失败（不向后续端口顺延）。
18. **端口顺延必须回写 `appConfig.port`**：originGuard 白名单读该字段，不回写则 17388 被占顺延到 17389 后所有写入一律 403（页面能开、能查，一保存就失败，极难排查）。
19. 桌面壳 sidecar 契约：`HTD_DESKTOP=1` → 不开浏览器、跳过复用退出、`stdout` 输出 `HTD_READY {port,...}`；壳只 spawn 一次，后端自己顺延并回报真实端口。
20. **Tauri 壳走 `http://127.0.0.1:<port>` 而非 `asset://`**：保持 Origin 与 Web 版一致，originGuard 白名单零改动、前端零适配。
21. `npm run lint` 现为**两段合计 68 项**：`validate-theme`+`visual-audit`+`verify-registry`=22 项，外加 `verify-tauri-config`=46 项（跨语言契约）。说「全绿」时按 68 项计。
22. **数据库静态加密（V2-3）**：启用后取不到口令即退出、绝不降级明文；Windows 强杀收不到退出信号会留运行期明文，靠启动时 `recovered` 分支兜底。
23. **服务端部署（S4）三条硬约束**：① 来源白名单只有 `allowed-origins.js` 一个实现，CORS 与 originGuard 共用；② 白名单**按请求时动态计算**，不可启动时固化；③ `HTD_HOST` 非回环时**必须**设 `HTD_ACCESS_TOKEN`，否则启动打告警。
24. **新增后端中间件也要配单测**（纯逻辑构造 req/res 打桩，无需 supertest，秒级跑完）。安全类中间件没有回归保护等于没有。
25. **同一文件必须串行 Edit**：并行对相同文件多次 Edit 会静默丢失部分改动（已踩 3 次：verify-registry 计数、app.js 的 agentRouter import）。改为顺序 Edit，每次后 Read 确认。
26. **沙箱禁止子进程网络互通**：`node src/server.js &` 起的真实子进程，127.0.0.1 端口在沙箱内不可达（s3-0-sidecar 90s 超时根因）。验证 HTTP 层请用 **in-process** `createApp()` + `app.listen(0,'127.0.0.1')` + `fetch`（stage7 同款），无需真实端口、不 spawn 子进程。
