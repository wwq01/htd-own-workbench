# V2-3 本地数据库静态加密方案

> 状态：**已完整落地并接入启动流程（2026-09-13）**，并在同日补齐**备份加密配套**（第 7 节）：
> 加密模块 + 生命周期管理（`database/vault.js`）+ 启用/回滚/校验/批量加密备份脚本 + 单测 +
> 端到端冒烟全部通过。口令走 `HTD_DB_PASSPHRASE` 或终端交互，
> 取不到口令即退出，**不降级明文**。启用与否是可选的：未启用时全部逻辑短路，行为与之前完全一致。
> 目标：本地 SQLite 库（当前明文）落地为**静态加密（data-at-rest）**，主密码 + AES-256-GCM，密钥不落盘。
> 原则：本地优先 / 离线可用 / 数据自主 —— 全程无网络、无云、密钥不离本机。

---

## 1. 为什么现在做

S3-1 已落库，Tauri 壳让应用从「本机 Web 服务」走向「可分发的桌面 App」。一旦随 U 盘 / 笔记本携带，明文库（`D:\htd-own-workbench-log\data\workbench.db`）即成为直接可读的全部个人数据。总纲建议「安全属性不晚于 Tauri 首发，避免 APP 化后仍是明文」。

本方案仅 Node 侧、零新增依赖，**不依赖 Rust**，可与 Tauri 编译并行推进。

---

## 2. 密码学选型

| 环节 | 方案 | 理由 |
|---|---|---|
| 密钥派生 (KDF) | **scrypt**，`N=2^15, r=8, p=1`（内存上限 64MB） | Node 内置 `crypto.scryptSync`，**零原生依赖**；抗 GPU/ASIC 暴力破解，代价参数对本地单人应用足够 |
| 对称加密 | **AES-256-GCM** | 认证加密：同一算法既保密又防篡改（auth tag 校验） |
| 密钥来源 | 主密码（用户启动/解锁时输入） | 不存密钥、不存派生结果；密码正确才能解开 |
| 随机数 | `crypto.randomBytes` 生成 salt(16B) + iv(12B) | 每次加密盐/IV 不同，同一明文密文不重复 |

> 选型权衡：Argon2id 是 KDF 首选，但需引入原生包（违背「零新增依赖」）。scrypt 同为内存Hard KDF，Node 内置即用，先落地；若后续要求更高，平滑替换为 Argon2id 即可（仅 `deriveKey` 一处改动）。

## 3. 信封格式（自包含、可独立解密）

密文内携带全部派生所需的元数据，**无需额外密钥文件**：

```
偏移        字段        长度
[0..4)      MAGIC      4B   "HTD1"
[4]         VERSION    1B   当前 1
[5..21)     SALT      16B   scrypt salt
[21..33)    IV        12B   GCM nonce
[33..49)    AUTH      16B   GCM auth tag
[49..)      CIPHERTEXT  变长
```

解密时：校验 MAGIC → 取 salt 派生密钥 → `setAuthTag` 校验完整性 → 解出明文。**密码错误 / 密文被篡改** 均抛 `DECRYPT_FAILED`（GCM 认证失败），不会泄露信息。

## 5. 启动 UX（2026-09-13 已实施：形态 A + 环境变量口令）

**选型结论**：形态 A（原地信封）。形态 B（字段级）改造成本高、查询不可索引，不做。

**口令来源（按优先级）**

1. `HTD_DB_PASSPHRASE` 环境变量 —— 常驻 / 守护 / 开机自启场景必需（没有终端可交互），
   可写入 `deploy/server.env`（该文件已 gitignore）。
2. 终端交互输入 —— 直接 `npm start` 时提示输入，**隐藏回显**（不写入终端滚动缓冲区）。
3. 两者都不可用 → **直接退出并报错**（`DB_LOCKED`）。

> 明确**不做**「跳过本次、以明文只读」降级：静默降级会让用户误以为数据仍受保护，
> 这是本方案最危险的失败模式。口令错误同理（`BAD_PASSPHRASE`，绝不降级）。

**生命周期**：启动解密出 `data/workbench.db`（运行期明文）→ 运行 → 退出时重新加密回
`workbench.db.enc` 并删除明文与 `-wal/-shm` 残留。退出钩子覆盖三条路径：优雅关闭、
强制退出超时、以及 `process.on('exit')` 兜底（任何绕过前两条的 `process.exit` 也会被拦住）。

**启用 / 回滚 / 校验**：`backend/scripts/enable-encryption.mjs`

- 默认（启用）：交互设置主密码（≥8 位、二次确认）→ 先备份 `workbench.db.bak-<时间戳>`
  → 写 `.enc.tmp` → 往返校验 → 原子 rename → 才删明文
- `--verify`：只校验口令能否解开，不落盘
- `--disable`：解密还原明文库，密文库归档为 `.disabled-<时间戳>`。若存在上次残留的运行期明文，
  默认**拒绝**（防止覆盖数据）；确认它就是最新数据时加 `--force`（会校验 SQLite 文件头）

**待确认项 → 已决策**

1. 主密码设置入口 → 走**脚本**而非设置页：服务端部署场景脚本更自然，且避免主密码经由 Web 传输。
2. 启动是否支持降级 → **不支持**，取不到口令即退出。
3. 遗忘兜底 → 明确告知不可恢复；启用前强制备份，回滚仅依赖主密码。

**验证记录（2026-09-13）**：`vault.test.js` 9 用例全绿；端到端冒烟（隔离 dataRoot）通过
——启用后仅剩 `.enc` + 备份；带口令启动探活 200；正常退出后明文回收且 `.enc` 解密仍是合法 SQLite
（文件头 `SQLite format 3`）；`process.on('exit')` 兜底钩子实测能回收明文。

## 6. 迁移与回滚

- **迁移**：用户首次启用加密时，服务端做一次「明文库 → 加密副本」并保留原明文库一段时间作为备份，确认无误后由用户手动删除。
- **回滚**：若需撤销加密，解密 `.enc` 还原 `.db` 即可；因密钥不落盘，回滚仅依赖主密码。
- **遗忘主密码**：无密钥即无法解密，等同数据丢失——必须在启用时强提示备份与记牢。

## 7. 配套：备份同样落密文（2026-09-13 补齐）

### 7.1 为什么必须补

启用加密后若备份仍是明文副本，「锁了前门、开了后门」——任何人拿到 `backups/`
即可读走全部数据，主库加密形同虚设。这不是可选项，是加密自洽的必要条件。

### 7.2 规则

| 场景 | 产物 | 说明 |
| --- | --- | --- |
| 启用加密（server 解锁后注入主密码） | `workbench_xxx.db.enc` | 与主库同一信封格式、同一主密码 |
| 未启用加密 | `workbench_xxx.db` | **行为与之前完全一致**，零回归 |

- 注入点：`server.js` 在 `unlockDatabase()` 成功后 `backupService.setPassphrase(pass)`，
  与异地备份同源；主密码只在内存，不落盘。
- `meta` 记录 `encrypted: true`，列表接口回显该字段，前端展示「已加密」标签。
- **历史明文备份不会自动改写**：启用加密后需显式跑一次
  `node backend/scripts/enable-encryption.mjs --encrypt-backups` 转换（启用脚本结尾会自动提示）。
  该子命令逐个「写 `.enc.tmp` → 往返校验 → rename → 才删明文」，损坏文件跳过且保留原文。

### 7.3 硬约束（改动 `backup.service.js` 时不得破坏）

1. **加密前先校验源为有效 SQLite**：绝不把损坏库封成「看起来正常」的信封。
2. **明文副本是临时物**：落在备份目录内，加密成功即删，不在磁盘留下第二份明文。
3. **恢复缺主密码必须显式报错**（`BACKUP_PASSPHRASE_REQUIRED`），
   绝不降级为「跳过解密直接拿密文覆盖主库」——那会造成二次破坏。
4. **恢复前安全快照同样落密文**，否则备份目录会冒出明文副本。
   但快照**不做** SQLite 校验：主库本身损坏时恰恰最需要恢复，不能因快照失败阻断自救。
5. **异地备份不得二次加密**：本地已是 `.db.enc` 时原样上传。
   再包一层会形成双信封，恢复时解一层仍是密文，等于备份不可用。

### 7.4 测试

`src/modules/system/backup-encryption.test.js`（16 用例）+ `remote-backup.test.js`（16 用例）：
产物形态、解密回原字节、无明文残留、缺密码/错密码拒绝、信封内损坏拒绝、
主库损坏仍可自救、保留策略认 `.db.enc`、真实文件系统冒烟、异地不二次加密。

## 8. 安全边界（诚实说明）

- 仅加密**静态文件**；运行期内存中明文库 + 派生密钥存在，进程退出即释放。
- 传输层仍是本地 HTTP（受 `originGuard` 白名单约束），不做传输加密——本地回环可接受。
- 防不住「主密码被肩窥 / 键盘记录」与「运行时内存 dump」；这是本地单人应用的合理边界。
- **Windows 上被强杀会留下运行期明文**：`taskkill /F`、任务管理器结束进程、系统断电都收不到
  退出信号（实测连不带 `/F` 的 `taskkill` 对控制台进程也被拒绝），此时 `data/workbench.db` 会残留。
  下次启动会以它为准并打告警（`recovered`），正常退出后自动重新加密——**数据不丢**，
  但该时段磁盘上是明文。需要确保回收请用正常退出路径（前台 Ctrl+C）。
- 不替代系统级全盘加密（BitLocker/FileVault），二者可叠加。
