## 6.2 任务 / 项目 / 复盘状态机

### 6.2.1 任务 5 态（替代原 3 态）
- **5 态枚举**：`TASK_STATUS = { NOT_STARTED: 'not_started', IN_PROGRESS: 'in_progress', COMPLETED: 'completed', CANCELLED: 'cancelled', DELAYED: 'delayed' }`（V1.2 之前只有未开始/进行中/已完成 3 态）
- **新增「延期」操作**：任务卡片操作区加「延期」按钮，点击弹二选一小 Modal：
  - 选项 1：**延期到明天**（自动 `dueDate += 1 天`，状态切 `DELAYED`）
  - 选项 2：**延期到指定日期**（日期选择器，选后状态切 `DELAYED` + 记录 `delayedUntil`）
- **迁移**：老数据 3 态 → 5 态映射表写在 `backend/prisma/migrations/V1.3.0-task-5status/migration.sql`，执行时同步写入所有历史任务的 `delayedUntil = NULL`
- **状态点颜色**：复用 §5.3b.1 StatusDot 组件，5 态色值读 CSS 变量

### 6.2.2 项目阶段状态机（6 阶段 + 切换记录）
- **6 阶段枚举**：`PROJECT_PHASE = { POC: 'poc', BIDDING: 'bidding', IMPLEMENTATION: 'implementation', ACCEPTANCE: 'acceptance', CLOSED: 'closed', ON_HOLD: 'on_hold' }`（售前 6 阶段 + 新增「暂停」用于中间停摆）
- **切换记录**：新建表 `ProjectPhaseTransition`（`id / projectId / fromPhase / toPhase / reason / createdAt / createdBy`），每次阶段切换必写一条记录，禁止绕过 API 直接改 phase 字段
- **项目详情页新增「阶段历程」时间线 Tab**：展示 `from → to` + 原因（可选）+ 时间，按时间倒序
- **ALLOWED_TRANSITIONS**（V1.2 §5.3e.4 通用状态机工厂落地后接入）：`{ poc: [bidding, on_hold, cancelled], bidding: [implementation, on_hold, cancelled], ... }`，非法迁移直接 BackendError

### 6.2.3 复盘状态机（草稿 / 已提交 / 已沉淀）
- **3 态枚举**：`REVIEW_STATUS = { DRAFT: 'draft', SUBMITTED: 'submitted', PRECIPITATED: 'precipitated' }`
- **借鉴 person_dashboard 语义**：
  - `DRAFT`：编辑中，可任意改，首页「知识栏」草稿计数 +1
  - `SUBMITTED`：作者确认写完，不可再改内容（只能改标签），首页知识栏「待沉淀」计数 +1
  - `PRECIPITATED`：已一键生成 Vault 沉淀条目（§6.8），沉淀条目引用复盘原文
- **操作流**：周复盘 / 项目复盘写完点「提交」→ `draft → submitted`；「提交」页点「生成沉淀」→ `submitted → precipitated`（同时调用 §6.8 的沉淀 API）

### 6.2.4 统一 stateMachine.js 抽象
- **落地文件**：`backend/lib/stateMachine.js`（原 §5.3e.4 规划的通用工厂 V1.3 正式落地）
  ```js
  // 最小 API 设计
  export function createStateMachine({ name, initial, ALLOWED_TRANSITIONS, onTransition }) {
    // transition(state, event, payload) → { ok, newState, error }
    // 非法迁移返回 ok=false + BackendError DETECT.STATE_MACHINE.INVALID_TRANSITION
    // 合法迁移调用 onTransition(from, to, payload)（写切换记录 / 发 eventBus）
  }
  ```
- **迁移路线**：先迁移任务 5 态机 → 项目 6 阶段 → 复盘 3 态 → 统一走工厂；V1.2 的草稿 5 态机（前端）仍独立但语义对齐
- **UI 控件**：前端 `frontend/src/components/StateSelect.vue` 通用下拉，根据 ALLOWED_TRANSITIONS 当前状态的下一跳动态渲染可选项（不在白名单的 option 不显示，避免用户选错）

### 6.2.5 测试：合法 + 非法迁移全覆盖
- 任务 5 态：枚举合法迁移 12 条 + 非法迁移 8 条（如 `completed → delayed` 非法），每条自动化断言
- 项目 6 阶段：合法 18 条 + 非法 12 条，阶段切换表必生成一条记录
- 复盘 3 态：合法 2 条（draft→submitted / submitted→precipitated）+ 非法 4 条（如 draft→precipitated 跳步非法）

## 6.6 时间块 · 番茄钟（独立模块 · 归属生活组）

### 6.6.1 模块定位与字段
- **分组**：🌱 生活组（与习惯打卡并列，见 §6.5.1）
- **字段完整定义**：
  | 字段 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- |
  | `id` | Int | PK | 主键 |
  | `startedAt` | DateTime | ✅ | 起始时间（精确到分） |
  | `endedAt` | DateTime? | ❌ | 结束时间（未完成时为 NULL） |
  | `plannedMinutes` | Int | ✅ | 计划时长（分钟，默认 25 番茄钟，可改 15/30/45/60） |
  | `actualMinutes` | Int | ✅ | 实际时长（endedAt-startedAt 计算，手动可改，默认 0） |
  | `type` | Enum | ✅ | `WORK` / `STUDY` / `REST` / `OTHER`（工作/学习/休息/其他） |
  | `relatedProjectId` | Int? | ❌ | 关联项目 ID（type=WORK 时推荐填） |
  | `relatedStudyId` | Int? | ❌ | 关联充电学习记录 ID（type=STUDY 时推荐填） |
  | `note` | String(500)? | ❌ | 备注 |
  | `interrupted` | Boolean | ✅ | 是否被中断（默认 false，番茄钟点放弃时 true） |
  | 标准时间戳 | DateTime | — | createdAt/updatedAt/deletedAt |

### 6.6.2 手动开停完成：后台不阻塞浏览器
- **番茄钟模式**：点击「开始番茄钟」按钮 → `startedAt = now` + `plannedMinutes = 25` → 前端 `setInterval` 每秒更新「已用 XX:XX / 25:00」进度条（读系统时间差，不是 setInterval 累计，避免标签页休眠不准）
- **后台不阻塞**：用户最小化浏览器 / 切 Tab 时，`document.hidden` 状态下仍以 `performance.now()` 或服务端时间差校准，回到页面时显示正确进度；**不要求前端在后台 100% 精确**，用户可手动调整 endedAt / actualMinutes 修正
- **完成方式**：3 种：
  1. 进度到 plannedMinutes → 自动弹「番茄钟完成！」通知 + `actualMinutes = plannedMinutes` + `endedAt = now`
  2. 手动点「结束」→ `endedAt = now` + `actualMinutes = min(已用, plannedMinutes)` + `interrupted = true or false`（用户可选「完成了」/「中断了」）
  3. 历史补录：列表页「补录一个时间块」→ 填起止时间，直接写入不经过计时

## 6.8 沉淀 Vault 起步（独立模块 · 归属知识组）

### 6.8.1 模块定位与最小数据
- **分组**：📚 知识组（侧边栏顺序：充电学习 / **沉淀 Vault** / 阅读资料）
- **最小数据模型**（字段精简起步，V2.0 再扩双向链接/图谱）：
  | 字段 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- |
  | `id` | Int | PK | 主键 |
  | `topic` | String(200) | ✅ | 主题（标题） |
  | `content` | Text(markdown) | ✅ | 笔记正文，Markdown 纯文本（前端渲染 Markdown → HTML，离线手写 parser，V1.5 再引 markdown-it） |
  | `tags` | String[] | ✅ | 标签数组（便于首页推荐 & V2.0 标签树） |
  | `status` | Enum | ✅ | `DRAFT` / `PRECIPITATED` / `ARCHIVED`（草稿 / 已沉淀 / 归档，V2.0 再细分） |
  | `sourceType` | Enum | ✅ | 来源类型：`MANUAL` / `WEEKLY_REVIEW` / `PROJECT_REVIEW` / `MEETING_REVIEW` / `CREDENTIAL_NOTE` / `DEPLOY_NOTE` |
  | `sourceId` | Int? | ❌ | 来源记录 ID（sourceType != MANUAL 时必填） |
  | `sourceUrl` | String(200)? | ❌ | 来源 URL Hash（点击跳回原记录用） |
  | 标准时间戳 | DateTime | — | createdAt/updatedAt/deletedAt |

### 6.8.2 沉淀来源：周/项目/会议 复盘提交后自动生成草稿
- **触发钩子**：
  1. 周复盘 status `DRAFT → SUBMITTED`（§6.2.3）成功 → 自动调用 `VaultService.autoCreateFromReview({ sourceType: 'WEEKLY_REVIEW', reviewId })`
  2. 项目复盘 status `DRAFT → SUBMITTED` → 同上 `PROJECT_REVIEW`
  3. 会议纪要点「生成复盘」且复盘 status → SUBMITTED → 同上 `MEETING_REVIEW`
- **自动生成的草稿内容**（不复制原文正文，只保留「摘要 + 引用指针」，详细见 §6.8.3 引用关系）：
  ```markdown
  # {原复盘标题} → 沉淀草稿（自动生成）

  来源：[{sourceTypeReadable}]({sourceUrl})（点击跳回原记录）
  创建时间：{createdAt}

  ## 摘要（请编辑后沉淀）
  （请用 3-5 条总结本复盘的核心沉淀要点，V1.3 自动从复盘 Action Items 前 3 条预填占位）
  - 占位 1
  - 占位 2
  - 占位 3

  ## 正文（可选，引用原复盘不复制，可在此补充延伸思考）
  （引用关系已建立，如需引用原文具体段落请跳回 {sourceTypeReadable} 查看）
  ```
- 草稿生成后状态 = `DRAFT`，首页知识栏「待写沉淀」计数 +1（§6.1 知识栏卡片 3）

### 6.8.3 凭据 / 部署记录备注一键转沉淀
- **位置**：凭据保险箱「备注」字段底部、部署档案「操作记录」每条操作右下角 → 新增「💡 转沉淀」小按钮
- **点击行为**：弹 Modal → 填主题（默认预填「凭据备忘：{credentialName}」）+ 标签（默认预填 `['凭据','{credentialGroup}']`）→ 点确定 → 生成 `VaultDRAFT` + sourceType=`CREDENTIAL_NOTE`（或 `DEPLOY_NOTE`）+ sourceId=对应记录 ID
- **引用跳转**：沉淀详情页「来源信息」区卡片显示 `来源：凭据保险箱 - {name}`，可点击 → hash 路由跳回凭据详情页（§6.3.2 高亮机制复用）

### 6.8.4 沉淀与原模块关系：引用不复制正文
- **核心原则**：沉淀内容永远**不复制原复盘 / 原凭据的完整正文**到 Vault.content，只存：
  1. 摘要（用户提炼的 3-5 条）
  2. sourceType + sourceId + sourceUrl 三元引用指针
  3. 用户手动在沉淀页新增的「延伸思考」正文（≠ 原文复制）
- **为什么引用不复制**：
  - 避免双写不一致（复盘正文改了，沉淀里的副本没同步 → 数据矛盾）
  - 节省存储（复盘内容可能 5000 字，沉淀摘要只要 300 字）
  - 知识图谱 V2.0 基于引用关系建立，复制正文会断链
- **实现约束**：后端 VaultService.create / update 接口校验：如果 `sourceType != MANUAL` 且 `content` 超过 `sourceType = MANUAL` 时平均字数的 2 倍 → 给出 BackendError 警告（软约束，不强阻断，提示用户「引用模式不建议粘贴完整原文，建议提炼摘要，原文请跳回来源查看」）

### 6.8.5 首页沉淀推荐：基于本周完成事项 + 重点项目推送 3 条
- **推荐算法（V1.3 规则式，V2.0 再做 Agent 推荐）**：
  1. **候选池生成**：本周（周一 0 点 ~ 今）状态变为 `COMPLETED` 的今日任务 + 本周状态变为 `CLOSED` / `ACCEPTANCE` 的项目 + 本周提交 `SUBMITTED` 但未生成沉淀的复盘
  2. **打分（规则权重）**：项目阶段变化 × 4 分 + 任务含标签「重点」× 2 分 + 复盘待沉淀 × 3 分 + 本周 `today 计划完成率 > 80%` 加 1 分
  3. **取前 3 条**：展示在首页知识栏卡片 3「推荐待写沉淀」，每条带「一键生成草稿」按钮，点击自动调 §6.8.2 VaultService（sourceType 按候选类型推导）
- **空态**：本周无完成事项时，推荐卡片显示空态 §5.3b.4：`title = '本周还没有值得沉淀的产出'，actionText = '去今日计划看看有没有已完成的？'`

### 6.8.6 测试：草稿生成 + 引用关系 + 来源打开
- 自动化：周复盘 1 条 → status DRAFT → SUBMITTED 后 → Vault DRAFT 表新增 1 条，sourceType = WEEKLY_REVIEW，sourceId = reviewId，sourceUrl 非空
- 自动化：凭据 A 点「转沉淀」→ Vault 生成，content 字数 ≤ 500（软约束验证通过）；手动把 content 改成 5000 字粘贴 → 更新接口返回警告 BackendError `RESULT.VAULT.CONTENT_TOO_LONG_FOR_SOURCE`（软告警 + 仍允许但记录日志）
- 手测：沉淀详情页点「来源信息 → 跳回原记录」→ URL hash 正确 + 原记录高亮 3s + 原记录内容与沉淀摘要一致（对账）

## 6.9 表单与校验

### 6.9.1 前端 Zod 校验与后端共用 schema 文件
- **schema 位置**：统一放在 `shared/schemas/` 目录（新建，前后端都 import 同一份，Prisma 不用做 source of truth），示例：
  ```js
  // shared/schemas/meeting.schema.js
  import { z } from 'zod'  // V1.3 确认无构建下引入 zod UMD，兼容前后端
  export const MeetingCreateSchema = z.object({
    title: z.string().min(2, '会议主题至少 2 字').max(200),
    heldAt: z.coerce.date(),
    participants: z.array(z.string().min(1)).min(1, '至少 1 位参与人'),
    agenda: z.array(z.object({ order: z.number(), title: z.string().min(1) })).min(1, '至少 1 个议题'),
    // ...
  })
  ```
- **前端使用**：Modal 内 `onSubmit` 调用 `MeetingCreateSchema.safeParse(formData)`，失败时在输入框下方**就地红字提示**（不 Toast，不跳转，不把错误回退给后端打网络请求）
- **后端使用**：路由层 `req.body` 先调同一个 `MeetingCreateSchema.parse()`（`parse` 抛错 → 中间件捕获成 BackendError DETECT.VALIDATION.ZOD，返回给前端兜底）
- **收益**：前后端校验规则 100% 一致，避免「前端过了后端校验挂」的扯皮；新增字段只改 1 处 schema

### 6.9.2 统一字段类型映射 → 控件自动选择
- **类型映射表（组件注册表）**：`frontend/src/components/form/field-mapping.js` 定义 6 类基础字段 → 自动选择对应控件：
  | 字段类型（schema 里标记） | 自动渲染控件 | 额外 props |
  | --- | --- | --- |
  | `string` + `max ≤ 100` | `HtpInput.vue`（单行输入） | placeholder / maxlength |
  | `string` + `max > 100` / `textarea` | `HtpTextarea.vue`（多行） | rows / maxLength |
  | `number` | `HtpNumberInput.vue`（带步进器） | min / max / step |
  | `date` / `datetime` | `HtpDatePicker.vue`（原生 `<input type="datetime-local">` 封装） | showTime |
  | `enum` | `HtpSelect.vue`（单选下拉） | options 数组 |
  | `array(string)` | `HtpChipInput.vue`（chip 多选，回车添加） | 建议候选 |
  | `relation`（关联 entity，如 relatedProjectId） | `HtpEntitySelect.vue`（搜索 + 下拉 + 懒加载） | entityType / displayField |
- **用法**：业务 Modal 不用手动写 `<input><select>`，只要传 `fields = [{ key:'title', type:'string', label:'主题', required:true }, ...]` 数组，`<HtpDynamicForm :fields="fields" v-model="formData"/>` 自动渲染全部 + 自动套 Zod 校验就地提示

### 6.9.3 模块挂载点三件套：meta → 路由 → 导航项 + 卡片摘要
- **建立目的**：V1.4+ 挂载新模块（如 POC 跟踪 / 漏洞跟踪）不需要改 5 处代码（不用加路由/加导航/加首页卡片/加 meta/加权限），只写 1 份 `meta` + 1 份 `Module.vue`，≤ 30 分钟完成（§6.12 验收项）
- **三件套定义**：
  1. **模块描述 meta**：`frontend/src/modules/{moduleKey}/meta.js`（如 `modules/meeting/meta.js`）导出：
     ```js

       key: 'meeting', name: '会议纪要', group: 'work', icon: '📝',
       route: '/meeting', view: () => import('./MeetingIndex.vue'),
       capabilities: { hasDetail: true, hasReview: false, hasDevLogs: false, hasFinance: false },
       homeSummaryCard: { column: 'work', order: 4, render: 'recentMeeting' }, // 首页三栏哪栏 + 第几张
       fields: [ /* §6.9.2 fields 数组 */ ],
     ```

  2. **路由自动注册**：`frontend/src/router/modules-auto.js` 扫描 `modules/*/meta.js`，自动往 Hash Router 注册 `/meeting` → MeetingIndex.vue（V1.3 仍无构建，手写 require.context 或显式 import 数组，不搞动态扫描魔法）
