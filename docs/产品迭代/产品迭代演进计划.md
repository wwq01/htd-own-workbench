### 项目硬约束（不可违背）

| 约束 | 适用范围 | 说明 |
| --- | --- | --- |
| **本地优先** | 全版本 | 核心数据 100% 本地，备份、迁移、销毁完全可控 |
| **离线可用** | 全版本 | 所有"必做功能"必须能在断网下完成 |

| **GitHub 远端** | 工程约定 | `git@github.com:wwq01/htd-own-workbench.git`（SSH 协议） |
| **Git 提交格式** | 工程约定 | `type: description`（如 `refactor: 视觉重构为 Liquid Glass 风格 (V1.1.0)`） |
| **SSH 推送** | 工程约定 | 国内访问 GitHub HTTPS 不稳定，**用 SSH 推送**；HTTPS 推不上不要硬试 |
| **版本登记** | 工程约定 | 每次发布必须在 `../记录 - 版本更新.md` 登记，声明"基于哪个版本之后" |

### 已踩过的坑（教训）

1. **SSH 推送建议**：HTTPS 推送 GitHub 经常"Connection was reset"，改用 SSH 后稳定。
2. **PowerShell 不支持 `&&`**：用 `;` 分隔命令；`curl` 是 `Invoke-WebRequest` 别名，需用 `curl.exe`。
3. **不要靠手测过提交**：每阶段必须新增/补齐自动化测试，手测通过不算完整。
4. **根据需要时再创建临时文件**：除非绝对必要，否则优先查找本地文件是否能够支持，如果不支持再考虑新增文件。
5. **文档要自我包含**：演进类文档必须做到"换 AI Agent 也能立即接手"，否则失去意义。

### 新 AI 上手 5 步走

1. **读本节**（1 分钟）：知道约束、偏好、坑。
2. **读 TL;DR**（30 秒）：知道是什么、当前进度、未来路线。
3. **读 § 16 当前状态快照**（1 分钟）：知道已发布什么、未发布什么。

## 0. 定位重塑（V1.2 起生效）

| 维度 | v1.0 / v1.1 旧定位 | V1.2+ 新定位 |
| --- | --- | --- |
| 产品 | 网络安全售前工程师工作台 | **个人工作生活一体化 + 知识沉淀平台** |
| 核心用户 | 网络安全售前工程师 | **本人**（贴合个人工作 + 生活 + 知识的真实场景，不追求通用化） |
| 范围 | 售前 + 工作 | **工作 / 生活 / 知识** 三组并列 |
| 知识沉淀 | 复盘 / 学习记录 | **复盘 + Vault + 阅读** 沉淀通路 |
| 售前字段 | 突出 | **保留为工作组的内置字段**（"工作"组下不再单独强调） |

### 0.1 新版导航分组（四组 + 资产 / 系统）

| 组 | 模块 | 备注 |
| --- | --- | --- |
| 🏠 **总览** | 首页 | V1.3 起按"工作 / 生活 / 知识"三栏聚合 |
| 💼 **工作** | 今日 / 明日计划、**复盘沉淀**、售前项目、开发工作、**会议纪要** | 复盘归入此组 |
| 🌱 **生活** | 游戏娱乐、**习惯打卡**、**时间块**、**财务速记** | 健康 / 节奏 / 收支 |
| 📚 **知识** | 充电学习、**沉淀 Vault**、**阅读 / 资料** | 沉淀 + 输入 |
| 🔐 **资产** | 凭据保险箱、**部署档案** | 凭据分组 + 有效期提醒；部署含 IP / 命令等敏感信息，与工作区隔离 |

### 0.2 关键判定

- **"复盘"归入"工作"组**：周复盘 / 项目复盘是对工作产出的反思，直接放在工作流末端。
- **"沉淀 Vault" 单独成线**：是知识组的"主输出"，与"充电学习"（输入）、"阅读"（输入）形成闭环。
- **"财务速记"进入生活组**：仅做收支 / 合同 / 回款的轻记录（脱敏），不替代财务系统。
- **"凭据"与"部署"独立成"资产"组**：与"工作"分开，避免泄露风险扩散到工作区。

### 0.3 旧 PRD 的处置

- `../基线 - PRD.md` 保留作为 v1.0 历史基线，不再随每次迭代更新。
- 本文件 + `../记录 - 版本更新.md` 承担 v1.2+ 的需求与变更载体。
- 若 V1.3 后差异过大，再起 `../PRD-V2.md` 重新梳理。

### 0.4 目标用户画像

- **唯一用户 = 本人（开发者即使用者）**：网络安全方向售前工程师，业余时间独立推进本工具，单机本地运行，无团队、无多租户。
- **典型一天**：上午处理售前项目与开发问题；午间 / 通勤用「游戏娱乐」「习惯打卡」调节节奏；晚上做复盘沉淀、充电学习、记录部署与凭据。
- **核心诉求**：
  1. 工作 / 生活 / 知识在同一入口聚合，减少在多个 App 间切换；
  2. 凭据、部署等敏感信息本地留存，绝不上云；
  3. 记录即沉淀——复盘、学习、阅读能回流为可复用经验；
  4. 视觉克制、操作顺手，长期使用不疲劳。
- **能力边界（不服务谁）**：不做多人协作 / 审批；不做移动端；不接在线 AI API；不替代专业财务 / 健身 App。

### 0.5 产品成功度量定义

> 因属个人单机工具，成功以"自用黏性 + 数据自主 + 质量稳定"衡量，而非 DAU / 营收。下列指标亦作为每轮体检的验收基线。

| 维度 | 度量指标 | 目标 |
| --- | --- | --- |
| 覆盖度 | 已落地模块占规划模块比例 | V1.3 起 ≥ 14/18 |
| 黏性 | 周活跃模块数（去重） | ≥ 5 个 / 周 |
| 数据自主 | 本地存储占比（无云写入） | 100% |
| 可靠性 | 备份成功率（近 30 天） | 100% |
| 稳定性 | 单次启动 uptime / 崩溃次数 | 0 崩溃 / 周 |
| 一致性 | 视觉令牌命中率（无硬编码色值 / emoji 图标） | 100% |
| 可维护 | 单元测试通过率 | 100%（基线 184/184） |
| 安全 | CORS 同源命中率 / 敏感字段白名单覆盖率 | 100% |

## 3. 演进原则（贯穿 V1.2 → V2.x）

1. **本地优先**仍是底线：核心数据 100% 本地，备份、迁移、销毁完全可控。
2. **离线可用**仍是底线：所有"必做功能"必须能在断网下完成。
3. **不绑死"无云"**：v1.2 之后允许"可选云"——例如云端只读备份、扫码登录跨设备，但默认关闭、按需开启。
4. **不绑死"单 Windows"**：v1.4 之后允许 macOS 启动器；浏览器仍以 Chrome / Edge 为基线。
5. **架构先行**：每次发布前先保证"模块挂载点、字段类型、状态机"等架构扩展位已就位，再加业务。
6. **测试同步**：每完成一个阶段必须新增/补齐自动化测试，禁止"手测通过就提交"。
7. **规范先行**：每引入一个新能力（新外观 / 新备份策略 / 新搜索语法）都先写规范文档，再写代码。
8. **三组导航一致**：所有新增模块必须明确归入"工作 / 生活 / 知识"三组之一，避免再次出现"复盘该放哪"这类争议。
9. **前端分层**：前端规范遵守 [前端系统化设计.md（前端工程总纲）](./前端系统化设计.md) 的7层架构（L1工程规范→L7视觉呈现）和三条迭代线（功能/视觉/基建）。新功能开发"先奠基、再盖楼"——从L1-L3往L4-L7做。任何借鉴/新增必须明确主题归属层（[L1行为] vs [L2装饰]），L2装饰必须可被主题切换器关掉。详见总纲 [§ 1 前端哲学](./前端系统化设计.md#1-前端哲学永远不变的基调) 与 [§ 2 分层架构](./前端系统化设计.md#2-前端分层架构7-层金字塔)。

- **本地 Agent 协作**：Agent 通道（inbox 文件投递）+ Skills 协议（周复盘生成器等内化）+ 审计日志 + JobRunner 6 态状态机 + 依赖注入 Runner 工厂 + SafeLineStream 10MB 防 OOM + Cancellable 双信号取消 + 三层错误码 + CapabilityDetector 启动时 AI 能力检测 + 纯函数 Prompt 构造器
- **可选云**：云端只读备份（WebDAV/S3 兼容，默认关）+ 跨设备扫码登录（仅登录态本机）+ 系统设置明示开关状态
- **主密码 + 本地加密**：可选 AES-256-GCM 加密 SQLite + 密钥派生自主密码 + 加密备份+助记词找回方案

## 11. 风险与回退预案

| 风险 | 触发条件 | 应对 |
| --- | --- | --- |
| 备份链路破坏主库 | 恢复逻辑 bug | 保留"恢复前安全备份"；回退到 v1.1 的 JSON 导入导出 |
| 多套外观 CSS 体积爆炸 | class 名冲突 / 体积 > 200KB | 按外观分文件按需引入；视觉规范先收口 |
| 全文搜索性能差 | 1w 条以上明显卡顿 | 退化为分模块独立索引；或引入 FTS5 |
| 跨平台启动器权限问题 | macOS Gatekeeper | 提供 `chmod +x` 提示 + "在终端打开"指引 |
| 可选云引入后隐私质疑 | 用户对"云"反感 | 严格默认关闭；明示开关；明确"零业务数据上行"承诺 |
| Agent 误操作 | 写错文件 / 覆盖数据 | 走 inbox 通道 + 审计日志；高危操作二次确认 |
| 4 个新模块工期超期 | V1.3 工作量过大 | 拆 V1.3.1 / V1.3.2 子版本；4 个模块分两批上 |
| 首页三栏信息过密 | 三栏卡片过多 | 收纳为"按需展开"二级面板；保持每栏 3-5 卡片 |
| 财务模块误用为记账 App | 用户把高敏财务数据全量录入 | 顶部显著提示"本机数据，不替代财务系统"；金额阈值二次确认 |
