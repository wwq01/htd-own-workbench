## 0. TL;DR（给决策者的结论）

1. **不另起独立的"重构版本"**。把重构并入 V2.0，采用 **A → B → C 三阶段演进式** 路径，与既有"业务代码 0 改动"的 V2.0 前提一致。
2. **后端分层骨架健康，保留**。`router/controller/service/repository/schema` 五件套普遍遵守，响应封装 100% 契约一致（`res.success` 188 处、`res.json` 0 处）。问题集中在**前端无构建瓶颈**与**几处一致性债务**。
3. **立即可做且价值明确的第一刀（M0）**：修复 4 个空导航图标、暗色主题图表配色失效、命令面板缺 10 个模块、"新建备忘"空操作、状态机双写路径。这些不依赖任何架构决策，独立可验证。
4. **最关键的产品裁定**：V2.0「知识图谱 1k 节点流畅」是否硬需求？——它直接决定**要不要上方向 B（Vite 构建化）**，是本报告唯一无法由代码证据单独裁定的问题。
5. **Tauri 迁移面远小于预期**（绝对路径仅 `app.config.js:15` 一处，`process.pkg` 仅 2 处，且 `HTD_DATA_ROOT` 覆盖机制已就位），可放心推迟到最后阶段。

## 1. 调研综述

### 1.1 PM 结论：锚定 V2.0 的演进式战略

- **用户画像**：唯一用户 = 作者本人（网络安全售前工程师），单机本地、无团队、无多租户。核心场景：多售前项目日报/周报、技术投标 RFP 应答、公众号 PR 素材沉淀、"第二大脑"知识沉淀、敏感凭据本地留存。
- **能力盘点**：V1.5.0 已收口（约 16 业务模块、可视化、搜索、字段配置平台、阅读模块、422/422 测试通过、exe 已构建探活）。对照 V2.0 缺口：真原生 APP、Vault 深化、知识图谱、本地 Agent、可选云、主密码加密、日报/周报自动生成（选做未交付）。
- **演进驱动 vs 债务驱动**：V2.0 的 APP 化/Vault/Agent/云/加密多为**加法**（尤其 APP 化分析已论证"业务代码 0 改动"）；多数技术债与 V2.0 无强耦合。少数债务是 V2.0 阻塞点（加密数据层决策、Vault 模型升级）。
- **战略建议**：**锚定 V2.0 演进式，不另起预备式清理**；把"阻塞型债务"并入 V2.0 的 **M0 里程碑**作为立项第一刀。

### 1.2 架构师结论：A → B → C 三阶段，A 先、C 后

- **架构快照**：分层清晰且普遍遵守；最强约束为 C1（前端无构建、43 个有序 script 拼装）、C2（V2.0 验收 1k 节点流畅）、C3（图表 = SVG 字符串 + `v-html` 注入）、C4（单文件 SQLite 单写进程）、C5（数据根绝对路径硬编码，但已收敛到单一文件）。
- **三方向权衡**：
  - **方向 A**（保持无构建，仅模块化 + 注册点自动化 `meta.js`）：成本最低、增量可控，但**不解决知识图谱机制债**，全局命名空间污染仍在。
  - **方向 B**（前端引入 Vite 构建化）：**唯一能根治 P0-3（1k 节点图谱）的方向**，npm 生态全面可用（d3-force、markdown-it），获得 tree-shaking/代码分割/HMR/构建期报错。代价是牺牲"改 JS 刷新即生效"的零门槛调试。
  - **方向 C**（面向 Tauri 端到端重构）：即 V2.0 完整实现，但**范围最大、并行度最差**，在已知缺陷上叠加"构建体系 + 进程模型 + 分发方式"三维度变更，回归易陷入三重归因。
- **结论**：**A → B → C 三阶段；A 先做、C 最后做**。推迟 C 代价很低（迁移面小），但 B 的必要性刚性（机制问题非优化问题）。

## 2. 重构战略总纲

```
V1.5.0 (已收口)
   │
   ├─ M0  阻塞型债务并入（立即，独立于业务进度）
   │
   ├─ S1  方向 A：止血 + 建立单一数据源（注册点自动化 meta.js）
   │         │   出口：新增模块只需改 meta.js + index.html 两处
   │         ▼
   ├─ S2  方向 B：前端 Vite 构建化（条件性，取决于 D1 裁定）★ 关键决策
   │         │   出口：dist/ 可被 pkg 消费；1k 节点图谱达帧率门槛
   │         ▼
   └─ S3  方向 C：Tauri 壳（sidecar 化 + 资源分发 + 双产物线）
                出口：真原生 APP，业务代码 0 改动
```

**原则**：
- 不推倒后端骨架；不引入与"本地优先/离线"相悖的依赖。
- 每一阶段有**可验证的出口判据**，阶段间低耦合。
- S2 是否执行，由决策点 D1（知识图谱硬需求）决定；若 D1 选择降级，则 S2 可无限期推迟，项目维持零构建极简优势。

## 4. 阶段路线图

### M0 — 阻塞型债务并入（立即，独立于业务进度）

目标：修复用户可见缺陷 + 收敛一致性债，不等架构决策。
关键任务：
- 修 P0-1（NAV_ITEMS 统一走 `htdIcon(key)`）、P0-2（图表色改 CSS 变量 / 统一三套主蓝为单一 token）、P2-4（空 handler + 拼音错字）。
- 对 `config.customFields` 做明确决策：要么后端 `reading.schema.js` 接入 `getCustomFieldsSync` 校验 + 前端按定义渲染，要么从配置平台移除（不留装饰）。
- 后端：`project.phase` 改用 `createStateMachine`；`todo.toggleStatus` 收敛进 `changeStatus`；8 张迁移表统一纳管或标注"不可配"。
- 测试隔离改为**按文件名 hash 生成独立 db 路径**，解除对 `fileParallelism:false` 的依赖。

出口判据：`grep` 不到重复 icon path 字面量；`npm test` 在 `fileParallelism:true` 下全绿；命令面板覆盖全部模块。

### S1 — 方向 A：止血 + 建立单一数据源

目标：消灭注册点漂移，建立 `meta.js` 注册表。
关键任务：
- 每个模块新增 `meta.js`，声明 `path/title/icon/component/commands` 单一数据源；`router`/`NAV_ITEMS`/`pageComponents`/`COMMANDS` 全部派生。
- 后端 `app.js` 改为扫描 `modules/*/*.router.js` 约定式挂载。
- 拆分 `system.service.js`(807) 中回收站/图表为独立模块（测试已按关注点拆开，实现未拆）。

出口判据：新增模块只需改 `meta.js` + `index.html` 两处（C1 未解除，从 5 处降到 2 处）。

### S2 — 方向 B：前端 Vite 构建化（★ 条件性，取决于 D1）

前提：D1 裁定"知识图谱 1k 节点流畅"为硬需求。
关键任务（内部再分两步）：
1. Vite + ESM + `import.meta.glob` 自动收集注册表（机械切换，因 S1 已建单一数据源）；拆分 `dataStore.js`(855)/`ProjectPage.js`(885)；design token 单一来源。
2. 图表机制从"字符串 + `v-html`"改为真实 Vue 组件 + 响应式 SVG/Canvas；引入 d3-force。**必须有性能门槛测试**：1k 节点力导向 ≥30fps（中间）/60fps（验收），在做图谱业务前验证。

出口判据：`dist/` 可被现有 pkg 流程消费；1k 节点图谱 demo 达帧率门槛；新增模块 0 手工注册。

### S3 — 方向 C：Tauri 壳

前提：S1/S2 完成，前端有 `dist/`、注册表自动化、路径收敛。
关键任务：
- `server.js` 抽 `startServer({openBrowser,port})`，`HTD_SIDECAR=1` 禁用浏览器弹出。
- 单实例语义：HTTP 探测 → 文件锁 + stdout 端口握约（兼容"用户双击老 exe"与 sidecar 并存）。
- 数据目录由 Tauri 注入 `appDataDir()`（经 `HTD_DATA_ROOT`），保留 `D:\荒天帝工作台` 作老用户迁移兜底。
- 资源分发选方案 (a)：前端仍由 sidecar 托管，WebView 指向 `127.0.0.1:17388`（业务代码 0 改动）。
- 统一 P2-5 跨平台 Node 版本与构建步骤；保留 pkg 产物线（双产物并行）。

出口判据：Tauri APP 启动即进工作台、无额外浏览器弹窗；SQLite 单写不被违反。

## 6. 风险与门禁

- **三重归因风险**（S3）：在已知缺陷上叠加三维度变更，回归难定位 → 故 A 先 C 后、逐级出口判据。
- **测试隔离脆弱**（P1-6）：依赖串行约定，开启并行即随机失败 → M0 改为按文件独立 db。
- **双产物线成本**（S3）：pkg exe + Tauri app 构建矩阵与测试翻倍，且 P2-5 已显示跨平台脚本不整齐 → S3 前先统一。
- **沉没成本警示**：`charts.js` 的 `lineChart` 已实现零消费，若 D1 选 B 应尽早启动 S2，避免在旧机制上继续堆积。

## 7. 建议的下一步

1. **先裁定 D1**（知识图谱硬需求）——这是唯一阻塞 S2 的产品决策。
2. **同步启动 M0 + S1**（不依赖 D1），立即修复用户可见缺陷、建立注册表单一数据源。
3. **S2 视 D1 决议**：选硬需求则进入 Vite 化设计（Phase 2）；选降级则 S2 推迟，项目维持零构建极简。
4. **S3（Tauri）最后做**，且前置项（浏览器弹出开关、单实例语义、跨平台 Node 统一）在 S3 前单独收口。
