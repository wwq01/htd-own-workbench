# S4 · 服务端部署方案

## 1. 形态与取舍

| 形态 | 启动方式 | 适用场景 | 安全要求 |
|---|---|---|---|
| 仅本机（默认） | `node backend/src/server.js` | 日常个人使用 | 无额外要求，与改造前完全一致 |
| 局域网 | `deploy/start.cmd`（配 `HTD_HOST=0.0.0.0`） | 家里/办公室内多设备（含手机、平板） | 建议设访问令牌 |
| 公网 / 域名 | 反向代理（Caddy / nginx）+ `HTD_ALLOWED_ORIGINS` | 外网访问 | **必须**设访问令牌 + HTTPS |

放弃桌面壳后，**浏览器就是客户端**。所有既有能力（30 张表、命令面板、Vault、RFP 应答等）原样可用，无需任何前端改造。

## 2. 快速开始

### 2.1 仅本机（默认，零配置）

```bash
cd backend && npm start
# 自动打开 http://127.0.0.1:17388
```

### 2.2 服务端常驻（局域网）

```bash
cp deploy/server.env.example deploy/server.env   # 按需修改（默认已是 0.0.0.0 + LAN）
```

Windows：`deploy\start.cmd`　|　Git Bash / Linux：`bash deploy/start.sh`

- 停止：`deploy\stop.cmd` / `bash deploy/stop.sh`
- 状态：`deploy\status.cmd` / `bash deploy/status.sh`
- 开机自启：`deploy\install-autostart.cmd`（登录即启动，计划任务，普通权限即可）
  卸载：`deploy\uninstall-autostart.cmd`

启动后控制台会打印实际监听地址与局域网地址：

```
访问地址: http://127.0.0.1:17388
局域网:   http://192.168.0.171:17388
运行模式: 服务端常驻（监听 0.0.0.0:17388）
访问令牌: 已启用
```

## 3. 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `HTD_HOST` | `127.0.0.1` | 监听地址。`0.0.0.0` 允许局域网/其他设备访问 |
| `HTD_PORT` | `17388` | 端口。可用值固定 17388/17389/17390，被占用自动顺延 |
| `HTD_SERVER` | 空 | `1` = 常驻模式：不开浏览器、不做「端口占用则复用退出」 |
| `HTD_LAN` | 空 | `1` = 自动把本机全部内网 IP 加入来源白名单（DHCP 换 IP 不失效） |
| `HTD_ALLOWED_ORIGINS` | 空 | 额外允许来源，逗号分隔；填 `*` 放行任意来源 |
| `HTD_ACCESS_TOKEN` | 空 | 访问令牌。**留空 = 不鉴权**（仅本机时安全） |
| `HTD_DATA_ROOT` | settings.json | 数据目录 |
| `HTD_TRUST_PROXY` | 空 | `1` = 信任反向代理，取 `X-Forwarded-For` 真实 IP |

> `deploy/server.env` 已在 `.gitignore` 中，令牌不会误提交。

## 4. 安全模型（三层）

1. **来源白名单（originGuard / CORS）**：写入类请求校验 Origin，白名单由
   `backend/src/common/utils/allowed-origins.js` 统一解析——回环 + 显式配置 + （`HTD_LAN` 时）内网 IP + `*` 通配。
   此前白名单在三处各写一份且硬编码为回环地址，现已收敛为单一来源，避免「页面能开、一保存就 403」。
2. **访问令牌（accessGuard）**：`HTD_ACCESS_TOKEN` 非空时全站需验证。
   - 内置登录页**自包含**（内联 CSS/JS，不依赖任何静态资源，否则会被本中间件自己拦成死循环）
   - Cookie 存的是令牌 SHA-256，且 `HttpOnly` + `SameSite=Lax`，页面 JS 读不到
   - `timing-safe` 比较，防逐字节爆破
   - 同时支持 `Authorization: Bearer <token>`，便于 curl / 守护脚本 / 健康检查
   - 例外：`/api/v1/system/health` 放行（信息量仅服务名/版本，便于探活）
   - 令牌为空时中间件直接放行 —— 既有本机模式零回归
3. **启动时安全自检**：监听非回环地址却未设令牌 → 日志打出显著告警。

**未覆盖**：无多账号/权限分级（本工作台定位个人自用）；无限流与审计。
放到公网时请在反向代理层补 HTTPS、限流与访问日志。

## 5. 前端配合

`frontend/js/api.js`：会话失效（401 或响应非 JSON）时统一提示并跳转验证页，避免页面只剩静默报错。
仅拦截走该封装的请求；导出、主题设置等直接 `fetch` 的接口不受影响。

## 6. 运维

- 日志：`logs/server.log`（sh）或 `logs/server.out.log` / `server.err.log`（cmd）；PID 文件 `logs/server.pid`
- 探活：`GET /api/v1/system/health`
- 端口顺延：17388 被占会顺延到 17389/17390，并把实际端口回写 `appConfig.port`
  （否则来源白名单与实际端口不一致，写入请求会全部 403）
- 多实例：启动脚本检测到已在运行会直接退出，避免多进程争抢 SQLite 写锁
