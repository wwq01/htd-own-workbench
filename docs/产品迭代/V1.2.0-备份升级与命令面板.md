## 0. 版本目标（一句话 + 预期收益）

**一句话目标**：建立 SQLite 整库级自动/手动备份恢复体系（含保留策略、损坏校验、安全回滚），上线 Ctrl/Cmd+K 命令面板补齐操作效率短板，同时落地 5 个 P0 基础设施借鉴（错误码/白名单/事件总线/5 态机/双层 timer），为 V1.3 业务深度打牢数据安全与工程底座。

**预期收益**：
- 数据层面：误操作/断电/升级失败可回滚到任意历史版本，恢复链路自带"先备份再覆盖"安全网，损坏的备份文件拒绝覆盖主库
- 效率层面：高频操作（跳转模块 / 新建记录 / 切主题 / 手动备份）从 3-5 次鼠标点击缩减为 2-3 键完成，重度用户手不离键盘
- 工程层面：后端错误统一三层码 + 白名单导出防敏感泄漏 + 事件总线解耦；前端草稿保存从"偶发丢数据"变为 5 态机可追溯 + 路由切换强制 flush，长任务 polling 指数退避不炸服务器，键盘可达性 ARIA 合规

## 5.1 备份恢复体系升级（8 项完整任务）

### 5.1.1 每日自动备份
- **任务**：启动器启动后首次 API 调用触发，或每日 00:00 后首次写入触发一次整库 SQLite 备份
- **实现位置**：`backend/src/services/backup.service.js` → `scheduleDailyBackup()`
- **策略**：不依赖 cron/定时器进程（Windows 下不可靠），走"懒触发"——每次写入操作检查 `lastDailyBackupAt`，超过当天则补备份
- **备份文件命名**：`backup-daily-YYYYMMDD-HHmmss.sqlite`（保留时间戳便于跨时区排序）

### 5.1.2 手动备份 + 命名
- **任务**：数据与备份页新增「立即备份」按钮，弹出 Modal 允许输入自定义备注名（可选）
- **实现位置**：前端 `frontend/src/views/DataBackup.vue` + 后端 `POST /api/backup/manual`
- **命名规则**：用户填备注则 `backup-manual-{备注}-YYYYMMDD-HHmmss.sqlite`，未填则 `backup-manual-YYYYMMDD-HHmmss.sqlite`
- **立即反馈**：备份完成后顶栏状态点切为「已保存」+ Toast 提示备份文件体积

### 5.1.3 备份清单 + 长期保留
- **任务**：数据与备份页列出所有备份文件（表格：文件名 / 类型（每日/手动） / 体积 / 创建时间 / 操作）
- **实现位置**：`GET /api/backup/list` 返回文件系统扫描结果；前端表格支持按时间倒序
- **长期保留**：手动备份默认永久保留（不参与自动清理），用户可单独删除

### 5.1.4 保留 30 份策略
- **任务**：每日自动备份仅保留最近 30 份，超出自动删除最旧的每日备份（手动备份不删）
- **实现位置**：每次自动备份成功后调用 `pruneDailyBackups(keep = 30)`
- **容错**：删除失败仅记录日志不抛错（不影响备份主流程）

### 5.1.5 恢复前安全备份
- **任务**：用户点击「恢复此备份」时，**先对当前主库做一次安全快照**（`backup-pre-restore-YYYYMMDD-HHmmss.sqlite`），再执行覆盖
- **实现位置**：`POST /api/backup/restore/:filename` → 第一步 `createPreRestoreSnapshot()` → 第二步 `copyBackupToMain()` → 第三步 `Prisma.$disconnect()` + 重连
- **收益**：恢复选错文件可一键回退到"恢复前那一刻"的状态

### 5.1.6 恢复校验完整性 + 迁移版本拒绝覆盖
- **任务**：恢复前两步校验——① 校验 SQLite 文件头完整性（`SQLite format 3\0` 魔数）+ 跑 `PRAGMA integrity_check` 返回 `ok` 才允许覆盖；② 备份文件内 `_schema_version` 表（V1.2 新建）读取版本号，**若备份版本 > 当前运行版本则拒绝**（防止新版本降级覆盖，升级必须先升级运行版本再恢复旧备份）
- **实现位置**：`restoreBackup()` 内 `validateSQLiteFile()` + `checkSchemaVersionCompatible()`
- **错误提示**：损坏 → "备份文件已损坏，无法恢复（已保留原主库）"；版本过高 → "备份由更高版本创建，请先升级工作台再恢复此备份"

### 5.1.7 备份失败状态提示
- **任务**：顶栏新增备份状态点（4 态：未备份/备份中/已备份/失败），失败时鼠标悬停显示失败原因（磁盘满 / 权限不足 / SQLite 被锁等）
- **实现位置**：前端 `StatusDot` 组件（§5.3b）+ 后端 backup 路由所有错误走 BackendError 三层码（§5.3e）
- **降级策略**：连续失败 3 次自动暂停自动备份，数据与备份页显式红条提示 + 手动重试按钮

### 5.1.8 backup.test.js 测试
- **任务**：`backend/tests/backup.test.js` 覆盖以上 7 项的自动化测试
- **测试用例清单**：
  1. 每日备份懒触发：首次写入触发、同日二次写入不重复触发
  2. 保留 30 份：造 35 份每日备份 → prune 后剩 30 份 + 手动备份不受影响
  3. 恢复前安全备份：恢复后磁盘存在 pre-restore 文件 + 内容等于恢复前主库
  4. 损坏文件拒绝：手工构造损坏 SQLite（改字节） → integrity_check 失败 → 拒绝覆盖 + 主库内容不变
  5. 版本过高拒绝：备份文件 _schema_version=999 → 当前版本=1 → 拒绝覆盖 + 主库内容不变
  6. 手动备份命名：带备注 / 不带备注两种文件名正确
  7. 备份失败状态：模拟磁盘满 → 顶栏状态点=失败 + 原因正确

### 5.2.2 拼音首字母模糊匹配

### 5.2.3 回车 / Esc 交互

## 5.3 联调打磨（5 项，标注 [L1]/[L2]/[L1+L2] 归属层）

### 5.3.1 接口 Origin 校验 **[L1 行为]**
- **任务**：后端所有写入类接口（POST/PUT/DELETE）校验 `Origin` 请求头，仅允许 `http://127.0.0.1:{port}` 与 `http://localhost:{port}` 通过，其他 Origin 直接返回 403 + BackendError `ORIGIN_FORBIDDEN`
- **实现位置**：`backend/src/middleware/origin-guard.js`，App 中间件在路由之前挂载
- **GET 接口放行**：只读 GET 请求不校验（便于本机浏览器不同端口临时调试），但所有 GET 返回 `X-Content-Type-Options: nosniff`
- **测试**：backup.test.js 追加用例——非 127.0.0.1 Origin 发起 POST → 403 + 主库未修改

### 5.3.2 保存状态细化：顶栏「已保存 / 保存中 / 失败」 **[L1+L2]**
- **L1 行为**：Pinia 全局 `uiStore.saveState` 三态枚举（`saved` / `saving` / `failed`），每次 API 请求前 → `saving`，成功 → `saved`（2.5s 后回到 idle），失败 → `failed`（悬停显示错误详情）
- **L2 装饰**：顶栏左侧状态点组件（§5.3b）4 态颜色 + 脉冲动画；`saved` 态绿色对勾图标，`saving` 态旋转 loading（τ 阻尼），`failed` 态红色叉号 + 轻微 shake（prefers-reduced-motion 时 shake 降级为纯颜色）
- **归属层**：三态逻辑 = L1；颜色/脉冲/shake = L2（装饰开关控制）

### 5.3.3 启动器端口顺延 + 复用进程 **[L1 行为]**
- **任务**：pkg 打包启动器默认端口 `17388`，若被占用则依次尝试 `17389` / `17390`，3 个都被占则报错"端口 17388-17390 均被占用，请关闭其他工作台实例"
- **进程复用**：启动时先检测端口是否已有工作台实例在跑（发送 `GET /api/health` 返回 `{ service: 'htd-own-workbench', version }` 判定成功），**若已存在则直接 `exec('start http://127.0.0.1:{port}')` 打开浏览器，不启动第二份 Node 进程**（避免多进程写 SQLite 锁冲突）
- **实现位置**：`launcher/run.vbs` / `launcher/run.bat`（pkg 入口脚本）→ 端口探测循环 + 健康检查 + 复用分支
- **手测项**：先双击 exe 打开实例 1 → 再次双击 exe → 只打开新浏览器 tab（任务管理器 Node 进程数不变）

### 5.3.4 手动保存按钮（顶栏） **[L1+L2]**
- **L1 行为**：顶栏右侧新增「💾 保存」按钮，点击触发所有已挂载草稿组件的 `flush()` 方法（§5.3d forwardRef），全部成功后 Toast「全部草稿已保存」，部分失败则列出失败模块名
- **L2 装饰**：按钮 hover 轻微放大 1.02x（τ 阻尼 200ms），保存中按钮变 loading 态不可重复点击
- **归属层**：flush 编排 + 错误聚合 = L1；hover 动效 + loading 过渡 = L2（装饰开关）

### 5.3.5 回收站三段式：二次确认永久删除 **[L1 行为]**
- **任务**：所有软删除数据（任务/项目/凭据/备忘等）统一进入「回收站」视图，三段式流程：
  1. **第一段**：业务模块点「删除」→ 软删除（`deletedAt = now()`）→ 不弹出确认，Toast「已移至回收站，30 天后自动永久删除」
  2. **第二段**：回收站视图点「永久删除」→ **Modal 二次确认**（红色警告文案 + 需手动勾选「我确认此操作不可撤销」复选框 + 输入 `DELETE` 三个字母才激活确认按钮）
  3. **第三段**：确认后物理 DELETE + Toast「已永久删除，不可恢复」
- **实现位置**：`backend/src/middleware/soft-delete.js` + 前端通用 `ConfirmPermanentDelete.vue` Modal 组件
- **自动清理**：V1.2 仅做手动永久删除；30 天自动清理留到 V1.4（不抢本期工期）

- **L1 行为**：所有列表为空时，空态组件统一走 `{ title: '当前场景描述', actionText: '下一步操作按钮文案', actionHandler }` 两段式结构，禁止纯"暂无数据"四个字

### 5.3b.5 URL 即状态：useSearchParams **[L1 行为]**
- **L1 行为**：模块内筛选条件（日期范围 / 搜索关键字 / Tab 选中项）同步到 URL query string，刷新页面 / 分享链接可还原；Vue 3 无构建版不用 Vue Router 的 `useRoute`，直接手写 `useSearchParams()` 组合式函数（`get` / `set` / `watch` 三个 API）
- **实现位置**：`frontend/src/composables/useSearchParams.js`，内部用 `window.location.search` + `URLSearchParams` + `popstate` 事件监听

## 5.3d 借鉴 ReaderWorkspace 草稿状态机（6 项，每项落地文件路径 + 预期收益）

### 5.3d.1 Note 5 态机 + revision 单调递增
- **借鉴来源**：[ReaderWorkspace.jsx:66-104](file:///D:/WorkSpace/%E7%AC%AC%E4%B8%89%E6%96%B9%E5%B7%A5%E4%BD%9C%E5%8F%B0%E5%80%9F%E9%89%B4/person_dashboard/Workbench/src/components/reader/ReaderWorkspace.jsx#L66-L104)
- **落地文件路径**：`frontend/src/utils/draft-state.js` → 导出常量 `DRAFT_STATUS = { PENDING: 'pending', SAVING: 'saving', SAVED: 'saved', FAILED: 'failed', NULL: null }` + `createDraftState(initialContent)` 返回 `{ status, content, revision, lastSavedAt, error }`
- **规则**：每次内容变更 `revision += 1`（单调递增，不允许回退），后端保存响应必须带回 `serverRevision`，前端比对 `serverRevision >= clientRevision` 才切 SAVED，否则强制 FAILED（防版本覆盖）
- **预期收益**：草稿保存状态不再是"成功/失败"二元，可区分「用户正在输入还没发」（pending）「请求在路上」（saving）「服务器确认已存」（saved）「网络/校验失败」（failed）四种场景，UI 状态点精准显示

### 5.3d.2 双层 timer + inFlight 队列 → 防抖 650ms + 3 入口
- **借鉴来源**：[ReaderWorkspace.jsx:506-563](file:///D:/WorkSpace/%E7%AC%AC%E4%B8%89%E6%96%B9%E5%B7%A5%E4%BD%9C%E5%8F%B0%E5%80%9F%E9%89%B4/person_dashboard/Workbench/src/components/reader/ReaderWorkspace.jsx#L506-L563)
- **落地文件路径**：`frontend/src/utils/draft-saver.js` → 类 `DraftSaver`
  - **第一层 debounce timer（650ms）**：输入事件触发，650ms 内再次输入则重置
  - **第二层 flush timer（2000ms 兜底）**：如果用户持续输入不停，2s 到点强制发一次请求（防止 pending 堆积太久）
  - **inFlight 队列**：请求发出后把 `{ revision, promise }` 入队，响应回来出队；如果队列里 revision 比当前本地旧，**丢弃该旧响应**（不覆盖新内容）
  - **3 入口触发**：① debounce 到期自动；② flush 2s 兜底；③ 用户点击「手动保存」按钮 / 路由切换前（§5.3d.3）强制 flush
- **预期收益**：既不会"每按一个键发一次请求"把服务器打挂，也不会"用户写了 5 分钟忘点保存断电丢数据"；inFlight 队列彻底解决「旧请求后回来覆盖新内容」的经典竞态

### 5.3d.3 forwardRef + useImperativeHandle → 暴露 flush()
- **借鉴来源**：[ReaderWorkspace.jsx:601](file:///D:/WorkSpace/%E7%AC%AC%E4%B8%89%E6%96%B9%E5%B7%A5%E4%BD%9C%E5%8F%B0%E5%80%9F%E9%89%B4/person_dashboard/Workbench/src/components/reader/ReaderWorkspace.jsx#L601)

### 5.3d.5 Polling 退避指数：800 → 1600 → 3200 → 4800 封顶
- **借鉴来源**：[reader-ui.js:192-200](file:///D:/WorkSpace/%E7%AC%AC%E4%B8%89%E6%96%B9%E5%B7%A5%E4%BD%9C%E5%8F%B0%E5%80%9F%E9%89%B4/person_dashboard/Workbench/src/lib/reader-ui.js#L192-200)

## 5.5 验收

### 5.5.1 自动化测试覆盖（backup.test.js）

- ✅ 保留 30 份清理正确 + 手动备份不被清理
- ✅ 恢复前自动快照 + 快照内容等于恢复前主库

- ✅ 手动备份命名（带备注 / 不带备注）正确
- ✅ 备份失败状态码（磁盘满 / 权限）→ BackendError 三层码正确

### 5.5.2 手测项：浏览器
- **命令面板**：
  - Ctrl/Cmd+K 打开面板，输入「项目」「今日」「备」命中正确跳转
  - 输入「暗」切暗色，输入「亮」切亮色（实时生效）
  - Enter 执行、Esc 关闭、↑↓ 选 1-9 项均正常
  - 关闭 prefers-reduced-motion 后：面板打开无过渡、选中项无脉冲（仅颜色变化）
- **回收站三段式**：
  - 删 1 条任务 → Toast「已移至回收站」→ 业务列表消失
  - 回收站点「永久删除」→ 不勾选复选框 + 不输入 DELETE 时，确认按钮禁用
  - 勾选 + 输入 DELETE → 二次确认按钮激活 → 删除后回收站消失
- **Origin 校验**：
  - 本机浏览器正常操作全部通过
  - 模拟 Origin = `http://evil.com` 发 POST /api/backup/manual → 返回 403 + 备份目录无新文件

### 5.5.3 手测项：启动器
- **端口顺延**：手动 `netstat` 占 17388 → 启动工作台 → 打开 17389 正常运行
- **进程复用**：工作台已开 17388 → 再双击 exe → 任务管理器 Node 进程数不变 + 浏览器新开 17388 Tab
- **版本升级不丢数据**：
  - 在 V1.1.0 手动创建 10 条任务 + 3 个项目 + 5 条凭据
  - 替换 V1.2.0 exe 启动 → 数据完整显示 + 自动备份 1 份 daily + 手动备份 1 份命名验证可恢复
