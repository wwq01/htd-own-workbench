## 1. 背景与目标

S1/S2-1 完成后，前端从「43 个有序 `<script>`」收敛为 Vite 单入口聚合（`dist/`），但**组件形态与渲染机制未变**——仍是「IIFE 全局 Vue + JS 组件 + template 字符串」。遗留两大问题：

- **P0-3（架构审计报告）**：`charts.js` 用「字符串拼接 + `v-html`」渲染 SVG，每帧重算全量，力导向布局不可达 → 知识图谱 1k 节点验收硬性不兼容。
- **组件缺口（视觉审计 §5.5）**：`Skeleton/Switch/Table/Drawer/Tooltip/MarkdownEditor/GraphCanvas` 全部缺失，各模块列表/空态/二次确认/Markdown 渲染各自为战。

S2 是**组件化与能力深化**阶段，路线图含 5 个工单（S2-2 ~ S2-6），其中 **S2-2 知识图谱是 D1 硬需求**（战略已裁定：1k 节点流畅 → S2 必做）。

## 3. 技术选型决策（⚠️ 需裁定，见 §7）

### 3.1 组件化路线（红线相关，必选 A 或 B）

- **路线 A（推荐，低风险）**：保持 `window.Vue` IIFE 全局，**不引入 SFC / 编译器**。
  - `charts.js` 改写为**组合式/选项式 JS 组件**（用 `computed` 响应式生成 SVG 字符串或 `render` 函数），数据更新只触发最小重渲染，根治 P0-3「整段重算」。
  - 图谱引入 **`d3-force`**（纯计算库，无 DOM 依赖），经 Vite 打包进 `dist/`；Vue 响应式驱动 SVG 渲染，不引入重 DOM 操作。
  - ✅ 守住两条红线：业务代码 0 改动进 Tauri（仍是 IIFE Vue 写法）、离线优先（运行时零网络）。

- **路线 B（高改动）**：引入 `vue` ESM + `@vue/compiler-sfc`，全面 SFC（`.vue`）化。
  - 标准工程形态，但需重构 IIFE 全局加载链路（`index.html` 三库 + `entry.js` 副作用 import 全部重做），与「低风险演进式」战略不符，风险高、回归面大。

### 3.1-B 路线 B 落地策略（兼容式渐进迁移）

用户 2026-09-11 裁定采用路线 B（全面 SFC 化）。但「全面」是**最终态**，执行上采用兼容式渐进迁移，避免一次性重写 21 模块 + 12 组件导致的回归雪崩：

1. **B0 基建（加载机制切换）**：安装 `vue`（ESM）+ `@vitejs/plugin-vue` + `@vue/compiler-sfc`；`main.ts` 以 `import { createApp } from 'vue'` 启动，并 `window.Vue = Vue` / `window.Pinia = Pinia` 兼容旧代码；`index.html` 收敛为单 `<script type=module src=/src/main.ts>`，移除 IIFE 三库 script；`vite.config.js` 加 `vue()` 插件、移除 `copyIifeLibs`。**旧 JS 组件因 `window.Vue` 兼容继续工作，功能等价 S2-1。**
2. **B1 地基（S2-6）**：新建 Skeleton/Switch/Table/Drawer/Tooltip/MarkdownEditor 直接用 **SFC（.vue）** 编写，树立规范。
3. **B2 核心（S2-2）**：图表改写为 SFC 组件（响应式 SVG）+ 挂载 lineChart + 知识图谱 GraphCanvas（SFC + d3-force）。
4. **B3 渐进迁移**：后续版本逐步把现有 12 组件 + 21 页面模块从「JS 组件 + window.Vue」改写为 SFC；完成前 `window.Vue` 兼容层保留。
5. **离线优先**：Vue/Pinia/d3-force 全部构建期打包进 `dist/`，运行时零网络；IIFE 全局库不再随 dist 发布。

> 风险：B0 切换后，任何仍依赖 IIFE 全局但被误删的引用会白屏；故 B0 必做全量回归（启动 + 21 模块挂载 + lint + vitest）守门。

### 3.2 d3-force 引入 vs 自写力导向

- **推荐引入 `d3-force` 单包**（min ~50KB，仅 `forceSimulation/forceManyBody/forceLink/forceCenter` 等纯计算模块），Vite 打包进 `dist/`，运行时零网络 → **满足离线优先**。
- 备选自写简单力导向（零依赖，但需自调参、稳定性/性能需自证，工期反而更长）。
- 引入方式：在 `frontend/` 受管工作区 `npm install d3-force`（仅此纯计算库），某图谱模块 `import { forceSimulation } from 'd3-force'`，Vite 自动打包。

### 3.3 离线优先如何满足（澄清红线误解）

- S2-1「零 npm 依赖」是为**低风险平移**临时约束，非永久红线。
- 离线优先红线 = **运行时禁止从 CDN 拉取**。构建期把依赖（d3-force）打进 `dist/`（本地静态资源）完全合规。
- 调整：`vite.config.js` 注释与策略由「零 npm 依赖」放宽为「**仅纯计算 / 渲染库可打包进 dist**（禁止任何运行时网络依赖）」；vue/pinia 仍走 IIFE 全局（避免引入 Vue 编译器）。

## 5. 各工单拆解 + 出口判据

### S2-6 地基组件 + Token 单一来源
- 新建 `frontend/js/components/`：`HtpSkeleton.js` / `HtpSwitch.js` / `HtpTable.js`（统一列表骨架/空态/分页）/ `HtpDrawer.js` / `HtpTooltip.js` / `HtpMarkdownEditor.js`（markdown-it 强渲染，S2-3 复用）。
- Token 单一来源：JS 侧图表色全部读 `var(--chart-series-*)`，无裸 hex 逃逸（M0-1 已部分做，收口残留）；补图标回归测试（NAV_ITEMS/COMMANDS 的 icon 键均在 `icons.js` 存在）。
- 增强 `HtpInput`：`$attrs` 透传 `step/min/extra class`（S1-2 收口）。
- 出口：新组件各补单测；`grep` 无 JS 裸 hex；图标回归测试绿。

### S2-2 图表/图谱组件化（D1 硬需求）
- 图表：`charts.js` 改写为 Vue 组件（bar/donut/line/stackedBar/timeline），`computed` 响应式生成 SVG，调用方用 `<component>` 而非 `v-html`；挂载 `lineChart` 到首页/财务趋势位（消 P2-2）。
- 图谱：新建 `GraphCanvas.js`（Vue 组件 + d3-force 布局 + SVG 渲染），支持节点/边/拖拽/缩放，1k 节点性能门槛。
- 出口：P0-3 根治（`v-html` 图表调用清零）；`lineChart` 有挂载点；**知识图谱 1k 节点 ≥30fps（中）/60fps（验）**；新增布局稳定性/空数据/性能单测。

### S2-3 Vault 深化
- `VaultPage` 从纯文本渲染升级：双向链接（`[[note]]`）、标签树、引用图谱（复用 `GraphCanvas`）、markdown-it 强渲染。
- 出口：Vault 非纯文本；双链可跳转；引用图谱节点可达。

### S2-4 Note 双轨
- Note 模型 free/quote 双轨 + anchor 双向跳转（笔记 ↔ 原文）。
- 出口：笔记↔原文可互跳。

### S2-5 RFP 逐条应答
- Bid 模块新增 RFP 条目级结构（条目 + 应答 + 证据挂载）。
- 出口：Bid 支持条目级应答 + 证据挂载。
