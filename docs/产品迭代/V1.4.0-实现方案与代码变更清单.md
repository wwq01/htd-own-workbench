## 0. 一句话结论

V1.4 = 在**不改动任何现有业务模块**前提下，补齐工程化底座（多套外观切换 + 跨平台启动器 + CI）并新增 4 个独立业务模块（POC 跟踪 / 投标档案 / 漏洞跟踪库 / 应急响应记录），并把版本号、文档、代码结构统一推进到 `1.4.0`，且 100% 兼容现有主要功能。

三条核心收益：**用得久**（2 套外观 × 暗/亮按需切换，仅 CSS 变量、零数据迁移）、**跑得稳**（CI 门禁把"本地能跑"变"合并即可信"）、**挂得动**（4 新模块仍走既有四触点挂载，验证模块可持续挂载能力）。

### 1.1 兼容性总原则（贯穿全文）

1. 新业务模块零侵入现有模块：每模块 = 新增文件 + 在 4 处各加 1 行，不修改任何现有模块代码路径。
2. 主题仅覆盖 CSS 变量：组件 CSS 零改、class 名契约不变、JS 不动。
3. 暗/亮与外观解耦：切换只改 `<html>` 上的 data 属性，SQLite 业务数据完全不动。
4. 现有模块最小改动仅限系统设置内部（外观选择器 + 兼容 `applyTheme` 旧调用）。

## 3. 设计令牌（两套外观）

> 完整 JSON 见设计师交付；此处给出锁定结论。两套外观**共用同一套语义令牌骨架**，仅覆盖「外观层」令牌，组件零改动。

### 3.1 两套外观差异签名（CI 自动断言）

| 令牌 | Liquid Glass | Notion 极简平铺 |
| --- | --- | --- |
| `--glass-blur` | 22 | 0 |
| `--glass-bg` | 半透明 | 实色 |
| `--glass-border` | 高光描边 | 发丝线 |
| `--glass-highlight` | 有 | transparent |
| `--bg-spot-1/2` | 有色光斑 | transparent |
| `--bg-gradient` | 分层渐变（靛蓝/青，非紫粉） | 实色 |
| `--shadow-card` | 非空 | null |
| `--radius-base` | 12 | 6 |
| `--spacing-base` | 16 | 12 |
| `decorations.glassStyle` | glass | flat |

### 3.2 P0 红线核对（规划层已内建）

- 图标全部沿用锁定 `HTD_ICONS` SVG，**无 emoji**；
- 背景墙渐变主相为靛蓝/青，杜绝紫粉渐变；
- 所有取值经 Design Token 引用，组件 CSS 无硬编码色（现有 components.css 已合规）；
- 动效缓动统一 `cubic-bezier(0.2,0.8,0.2,1)`，**禁用** `cubic-bezier(0.68,-0.55,0.265,1.55)` 弹跳；
- 工作台为应用内 UI，文案沿用真实业务文案，无营销 Hero。

### 3.3 theme.json 规范字段（CI 校验对象）

顶层必含：`id / name / version / appearance / supportsDarkLight / dark / light`；每套含 `colorPalette / borderRadius / shadows / typography / motion / spacing / decorations`。`validate-theme.js` 校验：字段齐全、暗亮双套存在、半径 ≤28、时长 ≤400ms、easing 非弹跳、对比度 WCAG AA。

### 3.4 可访问性（WCAG AA）

`fgPrimary/fgSecondary/fgTertiary` 对 `panel/bgPage` 对比度四套均 ≥4.5:1（fgTertiary 临界项已收紧取 `#566573` / `#6B6A66`）。注意：主色按钮白字（`#5B8DEF`）对小号文字临界，建议小号/窄屏主按钮文字改用更深主色 `#2456BF` 以保 4.5:1。

## 4. 技术方案

### 4.1 多主题切换架构（三维模型）

| 维度 | 取值 | 落点 |
| --- | --- | --- |
| `data-theme` | dark / light | `<html>`（既有，保留） |
| `data-appearance` | liquid-glass / notion-flat | `<html>`（新增） |
| `data-decoration` | on / off | `<html>`（新增，仅 liquid-glass 生效；notion-flat 强制 off） |

**前端主题管理器** `frontend/js/utils/theme-manager.js`（新增）：启动最早执行（置于 `app.js` 之前）防 FOUC；双写 `localStorage['htd-theme']` + `settings.json`；`applyTheme({appearance,theme,decoration})` 仅设三属性；`prefers-reduced-motion` 时动画时长强制 0；暴露 `window.htdTheme` 供设置页/命令面板调用。降级：令牌缺失/加载失败 → 回退 Liquid Glass 默认。

**现有 3 个 CSS 重组为「基础令牌 + 每外观覆盖层」**（零改选择器/类名）：

- `global.css`：`:root` 保留既有值作兜底；新增 `html[data-appearance="notion-flat"]` 覆盖块（重映射 `--glass-*` 为实色/0、背景墙改实色）+ `html[data-appearance="notion-flat"][data-theme="light"]` 组合块 + `html[data-decoration="off"] body { background-image:none }`。
- `components.css` / `pages.css`：**不改任何选择器/属性值**（组件已引用 `--glass-*`/`--shadow-*`/`--border-*`，覆盖层自动令其变平）。

### 4.2 跨平台启动器

- **macOS** `build/launcher/荒天帝工作台.command`（新增）：内联端口探测 17388→17389→17390；`GET /api/v1/system/health` 命中 `service==='htd-own-workbench'` → 仅 `open` 浏览器并退出（复用）；取首个空闲端口以 `HTD_PORT` 启动 mac 二进制；读 `HTD_DATA_ROOT`/`HTD_PORT`；`upgrade` 子命令先 `cp -R` 备份旧二进制再覆盖（数据目录不动，靠 V1.2 自动备份兜底）。
- **Windows**：`pkg` 已产出单文件 exe，server.js 内已落地端口探测/顺延/同源复用（V1.2）。**无需重写**。仅可选新增 `build/launcher/start-htd.bat` 做设环境变量 + 升级前备份 exe + 启新 exe。
- 职责边界：v1.4 启动器 = 调用壳 + 升级备份；V1.2 server.js = 端口/复用能力。复用而非重写。

### 4.3 CI 设计（`.github/workflows/ci.yml`，新增）

| Job | Runner | 命令 | 门禁作用 |
| --- | --- | --- | --- |
| lint | ubuntu | `node scripts/validate-theme.js` + `node scripts/visual-audit.js` + `node --check` | 主题/契约/禁项守门 |
| typecheck | ubuntu | `node scripts/check-schemas.mjs`（加载全部 schema/enums/stateMachine 确认可导入） | JS 项目「类型」守门 |
| test | ubuntu (Node 24) | `npm test`（vitest run，268+ 用例） | 功能回归 |
| build | windows / macos | `npm run build:win` / `build:mac` | 产出 exe / mac 二进制 |
| launcher-test | macos | `.command` 探针 harness（探测占用→顺延→health 复用断言） | 启动器正确性 |

门禁：`needs:[lint,typecheck,test]` 全绿，build/launcher-test 才允许；branch protection 要求 CI 全绿；release 额外要求 build 成功。所有 job `node-version:24`。

### 4.4 四个新模块 API 与 DB Schema

通用约定：同源守卫（无登录态，本地单人）；5 层（router/service/controller/schema/repository）+ Prisma model + `app.js` 挂载；service 必有 `toPublic()` 白名单；状态变更统一经 `createStateMachine`；软删除 `deletedAt`；列表支持 `?q=&page=&limit=&sort=`；`toPublic()` 返回驼色干净对象（`deletedAt` 不导出）。

#### 4.4.1 POC 跟踪（工作）— `PocTracking`

字段：`id, goal(必填), environment?, customerParticipants(JSON[]), result?, status(default 'draft'), projectId?(软链无 FK), sortOrder, createdAt/updatedAt/deletedAt`；索引 `[status],[projectId]`。
状态机 `POC_STATUS_TRANSITIONS`（6 态）：`draft:[scheduled,cancelled]; scheduled:[in_progress,cancelled]; in_progress:[success,failed,cancelled]; success/failed/cancelled:[]`。
端点：`GET/POST /api/v1/pocs`、`GET/PUT/DELETE /api/v1/pocs/:id`、`PATCH /api/v1/pocs/:id/status`。

#### 4.4.2 投标档案（工作）— `BidArchive`

字段：`id, bidNo(必填,唯一), deadline?(YYYY-MM-DD), bidVersion?, bidResult(default 'pending'), status(default 'draft'), projectMilestoneId?(仅存 id 无 FK 无级联), sortOrder, ...`；索引 `[bidResult],[status],[projectMilestoneId]`。
轻状态机 `BID_STATUS_TRANSITIONS`：`draft:[submitted,archived]; submitted:[archived]; archived:[]`。
端点：同模板（`bids`）；另增 `GET /api/v1/bids?milestoneId=` 软关联查询（按存值过滤，不 JOIN 不级联）。

#### 4.4.3 漏洞跟踪库（资产组隔离）— `VulnTrack`

字段：`id, assetGroup(必填,隔离维度), vulnId(必填), affectedProduct?, exploitMethod?, reproduction?, fixStatus(default 'open'), severity(default 'medium'), sortOrder, ...`；索引 `[assetGroup],[fixStatus],[vulnId]`。
状态机 `VULN_FIX_STATUS_TRANSITIONS`（5 态）：`open:[fixing,wont_fix,closed]; fixing:[fixed,wont_fix,closed]; fixed:[closed]; wont_fix:[closed]; closed:[]`。
端点：同模板（`vulns`）；列表必带 `?assetGroup=`（前端分组切换即切该参数）。隔离用字段而非独立表（避免第 5 个 model，未来可拆）。

#### 4.4.4 应急响应记录（工作）— `EmergencyResponse`

字段：`id, title(必填), eventTimeline(JSON[]), responseActions(JSON[]), review?, status(default 'open'), severity(default 'medium'), sortOrder, ...`；索引 `[status],[severity]`。
状态机 `EMERGENCY_STATUS_TRANSITIONS`（4 态）：`open:[contained,resolved,closed]; contained:[resolved,closed]; resolved:[closed]; closed:[]`。
端点：同模板（`incidents`）；另增 `POST /api/v1/incidents/:id/timeline`（追加时间线条目）、`POST /api/v1/incidents/:id/actions`（追加处置动作）——服务端校验 JSON 结构后合并写回（标准化模板保证字段一致）。

#### 4.4.5 四模块 × 四处注册关系总表

| 模块 | ① router.js | ② index.html | ③ app.js NAV+pageComponents | ④ dataStore.js action | 后端 app.js |

| 应急 | `/incident`→`incident` | `IncidentPage.js` | `IncidentPage` | `fetchIncidents/.../addIncidentTimeline/...` | `incidents` |

## 6. 代码改动要求（实现期纪律）

1. 严格走「4 处注册 + 后端 5 层 + Prisma model + app.js 挂载」既有模式，禁止为 4 模块发明新机制。
2. 任何状态变更必须 `createStateMachine(...).transition(...)`，禁止 service 内手写 if/else 校验（非法迁移统一 `PARAM_ERROR`）。
3. 每个 service 必须有 `toPublic()` 白名单导出，`deletedAt`/内部路径绝不外泄。
4. CSS 只加覆盖块，选择器/类名零增删；任何新色值只能出现在 `:root`/覆盖层/theme.json，组件 CSS 不得裸写色（P0）。
5. 导航与命令面板 icon 只用 `icons.js` 已有 SVG（或按同风格 24px 增补并登记），禁 emoji。
6. 所有动效 `transition` ∈ [80,400]ms、easing 非弹跳，且 `prefers-reduced-motion` 时归零。
7. 版本号三处（appStore/app.config/package.json）+ README + 版本日志同步 bump 到 1.4.0。
8. Prisma 变更必须生成 migrate 并重建 `template.db`，发版前在文档提示用户先手动备份。

### 8.1 端到端验证思路（节选）

- 主题持久化：`PUT /api/v1/system/settings {"themeFamily":"notion","mode":"light"}` → 200；`{"themeFamily":"blue"}` → 400；刷新后 GET 仍 notion/light。
- 端口顺延：占用 17388 启动 → 断言监听 17389；再占 17389 → 17390。
- 已运行复用：起实例 A 占 17388，再起 B → 断言仅 1 条 LISTEN。
- 4 模块 CRUD：隔离库内 `POST /api/v1/pocs {"title":"客户A POC",...}` → 201；`{"title":""}` → 400。
- CI 门禁：`ci.yml` 任一 step 非零即阻断合并。
- 版本同步：`grep -rho "1\.4\.0" <5落点>` → 期望仅 1.4.0。

### 8.2 测试策略

- 分层：单元 Vitest ~70%（service/zod/stateMachine 穷举/端口/theme 解析）、集成 Vitest+隔离 SQLite ~25%（route→service→DB 全链路）、E2E Playwright ~5%（主题即时+持久、双主题 8 页截图、4 模块四触点无白屏、.command 启动）。
- 命名：后端 `backend/src/modules/<module>/<module>.test.js` + `<module>-statemachine.test.js`（沿用 todo 模板）；前端 `tests/e2e/*.spec.js`。
- **测试完整性反作弊门（P0）**：检测测试文件删除、断言数不降、无新增 skip/xfail/.only、断言非硬编码实现值、测试框架配置未被篡改降阈值；发现任一 → 阻断，不计「通过」。
- 隔离：统一读 `HTD_TEST_DB_URL`（test-setup.js 复制 template.db），**禁止直连生产库**。

## 12. ADR（关键决策，文本版；实现期落 `docs/decisions/`）

- **ADR-v14-01 双轴主题模型**：`data-theme`(明度) × `data-appearance`(材质) × `data-decoration`(开关) 三属性，而非单一 theme 枚举。理由：LG 与 Notion 是表面材质差异非配色差异，分轴可独立演化（未来加 Neo 只需新 appearance 层）。
- **ADR-v14-02 启动器复用后端能力**：macOS .command / Windows .bat 仅做端口探测壳 + 升级备份，复用 V1.2 server.js 同源探测/顺延/复用逻辑，不重写。
- **ADR-v14-03 漏洞资产组用字段而非独立表**：MVP 用 `assetGroup` 必填字段+索引实现隔离，不新增第 5 个 model；未来若需元数据再拆表（迁移兼容）。
- **ADR-v14-04 theme.json 为令牌单一事实源**：内置主题由 CSS 覆盖层提供运行时值，theme.json 同时作 CI 校验对象与未来自定义主题格式，避免双源漂移。
