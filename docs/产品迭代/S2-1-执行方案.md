# S2-1 Vite 构建化 · 执行方案（Spec 附录）

> 依据：V2.0-全面重构计划.md §S2。本文件是 S2-1 的落地 Spec，执行前需确认。
> 门禁纪律：lint → 构建 → 冒烟 → 全量测试，每批一闸。P0 红线（禁 emoji 图标 / 禁紫粉渐变 / 禁硬编码色 / 禁弹跳缓动）不变。

## 一、目标与出口判据
- `vite build` 产出 `frontend/dist/`，后端静态服务可正常运行，**首屏无白屏**（侧边栏 + 首页组件渲染）。
- 保留 JS 组件 + template 字符串写法（**不改写为 `.vue` SFC**）。
- 模块注册 0 手工：`registry.js` 单一数据源不变，`verify-registry` 门禁不变。
- 后端全量测试 **427/427 不受影响**（前端改动不触碰后端）。
- 离线 exe 仍构建成功且功能等价（pkg 改打 `dist/`）。
- 视觉文件仅增 `import`，**不动类名 / 不动色值**（visual-audit 门禁守护）。

## 二、现状证据（已取证）
- 前端为「无构建」全局脚本：`index.html` 顺序 `<script>` 加载本地 IIFE 包（`vue.global.prod.js` / `vue-demi.iife.js` / `pinia.iife.prod.js`）+ 60 个全局 JS。
- 全局附着模式已确认：模块/组件/store 末尾均 `window.X = X`（`HomePage.js:377`、`HtpButton.js:34`、`uiStore.js:52`、`api.js:138`、`router.js:142`、`icons.js:49`、`store/index.js:6`）。
- `registry.js` `buildPageComponents()` 用 `window[component]` 延迟查找 —— 依赖上述附着。
- 后端 `express.static(frontendDir)` 服务前端；pkg assets 含 `frontend/**`。
- Vite 已在 `backend/node_modules`；**vue/pinia 仅 IIFE 全局包，npm ESM 包未装**（且 npm registry 当前可能不可达）。

## 三、关键设计决策：vue/pinia 走 external 全局（不装 npm 包）
为避免依赖网络、守住离线优先，Vite 把 `vue` / `pinia` 标记为 **external**，映射到现有 IIFE 全局 `Vue` / `Pinia`：
- `vite.config.js`：`build.rollupOptions.external: ['vue','pinia']` + `output.globals: { vue:'Vue', pinia:'Pinia' }`。
- `index.html` 保留三个 IIFE `<script>`（全局），再加一个 `<script type="module" src="/src/entry.js">`（Vite 产物）。
- 源文件里 `import Vue from 'vue'` / `import { defineStore, createPinia } from 'pinia'` 由 Rollup 解析为对应全局，**逻辑/template 零改写**。
- 若后续 registry 可达且想纯 ESM，可改 `npm i vue@3 pinia@2` 并去掉 external —— 本方案以 external 为默认（最稳）。

## 四、转换策略（机械改动，业务代码零改）
核心：每个源文件只「加 import + 保留 window 自附着」；由 entry 按 `index.html` 原顺序 import 触发副作用，`registry` 的 `window[component]` 照常工作。

| 文件类 | 改动 |
|---|---|
| 组件 / 页面模块（用 `Vue.*`） | 顶部加 `import Vue from 'vue';`，保留 `window.X = X` |
| Store（`appStore`/`uiStore`/`dataStore`） | `import { defineStore } from 'pinia';`，保留 `window.useXStore = useXStore`；`store/index.js` 改 `import { createPinia } from 'pinia'; window.htdPinia = createPinia();` |
| utils / composables / registry / router / api / icons / theme-manager / observable | 纯逻辑，保留 `window.X = X`；仅用到 `Vue.*` 时才加 import |
| `app.js` | **不改**（继续用 `window.Vue`/`window.htdPinia`/`window.htdRegistry`/`HtpButton` 等全局，由 entry 重新附着） |

### entry（新增 `frontend/src/entry.js`）
```js
import Vue from 'vue';
import { createPinia } from 'pinia';
window.Vue = Vue; window.htdPinia = createPinia();
// 严格按 index.html 原顺序 import，触发各文件 window 自附着副作用
import './js/store/index.js';
import './js/store/appStore.js';
import './js/store/uiStore.js';
import './js/store/dataStore.js';
import './js/utils/date.js'; /* ... 其余 utils / composables / api / router / components / modules / theme-manager ... */
import './js/registry.js';
import './js/app.js';
```
### index.html
删全部业务 `<script src>`（保留 css + 三个 IIFE lib），改为单入口：
`<script type="module" src="/src/entry.js"></script>`

## 五、Vite 配置（新增 `frontend/vite.config.js`）
- `root: frontend`，`base: './'`（离线相对路径，exe 静态服务友好）
- `build.outDir: 'dist'`（位于 frontend/ 下），`rollupOptions.input: 'index.html'`
- `build.rollupOptions.external: ['vue','pinia']`，`output.globals: { vue:'Vue', pinia:'Pinia' }`
- 不开启 SFC，纯 JS 模块打包

## 六、后端 / 打包联动
- `app.js` 静态服务：`frontendDir` 优先 `frontend/dist`（Vite 产物），不存在则回退 `frontend/`（保留无构建模式作兜底，零回归）。
- pkg assets：`frontend/dist/**` 替换 `frontend/**`（dist 优先；或两者都含）。
- `backend/package.json` `build:win`：在 `build:entry` 前增 `vite build`（建议新增 `build:fe` 步骤并串入）。

## 八、回滚

## 九、风险与缓解
- Vue ESM 默认导出形状 → `import Vue from 'vue'`（含 createApp/ref/computed），与全局包一致。
- Pinia ESM 替代 IIFE → store 改用 `import { defineStore }`；已验证 store 仅用 defineStore。
- 导入顺序 → entry 严格按 index.html 顺序，保证 window 全局就绪。
- 离线 exe → vue/pinia 经 external 仍走本地 IIFE，运行时无网络。
- 端口红线 → 冒烟用隔离端口或临时放宽 findAvailablePort，不改动 D2 三线约束的发布形态。

## 十一、执行记录（2026-09-10）

### 重大方案修正（相对 §三 / §四）
原方案 §三 用 rollup `external` 标 `vue`/`pinia` 为外部、§四 要求给每个源文件加 `import`。执行前复核发现两个隐患，改为更简更安全的方式：

1. **external 会导致浏览器白屏**：`external: ['vue','pinia']` 会在产物里留下裸导入 `import Vue from 'vue'`，浏览器无法解析 → 白屏。已弃用。
2. **源文件根本不需要 import**：取证确认所有前端源文件使用的是 `window.Vue` / `window.Pinia` **全局**（如 `store/index.js`: `const pinia = Pinia.createPinia()`），且 `grep` 证实 `frontend/js` **零个 ESM import**。因此 §四 的 P1「逐文件加 import」是多余且有破坏风险的。

**实际采用方案（shim-free 副作用导入）**：
- 仅新增 `frontend/src/entry.js`，按 `index.html` 原顺序 `import` 各文件触发 `window.X = X` 自附着副作用；**零源文件改动**。
- `index.html` 删全部业务 `<script>`，保留 3 个 IIFE 库 + 单入口 `<script type="module" src="/src/entry.js">`。
- `vite.config.js`：`root` 用 `import.meta.url` 定位，`base:'./'`，`plugins` 内 `copyIifeLibs` 在 `closeBundle` 把 `assets/lib/*.js` 拷进 `dist/assets/lib`（Vite 不打包非 module 的经典 `<script>`，否则悬空引用致白屏）。`frontend/package.json` 设 `type:module` 让配置以 ESM 加载。
- 后端 `app.js` 静态服务**优先 `frontend/dist`，缺失则回退 `frontend/`**（原生 ESM 兜底，零回归）。
- `build:win` 串入 `build:fe`（`vite build`）。
