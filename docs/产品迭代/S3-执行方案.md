## 2. S3-0 · Node sidecar 启动契约（不依赖 Rust，已完成）

### 2.1 为什么需要先定契约

Tauri 以 sidecar 方式拉起 Node 后端时，壳与子进程之间必须就**端口、就绪时机、数据目录**达成一致。这部分纯 Node 侧，先落地即可与后续 Rust 侧解耦并行。

### 2.2 契约内容

**环境变量**

| 变量 | 作用 | 默认值 |
|---|---|---|
| `HTD_DESKTOP` | `1`/`true` 进入桌面模式 | 未设置 = 普通模式 |
| `HTD_PORT` | 监听端口 | 17388（**仅允许 17388/17389/17390**） |
| `HTD_DATA_ROOT` | 数据根目录（壳传 AppData 路径） | `D:\荒天帝工作台` 或 `settings.json` 的 `dataRoot` |

**桌面模式与普通模式的三处差异**

1. **不自动打开系统浏览器** —— 页面由壳内 webview 加载。
2. **跳过「同端口已有实例则复用并退出」分支** —— 唯一实例由壳的 single-instance 保证。若 sidecar 在此 `exit(0)`，壳会判定子进程异常终止，反而拿不到端口。
3. **就绪后输出机器可读行**：

```
HTD_READY {"port":17388,"host":"127.0.0.1","url":"http://127.0.0.1:17388","apiPrefix":"/api/v1","dataRoot":"..."}
```

壳以 `/^HTD_READY (.+)$/` 逐行匹配 stdout，解析出 `port` 后令 webview 加载 `url`。

### 2.3 顺带修掉的真实缺陷：端口顺延导致写入全被 403

`originGuard` 的白名单读的是 `appConfig.port`。当 17388 被占用、服务顺延到 17389 时，浏览器实际 Origin 是 `http://127.0.0.1:17389`，而白名单仍是 17388 —— **所有 POST/PUT/PATCH/DELETE 一律 403**，且现象极具迷惑性（页面能开、列表能查，一保存就失败）。

修复：`server.js` 在 `listen` 成功后回写 `appConfig.port = port`，白名单自动跟随实际端口。测试用双向断言锁死（未回写 → 403；回写后 → 非 403）。

### 2.4 端口必须为固定三端口的原因

`findAvailablePort` 只在 17388 / 17389 / 17390 中探测，三者全占用即拒绝启动（不向后续端口顺延）。**S3 不能改用 OS 随机端口**：随机端口会同时破坏 originGuard 白名单与 pkg 打包的一致性约定。壳侧因此必须接受「用三个固定端口之一，全占用则提示用户」的行为。

## 3. S3-1 · Tauri + Node sidecar 打包（消费 dist/）

### 3.1 环境要求（当前**不具备**）

- Rust 工具链：`rustup` + 稳定版 Rust（1.77+），首次安装约 1.5–2 GB 下载
- MSVC 生成工具（Windows）+ WebView2 Runtime（Win11 已内置）
- Node 24 LTS（已有）
- 首次 Tauri 编译（含依赖编译）通常 **30–60 分钟**

### 3.2 骨架结构（待建）

```
src-tauri/
  Cargo.toml
  tauri.conf.json        # productName / identifier / bundle.targets / externalBin
  build.rs
  icons/                 # 32x32, 128x128, 128x128@2x, icon.icns, icon.ico
  src/main.rs            # 拉起 sidecar、读 HTD_READY、加载 webview、退出时回收
  binaries/
    htd-backend-x86_64-pc-windows-msvc.exe   # 现有 pkg 产物，作为 externalBin
```

### 3.3 复用现有资产，不做重复建设

后端 `package.json` 已有 `build:win` / `build:mac`（`@yao-pkg/pkg` → 单文件 exe），且 `pkg.assets` 已含 `../frontend/dist/**/*`。**sidecar 直接复用该 exe**，不重新发明打包链路。

### 3.4 main.rs 关键流程

1. 读取 `HTD_PORT` 候选（17388 → 17389 → 17390），传入 sidecar 环境变量，同时设 `HTD_DESKTOP=1`、`HTD_DATA_ROOT=<app_data_dir>`
2. `Command::sidecar("htd-backend")` 拉起，监听 stdout
3. 匹配 `HTD_READY` → 解析端口 → `WebviewWindow` 加载该 URL
4. 窗口关闭 / 应用退出 → `child.kill()`，确保不留孤儿 Node 进程（SQLite 单写锁）
5. single-instance 插件保证唯一实例；二次启动时聚焦已有窗口

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| Rust 工具链安装体积/耗时 | 单独维护窗口执行；未安装前保持 S3-1 不开工 |
| sidecar 孤儿进程导致 SQLite 锁 | main.rs 退出钩子 kill；再加退出前 `POST /system/shutdown`（如需要） |
| 固定三端口全被占用 | 壳侧提示用户释放；不改为随机端口（见 §2.4） |
| WebView2 缺失（Win10） | 安装包引导下载或内置引导安装 |
| 自动更新违背离线优先 | 默认仅提示不自动下载（§4） |
