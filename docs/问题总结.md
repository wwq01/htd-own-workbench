# 荒天帝工作台问题总结

> 更新时间：2026-08-10
> 适用范围：阶段 0-7 Windows 版本

## 已解决问题

| 问题 | 处理结果 |
|---|---|
| 东八区日期使用 `toISOString()` 造成日期偏移 | 统一使用本地日期格式化工具 |
| Prisma 中文路径或 `.env` 编码导致数据库路径异常 | 运行时显式设置 `datasourceUrl` |
| 设置页主题选择后页面未立即切换 | 主题选择增加即时预览，保存后持久化 |
| Windows 打包时目标 Node 运行时下载失败 | 使用 pkg 官方 Node 22 Windows 运行时缓存并校验 SHA-256 |
| ESM 直接打包导致启动失败 | 构建时生成 CommonJS 入口并使用 source fallback |
| 打包后前端资源缺失 | 将前端资源作为 pkg asset 内嵌 |
| 全新数据目录启动后没有数据表 | 构建数据库模板，首次启动自动复制初始化 |
| 测试环境缺少真实 HTTP 验证 | 增加真实 Express 临时端口 HTTP 集成测试 |

## 当前验证结果

- 20 个测试文件，184/184 通过。
- Windows 可执行文件可脱离 Node.js 启动。
- 首页、健康检查、统计、Todo CRUD 和重启持久化已验证。
- 浏览器视觉验收已完成，控制台错误为 0。

## 已知范围限制

- 本版本不构建 macOS 产物。
- Windows 安装包/便携版尚未制作，当前交付形态为单个 `.exe`。
- 修改数据路径后需要重启服务生效。

## 后续排查原则

1. 先查看数据目录下的 `logs\workbench.log` 和 `logs\error.log`。
2. 确认 Node.js 版本为 24 LTS，开发启动使用 `npm run dev`。
3. 数据异常前先从“数据与部署 → 本 APP 数据管理”导出 JSON 或创建 SQLite 备份。
