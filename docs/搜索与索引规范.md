# 搜索与索引规范（V1.5）

> **适用范围**：V1.5 落地的跨模块全文搜索（`GET /api/v1/search`）与命令面板（Cmd+K）搜索分支。
> **定位**：本文件描述搜索的「索引策略 → 查询契约 → 前端消费」全链路，是新增可搜索模块时必须同步修改的规范文件。
> **唯一事实来源**：`backend/src/modules/search/search.service.js` 的 `MODULE_CONFIGS` 注册表。本文件的模块清单与之不一致时，以代码为准并回头修订本文件。
>
> 相关文档：`docs/可视化与图表规范.md`（V1.5 同期交付）、`docs/阅读模块设计.md`（搜索覆盖的模块之一）、`docs/状态机与字段规范.md`（状态机约定）、`docs/模块挂载点规范.md`（前端路由注册）。

---

## 1. 定位与范围

### 1.1 解决的问题

工作台到 V1.5 已有 20 余个业务模块，跨模块定位一条记录只能逐个页面点进去翻。V1.5 提供统一的搜索入口：一次输入，遍历已注册模块的文本字段，按模块分组返回命中结果，并可直接跳转到该模块页面。

### 1.2 明确不属于本版范围

| 能力 | 本版是否支持 | 说明 |
| --- | --- | --- |
| 分词（中文/英文） | 否 | 见 §6 已知限制 |
| 相关性打分排序 | 否 | 组内按 `updatedAt desc` |
| 命中关键词高亮 | 否 | 只返回原文截取的 `snippet` |
| 跨模块统一分页 | 否 | 每模块各自 `take: limit` |
| 结果总数精确统计 | 否 | `total` 为已返回条目数之和，见 §3.3 |
| 字段级过滤（如只搜标题） | 否 | 每个模块的搜索字段在 `MODULE_CONFIGS` 中固定 |
| FTS5 虚表 / 倒排索引 | 否 | 见 §6.2 演进路径 |

## 2. 索引策略（重要：当前是 contains，不是 FTS5）

**当前实现没有使用 SQLite FTS5。** 搜索直接走 Prisma 对业务表的 `contains` 过滤，即 SQL 层的 `LIKE '%关键词%'` 子串匹配，没有任何倒排索引、虚表或分词器。

`backend/src/modules/search/search.service.js` 文件头注释原文：

```js
/**
 * 全文搜索模块 - Service 服务层（V1.5）
 * 跨模块模糊搜索：遍历已注册模块的文本字段，按模块分组返回结果。
 * 索引策略：SQLite 本地查询（contains），离线可用、零外部依赖；
 * 大数据量（>1w）场景可后续替换为 FTS5 虚表（见 docs/搜索与索引规范.md）。
 */
```

### 2.1 为什么选 contains

- 本地优先单机应用，数据库随 exe 分发，无外部搜索引擎依赖，离线可用。
- 个人数据量级（千级条目）下，全表 LIKE 的延迟不可感知，引入 FTS5 的同步维护成本（触发器、虚表重建、迁移脚本）收益不成比例。
- 与既有的软删除（`deletedAt = null`）语义天然兼容，无需为虚表单独维护过滤条件。

### 2.2 查询构造

每个模块的查询条件固定为三段：

```js
const where = {
  deletedAt: null,
  OR: cfg.fields.map((f) => ({ [f]: { contains: keyword } })),
};
const rows = await model.findMany({
  where,
  take: limit,
  orderBy: { updatedAt: 'desc' },
  select: { id: true, [cfg.titleField]: true, [cfg.snippetField]: true },
});
```

要点：

- `deletedAt: null` 硬编码，回收站内的软删除记录永不出现在搜索结果中。
- `OR` 数组由 `cfg.fields` 映射而来，注册几个字段就产生几个 LIKE 分支，模块内为「或」关系。
- `select` 只取 `id` + 标题字段 + 摘要字段三列，避免把 `notes` / `content` 这类大文本整列拉回内存。
- `orderBy: { updatedAt: 'desc' }` 是唯一的排序维度。
- `take: limit` 是每模块的截断量，不是全局总量。

## 3. 接口契约

### 3.1 端点

| 项 | 值 |
| --- | --- |
| 方法 | `GET` |
| 路径 | `/api/v1/search` |
| 挂载位置 | `backend/src/app.js:107`，`app.use(\`${appConfig.apiPrefix}/search\`, searchRouter)` |
| 路由定义 | `backend/src/modules/search/search.router.js`，仅一条 `router.get('/', searchController.search)` |
| 鉴权 | 无（本地单机应用，全站同一信任域） |

### 3.2 请求参数（`search.schema.js`）

| 参数 | 类型 | 必填 | 默认 | 校验规则 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `q` | string | 是 | — | `z.string().min(1, '搜索关键词不能为空')` | 搜索关键词。空白串会被 service 层 `q.trim()` 后判空并直接返回空结果 |
| `modules` | string | 否 | 无 | `z.string().optional()` | 逗号分隔的模块 key（如 `reading,project`）。留空搜全部 |
| `limit` | number | 否 | `5` | `z.coerce.number().int().positive().max(50).optional().default(5)` | 单模块返回条数上限，最大 50。经 `z.coerce.number()` 从 query string 转换 |

### 3.3 响应结构

成功响应由 `res.success()` 包裹，payload 为：

```json
{
  "groups": [
    {
      "module": "reading",
      "label": "阅读",
      "items": [
        {
          "id": "cmxxxx",
          "title": "零信任架构实践",
          "snippet": "本文讨论了零信任的三大落地难点…",
          "route": "/reading"
        }
      ]
    }
  ],
  "total": 1
}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `groups` | `Array<Group>` | 按模块分组的结果。空关键词时为空数组 |
| `groups[].module` | string | 模块 key，与请求参数 `modules` 的取值一致 |
| `groups[].label` | string | 模块中文名，供命令面板渲染分组标题 |
| `groups[].items` | `Array<Item>` | 该模块命中条目，最多 `limit` 条 |
| `groups[].items[].id` | string | 记录主键（cuid） |
| `groups[].items[].title` | string | 展示标题，由 `buildTitle()` 生成 |
| `groups[].items[].snippet` | string | 摘要，由 `buildSnippet()` 生成，最长 80 字符 |
| `groups[].items[].route` | string | 前端路由（如 `/reading`），供命令面板跳转 |
| `total` | number | **已返回条目数之和**，非真实命中总数 |

关键说明：`total` 的累加逻辑是 `total += items.length`（`search.service.js:83`），而 `items` 已被 `take: limit` 截断。因此当某模块有 200 条命中时，该模块只贡献 `limit` 条，`total` 也只加 `limit`。**`total` 应理解为「本次返回的条目总数」，不能用于「共找到 N 条」的文案。** 命令面板目前也确实没有展示 `total`。

### 3.4 空结果语义

| 场景 | 响应 |
| --- | --- |
| `q` 缺省或 `q.trim()` 为空 | `{ groups: [], total: 0 }` |
| `modules` 过滤掉全部模块 | `{ groups: [], total: 0 }` |
| 关键词无命中 | `{ groups: [], total: 0 }`（空组不会被 push，见 `if (rows.length)` 判断） |

三者返回体相同，调用方无法区分，也不需要区分。

## 4. 模块注册表（`MODULE_CONFIGS`）

### 4.1 配置结构

```js
{
  module: 'reading',            // 模块 key，用于 modules 过滤
  label: '阅读',                 // 中文名
  model: 'readingMaterial',     // Prisma client 上的模型键（首字母小写驼峰）
  fields: ['title', 'notes', 'sourceUrl'],  // 参与 LIKE 匹配的文本字段
  titleField: 'title',          // 结果标题取自该字段
  snippetField: 'notes',        // 结果摘要取自该字段
  route: '/reading',            // 前端跳转路由
  titlePrefix: '复盘',           // 可选，标题前缀
}
```

### 4.3 注册表的实现约束

1. **`model` 键必须存在于 Prisma client**，否则 `const model = prisma[cfg.model]; if (!model) continue;` 会静默跳过该模块——不报错，但该模块永远搜不到。新增模块后如搜索无结果，优先检查此处拼写。
2. **`fields` 中的字段必须存在于对应 Prisma model**，否则 Prisma 会抛运行时校验错误（而非静默跳过）。
3. **`titleField` 与 `snippetField` 允许相同**（`habit` / `time-block` / `bid` / `deployment` / `meeting` 即是）。此时 `select` 对象里两个计算属性名相同，后者覆盖前者，取到的是同一个值；`buildTitle` 与 `buildSnippet` 会分别处理，标题与摘要内容一致。
4. **`review` 是唯一使用 `titlePrefix` 的模块**。因为复盘记录没有独立标题字段，标题由 `type` 字段拼前缀生成：`复盘 · 周`（`buildTitle` 实现为 `` `${cfg.titlePrefix} · ${base || ''}`.trim() ``）。
5. **模块顺序即结果顺序**。`groups` 按 `MODULE_CONFIGS` 的声明顺序 push，未做任何排序。调整数组顺序即可调整命令面板中分组的展示次序。

### 4.4 新增一个可搜索模块的操作步骤

1. 确认该模块的 Prisma model 已存在且有 `deletedAt` 字段（搜索硬编码过滤 `deletedAt: null`，无该字段的 model 会导致 Prisma 报错）。
2. 在 `MODULE_CONFIGS` 末尾追加一条配置（追加而非插入，避免打乱既有分组展示顺序）。
3. 确认 `route` 已在 `frontend/js/router.js` 中注册，否则命令面板「查看全部」会跳转到空页面。
4. 无需改动 `search.router.js` / `search.controller.js` / `search.schema.js`——它们是模块无关的。
5. 无需改动前端——命令面板直接消费 `/search` 返回的 `groups[].label` 与 `route`。
6. 补一条 `search.test.js` 用例，验证该模块能被搜到。

## 5. 关键实现说明

### 5.1 标题与摘要生成

```js
function buildTitle(cfg, record) {
  const base = record[cfg.titleField];
  if (cfg.titlePrefix) return `${cfg.titlePrefix} · ${base || ''}`.trim();
  return base || '未命名';
}

function buildSnippet(cfg, record, max = 80) {
  const raw = record[cfg.snippetField];
  if (!raw) return '';
  return String(raw).length > max ? String(raw).slice(0, max) + '…' : String(raw);
}
```

- 标题为空时回落 `'未命名'`，摘要为空时回落空串（不显示摘要行）。
- 摘要是**从头截取**，不是围绕命中关键词截取——因为当前实现无法定位关键词在原文中的位置。超长时以 `…` 结尾。
- 摘要不做 HTML 转义，也不剥离 Markdown 标记。命令面板通过 Vue 的 `{{ }}` 插值渲染，天然转义，不存在 XSS；但若将来改为 `v-html` 渲染摘要，必须先转义。

### 5.2 模块过滤

```js
const moduleFilter = modules
  ? modules.split(',').map((s) => s.trim()).filter(Boolean)
  : null;
// ...
if (moduleFilter && !moduleFilter.includes(cfg.module)) continue;
```

`modules` 是逗号分隔字符串而非数组——因为 Express 的 `req.query` 对重复键会解析成数组，用字符串可避免歧义。传 `modules=reading,project` 可只搜两个模块；传 `modules=`（空串）经 `.filter(Boolean)` 后变成空数组，会过滤掉**所有**模块，等价于搜不到任何东西——这是当前实现的一个边界行为，调用方不应传空值。

### 5.3 未接入 `?fields=` 字段裁剪

V1.5 的 `?fields=` 列表字段裁剪能力（详见 `docs/阅读模块设计.md` §7）**未接入搜索接口**。`search.schema.js` 中没有 `fields` 字段，搜索结果的 item 结构固定为 `{ id, title, snippet, route }` 四项。原因是搜索结果项本身已是最小集，再裁剪没有收益。

## 6. 前端交互：`HtpCommandPalette` 搜索分支

落地文件：`frontend/js/components/HtpCommandPalette.js`（V1.5 §8.2 段落，自 `// ===== 跨模块搜索分支（V1.5 §8.2） =====` 起）。

### 6.1 与命令分支的关系

命令面板同时存在两类结果，在同一个列表里上下拼接渲染：

| 类别 | 数据来源 | 结构 | 数量 |
| --- | --- | --- | --- |
| 命令（`results`） | 前端硬编码 `COMMANDS` 数组（19 条），离线拼音匹配 | 导航 / 新建 / 主题 / 外观 / 备份 | 全量过滤后展示 |
| 搜索（`searchGroups`） | 后端 `GET /api/v1/search` | 按模块分组的业务记录 | **每组 5 条** |

索引编排上，命令在前、搜索在后，统一编入一个连续的下标空间：

```js
const searchGroups = Vue.computed(() => {
  if (!searchRaw.value || !searchRaw.value.groups) return [];
  let idx = results.value.length;          // 从命令结果数量之后开始编号
  return searchRaw.value.groups.map((g) => ({
    module: g.module,
    label: g.label,
    route: g.route,
    items: g.items.slice(0, 5).map((it) => ({ ...it, idx: idx++ })),
  }));
});
```

`totalItems = results.length + 各搜索组条目数之和`，用于 ↑↓ 键的下标边界判断。

### 6.2 状态与请求时序

| 状态 | 类型 | 作用 |
| --- | --- | --- |
| `searchRaw` | `ref(null)` | 后端原始响应 |
| `searchTotal` | `ref(0)` | 后端返回的 `total`（当前模板未展示） |
| `searchLoading` | `ref(false)` | 控制「搜索中…」提示条 |
| `searchGroups` | `computed` | 分组后的渲染数据 |

请求由 `Vue.watch(query, ...)` 驱动，**250ms 防抖**：

```js
Vue.watch(query, (q) => {
  if (searchTimer) clearTimeout(searchTimer);
  const t = (q || '').trim();
  if (!t) { searchRaw.value = null; searchTotal.value = 0; searchLoading.value = false; return; }
  searchLoading.value = true;
  searchTimer = setTimeout(async () => {
    try {
      const r = await window.htdApi.get('/search', { q: t });
      searchRaw.value = r && r.groups ? r : { groups: [], total: 0 };
      searchTotal.value = (r && r.total) || 0;
    } catch (e) {
      searchRaw.value = { groups: [], total: 0 };
    } finally {
      searchLoading.value = false;
    }
  }, 250);
});
```

要点：

- 只传 `q`，**不传 `limit`**，因此走后端默认的 `limit = 5`。前端再 `slice(0, 5)` 是一次冗余但无害的兜底。
- 请求失败时静默降级为空结果（不弹 toast），命令分支仍可正常使用。
- 关键词清空时立即复位状态并取消未触发的定时器。
- 每次 `open()` 都会重置 `searchRaw` / `searchTotal` / `searchLoading`，避免上次结果残留。

### 6.3 列表渲染结构

模板中的三类 `<li>`：

1. **组头**（`cmd-palette__group-head`）：搜索图标 + 模块 `label` + 「查看全部」链接。点击「查看全部」执行 `navigate(g.route)`，跳转到该模块列表页并关闭面板。注意这里跳转的是模块页，**不携带当前关键词**——目标页面的筛选框不会自动填入搜索词。
2. **结果项**（`cmd-palette__item--search`）：标题（`it.title`）+ 可选摘要（`it.snippet`）+ 右侧「搜索」类型标签。点击执行 `runSearch(it)` → `navigate(it.route)`。
3. **空态**（`cmd-palette__empty`）：`searchLoading` 为 true 时显示「搜索中…」；命令与搜索都无结果且非 loading 时显示「无匹配命令」。

### 6.4 键盘交互

| 按键 | 行为 |
| --- | --- |
| `↑` / `↓` | 在 `activeIndex` 上移动，边界为 `0` 与 `totalItems - 1`，跨越命令区与搜索区 |
| `Enter` | `activate()`：`activeIndex < results.length` 时执行命令，否则在搜索扁平数组中找 `idx === activeIndex` 的条目并跳转 |
| `Esc` | 关闭面板 |
| `Ctrl/Cmd + 1~9` | **仅在 `query` 为空时**生效，直接执行前 9 条命令；有关键词时不触发，避免与搜索输入冲突 |
| 鼠标 hover | `@mouseenter="activeIndex = it.idx"` 同步高亮 |

`Vue.watch(results, () => { activeIndex.value = 0; })` 会在命令结果变化时复位选中项；搜索结果的异步到达不触发该复位（`searchGroups` 未被 watch），因此在搜索回填的瞬间选中项可能仍停留在旧的命令条目上——这是一个已知的轻微交互瑕疵，尚未修复。

### 6.5 跳转实现

```js
function navigate(route) {
  if (route && window.htdRouter) window.htdRouter.navigate(route);
  close();
}
```

搜索结果项携带的 `route` 是模块级路由（如 `/reading`），**不带记录 id**。当前前端路由不支持「跳转到某条记录详情并高亮」的深链，因此搜索只能定位到模块页，用户需自行在列表中找目标条目。这是本版搜索最大的体验缺口，见 §7.3。

| 空关键词返回空结果 | `search({ q: '' })` 返回 `{ groups: [], total: 0 }` |
| 跨模块搜索命中多个模块并按组返回 | 同时新建 reading 与 project 记录，搜「零信任」，两组均出现在 `groups` 中，`total >= 2` |
| `modules` 过滤仅搜索指定模块 | 传 `modules: 'reading'` 时 `groups.length === 1` 且 `module === 'reading'` |
| 结果项含 `id/title/snippet/route` | item 四字段存在，标题包含关键词，`route === '/reading'`，`snippet` 为 string |

测试约定：

- 使用 `process.env.HTD_TEST_DB_URL` 指向的独立测试库，与开发库隔离。
- 数据前缀约定 `SRCH_`，`beforeEach` / `afterEach` 双向清理（`readingMaterial` 按 title、`project` 按 customerName 做 `contains` 删除）。
- **直接测 service 层，未测 HTTP 端点**。因此 `search.schema.js` 的参数校验（`limit` 上限 50、`q` 非空）没有自动化覆盖。

## 8. 已知限制与后续演进

### 8.1 已知限制

| 编号 | 限制 | 影响面 | 触发条件 |
| --- | --- | --- | --- |
| L1 | **无分词**：`contains` 是整串子串匹配 | 搜「零信任架构」无法命中只含「零信任」的记录；反之「零信任」可命中「零信任架构」 | 关键词比原文长或粒度不一致 |
| L2 | **无中文分词器** | 中文只能整串子串匹配，无法做「信任」→「零信任」的语义扩展 | 所有中文搜索 |
| L3 | **大小写行为未验证** | Prisma `contains` 在 SQLite provider 下翻译为 `LIKE '%kw%'`，SQLite 的 `LIKE` 对 ASCII 默认不区分大小写，但对非 ASCII 取决于 ICU 编译选项。本仓库**未编写针对大小写与中英文混排的测试**，实际行为标记为**待确认** | 混合大小写关键词 |
| L4 | **全表扫描**：无索引可用 | `LIKE '%kw%'` 前置通配符导致 B-tree 索引失效，每模块每次搜索一次全表扫描 | 单表数据量增长后 |
| L5 | **`total` 非真实命中数** | 见 §3.3 | 命中数超过 `limit` |
| L6 | **无高亮** | 摘要为原文前 80 字符，关键词可能不在可见区域内 | 长文本字段 |
| L7 | **无深链** | 只能跳转到模块页，不能定位到具体记录 | 每次使用 |
| L8 | **串行 15 次查询** | `for...of` 中 `await model.findMany()` 逐个模块串行执行，未做 `Promise.all` 并发 | 关键词较短、命中模块多时 |
| L9 | **搜索字段写死** | 无法按字段过滤（如「只搜标题」），也无法搜索 `tags` / `customFields` 这类 JSON 列的结构化内容 | 需要精确检索时 |
| L10 | **组头「查看全部」不带关键词** | 跳转到模块页后筛选条件为空 | 点击「查看全部」 |

### 8.2 性能特征

按当前实现，一次搜索的数据库操作次数 = `MODULE_CONFIGS` 中通过 `modules` 过滤后的模块数（默认 15）。每次都是单表 `findMany` + `LIKE`。在个人数据量级（单表千级）下实测延迟可忽略；单表突破万级后，`L4` 的全表扫描会成为瓶颈，此时应启动 FTS5 改造。

串行执行（`L8`）虽是优化点，但 15 次串行查询在本地 SQLite 上的总延迟仍在毫秒级，改造优先级低于 FTS5。

### 8.3 后续演进路径

**第一步（低成本）：并发化 + 精确计数**

- 把 `for...of` 串行改为 `Promise.all` 并发，缩短墙钟时间。
- 增加 `count` 查询（`model.count({ where })`）返回真实命中数，与 `total` 分离为 `total`（真实）与 `returned`（已返回）两个字段。

**第二步（中成本）：FTS5 虚表**

- 对文本量大的模块（`vault.content`、`reading.notes`、`review.*`）建 FTS5 虚表，通过触发器与业务表同步。
- 中文分词可选 `unicode61` + 自建 bigram 分词，或引入 `simple` 分词器配合前端预处理。
- 保留 `contains` 作为兜底：FTS5 查询失败或虚表未建时降级到现有路径，保证升级不破坏既有行为。
- 迁移脚本需处理「虚表重建」：备份恢复流程（`docs/备份与恢复手册.md`）要确保虚表随业务库一并重建，不能只拷贝主表。

**第三步（体验）：深链与高亮**

- 结果项 `route` 扩展为 `/reading?id=cmxxxx`，各页面 `onMounted` 时读取 query 参数并高亮/滚动到目标行。这需要各页面统一实现深链消费，涉及面较广，建议与 `docs/模块挂载点规范.md` 的四触点规范一并规划。

**在以上任一步骤落地前，本文件的 §2 标题都应保持「当前是 contains，不是 FTS5」的表述，不得提前改写。**
