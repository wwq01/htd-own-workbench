# 可视化与图表规范（V1.5）

> **适用范围**：V1.5 落地的数据可视化能力——后端图表聚合接口（`GET /api/v1/system/charts`、`GET /api/v1/system/project-charts`）、手写 SVG 图表工具 `window.htdCharts`，以及首页 / 学习 / 财务 / 项目详情四个挂载页面。
> **定位**：本文件是新增图表时必须同步修改的规范。凡新增数据集，必须先定契约（改后端聚合 + 本文件字段表），再改前端渲染。
> **唯一事实来源**：`backend/src/modules/system/system.service.js` 的 `getCharts()` / `getProjectCharts()` 与 `frontend/js/utils/charts.js`。
>
> 相关文档：`docs/搜索与索引规范.md`（V1.5 同期交付）、`docs/阅读模块设计.md`、`docs/多主题切换规范.md`（配色令牌）、`docs/模块挂载点规范.md`（页面挂载）。

---

## 1. 定位与范围

### 1.1 技术选型：手写 SVG，无第三方图表库

前端**没有引入任何图表库**（无 ECharts / Chart.js / D3）。全部图表由 `frontend/js/utils/charts.js` 手写 SVG 字符串生成，通过 Vue 的 `v-html` 指令注入 DOM。

选型理由：

- 无构建全局版 Vue 3（`Vue` 走 CDN 全局对象），引入以 ESM 为主的现代图表库需要改造加载方式，成本高。
- pkg 打包为 Windows 单 exe，需要把前端资源一并塞进二进制，减少依赖体积直接降低打包复杂度。
- 图表需求固定在五类（柱 / 环 / 折 / 堆叠柱 / 时间线），自绘的可控性优于配置式库的裁剪成本。
- SVG 走 CSS 变量（`var(--text-tertiary)` 等）取色，天然跟随 `docs/多主题切换规范.md` 的多外观切换，无需在 JS 里监听主题变更重绘。

### 1.2 交付范围

| 层级 | 交付物 |
| --- | --- |
| 后端聚合 | `system.service.js#getCharts()`（首页 + 学习 + 财务三类 11 个数据集）、`getProjectCharts(projectId)`（里程碑时间线 + 任务速率） |
| 后端接口 | `GET /api/v1/system/charts`、`GET /api/v1/system/project-charts` |
| 前端工具 | `frontend/js/utils/charts.js` 暴露 `window.htdCharts`，6 个公开 API |
| 前端样式 | `frontend/css/pages.css` 的 `.htd-chart*` 系列类 |
| 挂载页面 | `HomePage.js`（4 图）、`StudyPage.js`（2 图 + 周期切换）、`FinancePage.js`（4 图）、`ProjectPage.js`（2 图） |

### 1.3 明确不属于本版范围

| 能力 | 说明 |
| --- | --- |
| 图表交互（hover tooltip / 点击下钻 / 缩放） | 全部图表为静态 SVG |
| 坐标轴刻度与网格线 | 仅有一条基线和 X 轴文字标签，无 Y 轴刻度 |
| 图表导出（PNG / SVG 下载） | 未实现 |
| 数据刷新（轮询 / 实时） | 仅在页面 `onMounted` 或项目切换时拉取一次 |
| 图表级错误处理 | 拉取失败时 `console.error` 后 `charts` 保持 `null`，模板 `v-if` 整块不渲染 |
| 大数据量渲染优化 | 无虚拟滚动、无降采样 |

## 2. 后端接口契约

### 2.1 端点总览

| 方法 | 路径 | 挂载位置 | Controller | 说明 |
| --- | --- | --- | --- | --- |
| `GET` | `/api/v1/system/charts` | `system.router.js:45` | `systemController.getCharts` | 首页 / 学习 / 财务三类全量聚合，无参数 |
| `GET` | `/api/v1/system/project-charts` | `system.router.js:46` | `systemController.getProjectCharts` | 单项目图表，必填 `projectId` |

两个接口的 controller 实现均为一行转发，无额外参数处理：

```js
async getCharts(req, res, next) {
  try { res.success(await systemService.getCharts()); } catch (err) { next(err); }
}

async getProjectCharts(req, res, next) {
  try { res.success(await systemService.getProjectCharts(req.query.projectId)); } catch (err) { next(err); }
}
```

`getProjectCharts` 的 `projectId` 来自 `req.query`，**未经过 Zod schema 校验**，非空判断下沉到 service 层。

### 2.2 聚合策略

`getCharts()` 的性能策略（原文注释）：

> 个人数据量级小，直接拉取相关列后在 JS 端分桶聚合，避免 N+1 与复杂 SQL。

即：**不写 GROUP BY 聚合 SQL，而是用 `select` 只取需要的列，把行拉到 JS 内存里分桶累加**。唯二例外是项目阶段分布用了 `prisma.project.groupBy()`，合同回款用了 `orderBy + take: 6`。

| 数据域 | 查询方式 | 取用列 |
| --- | --- | --- |
| 待办完成趋势 | `todo.findMany` + JS 分桶 | `createdAt`, `completedAt` |
| 项目阶段分布 | `project.groupBy({ by: ['phase'] })` | — |
| 学习习惯两组 | `studyRecord.findMany` + JS 分桶 | `studyDate`, `duration`, `techDirection` |
| 习惯完成率 | `habit.findMany` + `habitCheckIn.findMany` | habit: `id,name,frequency,dailyTargetCount,weeklyTargetDays`；checkIn: `habitId,count` |
| 财务三项 | `financeRecord.findMany` + `contractReceivable.findMany` | finance: `date,type,amount,category`；contract: `contractNo,contractAmount,totalReceived` |

`studyRecord` 全表只查一次，被首页的 `studyHours` 与学习页的 `_buildStudyCharts(studyRecs, ...)` 复用，避免重复打库。

### 2.3 时间窗口常量

| 数据集 | 窗口 | 生成函数 |
| --- | --- | --- |
| `home.weekCompletionTrend` | 最近 7 天 | `lastNDates(7)` |
| `home.studyHours` | 最近 7 天 | `lastNDates(7)` |
| `home.habitCompletionRate` | 最近 7 天 | `lastNDates(7)`（checkIn 查询用 `date: { in: last7 }`） |
| `study.daily` | 最近 14 天 | `lastNDates(14)` |
| `study.weekly` | 最近 8 周 | `lastNWeeks(8)` |
| `study.monthly` | 最近 6 个月 | `lastNMonths(6)` |
| `study.directionStacked.data` | 最近 6 个月 | `lastNMonths(6)` |
| `finance.monthlyIncomeExpense` | 最近 6 个月 | `lastNMonths(6)` |

`lastNDates(n)` 返回 `['2026-08-28', ..., '2026-09-03']` 形式的 `YYYY-MM-DD` 字符串数组（经 `formatDate()`）；`lastNMonths(n)` 返回 `['2026-04', ..., '2026-09']`；`lastNWeeks(n)` 返回 `getWeekKey()` 生成的周键。窗口长度是**固定补零**的——即使某天没有数据，也会产出 `value: 0` 的桶，保证图表 X 轴长度恒定。测试正是用这一点做断言（`expect(charts.study.daily.length).toBe(14)`）。

## 3. 数据契约：`GET /api/v1/system/charts`

顶层结构固定三个键：

```json
{ "home": { ... }, "study": { ... }, "finance": { ... } }
```

### 3.1 `home`（首页 4 图）

#### 3.1.1 `home.weekCompletionTrend` — 本周完成趋势

类型：`Array<Object>`，长度恒为 **7**。

| 字段 | 类型 | 含义 | 取值说明 |
| --- | --- | --- | --- |
| `label` | string | X 轴标签 | `weekdayShort(date)` 生成，形如 `周一`、`周二` |
| `date` | string | 分桶日期 | `YYYY-MM-DD` |
| `completed` | number（整数） | 该日**完成**的待办数 | `completedAt` 格式化后等于该日期的记录数 |
| `created` | number（整数） | 该日**创建**的待办数 | `createdAt` 格式化后等于该日期的记录数 |

> 注意：前端 `HomePage` 只消费 `completed` 画柱状图，`created` 目前**未被任何图表使用**，属于已产出但未消费的冗余字段。

#### 3.1.2 `home.projectPhaseDistribution` — 项目阶段分布

类型：`Array<Object>`，长度取决于数据库中出现过的 `phase` 取值数量（**不固定**）。

| 字段 | 类型 | 含义 | 取值说明 |
| --- | --- | --- | --- |
| `label` | string | 阶段名 | 直接取 `phase` 字段原值（中文，如 `方案撰写`） |
| `value` | number（整数） | 该阶段项目数 | `groupBy` 的 `_count._all` |
| `color` | string | 该阶段配色 | 优先取 `PROJECT_PHASE_COLORS[phase]`，未命中则按索引取 `CHART_PALETTE[i % 10]` |

`PROJECT_PHASE_COLORS`（`backend/src/common/constants/enums.js`）为固定映射：`需求沟通 #64748B` / `方案撰写 #3B82F6` / `POC演示 #8B5CF6` / `投标答辩 #F97316` / `交付跟进 #06B6D4` / `项目结项 #10B981`。

#### 3.1.3 `home.studyHours` — 最近 7 天学习时长

类型：`Array<Object>`，长度恒为 **7**。

| 字段 | 类型 | 含义 | 取值说明 |
| --- | --- | --- | --- |
| `label` | string | X 轴标签 | `weekdayShort(date)`，形如 `周一` |
| `date` | string | 分桶日期 | `YYYY-MM-DD` |
| `value` | number（1 位小数） | 该日学习时长合计（小时） | `studyRecord.studyDate === date` 的 `duration` 求和，经 `round1()` |

> 匹配方式是**字符串相等**（`r.studyDate === d`），而 `studyDate` 是字符串列。若库中存在非 `YYYY-MM-DD` 格式的脏数据，该条会被静默丢弃。

#### 3.1.4 `home.habitCompletionRate` — 习惯完成率

类型：`Array<Object>`，长度 = 习惯数量（`habit` 表去重后），**不固定**；`name` 为空的记录会被 `.filter((h) => h.label)` 剔除。

| 字段 | 类型 | 含义 | 取值说明 |
| --- | --- | --- | --- |
| `label` | string | 习惯名称 | `habit.name` |
| `value` | number（整数，0~100） | 完成率百分比 | `min(100, round(actual / expected * 100))` |

`expected`（期望值）的口径：

| `frequency` | 期望值计算 |
| --- | --- |
| `WEEKLY` | `weeklyTargetDays \|\| 7` |
| 其他（含 `DAILY`） | `(dailyTargetCount \|\| 1) * 7` |

`actual` 是最近 7 天内该习惯的 `habitCheckIn.count` 求和。注意：**`checkins` 查询按 `date in last7` 过滤，但 `expected` 对 `DAILY` 固定按 7 天折算**，两者口径一致；`WEEKLY` 的 `expected` 与 7 天窗口也是对齐的。

### 3.2 `study`（学习页 2 图 + 周期切换）

由 `_buildStudyCharts(studyRecs, last14, last6Months)` 生成。

| 字段 | 类型 | 长度 | 元素结构 |
| --- | --- | --- | --- |
| `daily` | `Array<{label, date, value}>` | 恒 14 | `label` 为 `date.slice(5)`（形如 `08-28`），`date` 为 `YYYY-MM-DD`，`value` 为 1 位小数小时数 |
| `weekly` | `Array<{label, value}>` | 恒 8 | `label` 为周键（`getWeekKey()` 生成），`value` 为 1 位小数小时数 |
| `monthly` | `Array<{label, value}>` | 恒 6 | `label` 为 `YYYY-MM`，`value` 为 1 位小数小时数 |
| `directionStacked` | `{series, data}` | — | 见下 |

> `daily` 与 `home.studyHours` 的数据来源相同、窗口不同（14 vs 7）、`label` 格式不同（`08-28` vs `周一`），是两套独立聚合，不是复用。

#### 3.2.1 `study.directionStacked` — 按技术方向堆叠

```json
{
  "series": [{ "key": "AI安全", "label": "AI安全", "color": "#5B8DEF" }],
  "data": [{ "label": "2026-04", "values": { "AI安全": 2.5 } }]
}
```

| 路径 | 类型 | 含义 |
| --- | --- | --- |
| `series` | `Array<{key: string, label: string, color: string}>` | 图例与堆叠层定义。`key` 是技术方向原值，空值归并为 `'未分类'` |
| `series[].key` | string | 取值键，`data[].values` 的键与之对应 |
| `series[].color` | string | 由 `CHART_PALETTE[i % 10]` 按方向出现顺序分配 |
| `data` | `Array<{label: string, values: Object}>` | 长度恒为 6（最近 6 个月） |
| `data[].label` | string | `YYYY-MM` |
| `data[].values` | `Object<string, number>` | 键为所有方向的 `key`，值为该月该方向时长（1 位小数）。**每个月的 `values` 都包含全部方向键**，缺失补 `0` |

`dirs` 的推导：`[...new Set(studyRecs.map((r) => r.techDirection || '未分类'))]`，是全表去重后集合，**不受 6 个月窗口限制**——一个只在 2020 年出现过的方向也会出现在 `series` 里（并在所有月份取值 0）。

### 3.3 `finance`（财务页 4 图）

由 `_buildFinanceCharts()` 生成。

#### 3.3.1 `finance.monthlyIncomeExpense`

类型：`Array<Object>`，长度恒为 **6**。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `label` | string | `YYYY-MM` |
| `income` | number（2 位小数） | 该月 `type === 'INCOME'` 的 `amount` 求和 |
| `expense` | number（2 位小数） | 该月**非** `INCOME` 的 `amount` 求和（`if (r.type === 'INCOME') ... else ...` —— 是二分判断，不是判断 `EXPENSE`） |

月份归属：`formatDate(r.date).slice(0, 7)`。**不在 `last6` 窗口内的月份会被丢弃**（`if (monthMap[mk])`），因此早于 6 个月前的财务数据不进图表。

#### 3.3.2 `finance.categoryPie`

类型：`Array<Object>`，长度不固定；`value > 0` 才保留（`.filter((x) => x.value > 0)`）。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `label` | string | 分类中文名。查 `FINANCE_CATEGORY_LABELS` 映射，未命中则原值输出 |
| `value` | number（2 位小数） | 该分类支出金额合计 |
| `color` | string | `CHART_PALETTE[i % 10]`，`i` 为 `Object.keys(catMap)` 的枚举顺序 |

`FINANCE_CATEGORY_LABELS`（定义于 `system.service.js`）：`FOOD 餐饮` / `HOUSING 居住` / `TRANSPORT 交通` / `SALARY 工资` / `REIMBURSEMENT 报销` / `OTHER 其他`。

只统计 `type === 'EXPENSE'` 的记录；`category` 为空时归为 `'OTHER'`。

#### 3.3.3 `finance.contractProgress`

类型：`Array<Object>`，长度 **最多 6**（`take: 6`）。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `label` | string | 合同编号 `contractNo` |
| `planned` | number（2 位小数） | 合同金额 `contractAmount` |
| `received` | number（2 位小数） | 已回款金额 `totalReceived` |

排序：`orderBy: { contractAmount: 'desc' }`，取金额最大的 6 份合同。

> 前端 `FinancePage` 的 `contractSvg` 只画了 `received`（已回款）一根柱子，`planned` 字段**未被消费**。若要展示「计划 vs 已回款」对比，需改用 `stackedBarChart` 或双色柱，属于待办项。

## 4. 数据契约：`GET /api/v1/system/project-charts?projectId=xxx`

### 4.1 参数与错误

| 项 | 说明 |
| --- | --- |
| `projectId` | **必填**，位于 query string |
| 缺失时 | 抛 `BusinessError(ErrorCodes.PARAM_ERROR, '缺少项目 ID')` |
| `projectId` 不存在 | 不报错，返回 `{ timeline: [], taskVelocity: { total: 0, done: 0, pending: 0, completionRate: 0 } }` |

### 4.2 响应结构

```json
{
  "timeline": [
    { "label": "立项", "date": "2026-09-01", "done": true, "color": "#34D399" }
  ],
  "taskVelocity": { "total": 2, "done": 1, "pending": 1, "completionRate": 50 }
}
```

#### 4.2.1 `timeline` — 里程碑时间线

类型：`Array<Object>`，长度 = 该项目未删除的里程碑数（**不固定，可为 0**）。

| 字段 | 类型 | 含义 | 取值说明 |
| --- | --- | --- | --- |
| `label` | string | 里程碑名称 | `projectMilestone.name` |
| `date` | string \| null | 截止日期 | `projectMilestone.dueDate` 原值（字符串列），可能为 null |
| `done` | boolean | 是否完成 | `!!m.completed` |
| `color` | string | 节点配色 | 完成为 `'#34D399'`，未完成为 `'#5B8DEF'`（硬编码，不走色板） |

排序：`orderBy: { dueDate: 'asc' }`。**`dueDate` 为 null 的里程碑排序位置由 SQLite 决定**，通常排在最前，属于未定义行为。

#### 4.2.2 `taskVelocity` — 任务速率

类型：`Object`，固定 4 个键。

| 字段 | 类型 | 含义 | 计算式 |
| --- | --- | --- | --- |
| `total` | number（整数） | 任务总数 | `tasks.length` |
| `done` | number（整数） | 已完成数 | `tasks.filter(t => t.completed).length` |
| `pending` | number（整数） | 未完成数 | `total - done` |
| `completionRate` | number（整数，0~100） | 完成率百分比 | `total ? round(done / total * 100) : 0` |

查询只 `select: { completed: true }`，不取任务名——因为当前只做计数聚合。

## 5. 前端图表工具：`window.htdCharts`

落地文件：`frontend/js/utils/charts.js`（在 `frontend/index.html:44` 以普通 `<script>` 引入，先于所有页面模块加载）。

### 5.1 公开 API

```js
window.htdCharts = {
  PALETTE, colorAt, barChart, donutChart, lineChart, stackedBarChart, timelineChart, legend,
};
```

| API | 返回类型 | 用途 |
| --- | --- | --- |
| `PALETTE` | `string[10]` | 固定色板常量 |
| `colorAt(i)` | string | 按索引取色，`PALETTE[i % 10]` |
| `barChart(opts)` | SVG 字符串 | 柱状图 |
| `donutChart(opts)` | SVG 字符串 | 环形图（支持单分类整圆） |
| `lineChart(opts)` | SVG 字符串 | 折线图（带面积填充） |
| `stackedBarChart(opts)` | SVG 字符串 | 堆叠柱状图 |
| `timelineChart(opts)` | SVG 字符串 | 横向时间线 |
| `legend(items)` | **HTML 字符串** | 图例（唯一返回 HTML 而非 SVG 的函数） |

### 5.2 色板

```js
const PALETTE = ['#5B8DEF', '#22D3EE', '#34D399', '#FBBF24', '#FB923C', '#F87171', '#94A3B8', '#60A5FA', '#2DD4BF', '#A3E635'];
```

后端 `system.service.js` 中的 `CHART_PALETTE` 与之**逐项相同**（源码注释：「V1.5 图表配色（与前端 charts.js PALETTE 对齐）」）。两处需手动保持一致——**这是当前架构的一个隐患，没有自动化校验**。`FinancePage` 直接硬编码了其中几个色值（`'#34D399'` / `'#F87171'` / `'#5B8DEF'`）作为 `color` 参数传入，属于第三处重复。

### 5.3 通用参数（各图表 `opts` 的公共部分）

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `width` | number | 见各图表 | SVG viewBox 宽度（非像素，实际显示尺寸由 CSS 控制） |
| `height` | number | 见各图表 | SVG viewBox 高度 |
| `color` | string | `'var(--color-primary)'` | 主色（仅 bar / line 支持；donut 走 `data[].color`） |

所有图表函数的 SVG 外层由 `svgWrap` 统一生成：

```js
`<svg class="htd-chart" viewBox="0 0 ${W} ${H}" width="100%" preserveAspectRatio="xMidYMid meet" role="img">${inner}</svg>`
```

`width="100%"` + `preserveAspectRatio` 意味着 SVG 会等比缩放填满容器宽度，高度自适应。因此**`width` / `height` 只决定长宽比与内部坐标尺度，不决定屏幕上的实际像素大小**。

### 5.4 `barChart(opts)` — 柱状图

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `data` | `Array<{label: string, value: number}>` | `[]` | 数据项。`label` 用于 X 轴文字，`value` 决定柱高 |
| `width` | number | `320` | — |
| `height` | number | `160` | — |
| `color` | string | `var(--color-primary)` | 柱体填充色 |
| `showValue` | boolean | `false` | 是否在柱顶显示数值。四个挂载页面均未开启 |

内部计算：

- 内边距 `p = { top: 10, right: 8, bottom: 26, left: 30 }`。
- 最大值 `max = Math.max(...values, 1)`，`concat([1])` 保证空数据或全 0 时不出现除零。
- 柱宽 `barW = Math.min(slot * 0.55, 40)`，`slot = chartW / n`。**上限 40** 意味着数据量极少时柱子不会撑满。
- 柱高最小值 `Math.max(bh, 0.5)` —— 值为 0 时仍画 0.5 高的残柱，避免「有桶但看不见」。
- X 轴标签经 `truncate(label, 6)` 截断为最多 6 字符（超出显示 `…`）。中文标签如「需求沟通」为 4 字不受影响，但长合同号会被截断。
- 数值格式化 `fmt(v)`：绝对值 ≥ 1000 时显示为 `x.xk`。

### 5.5 `donutChart(opts)` — 环形图

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `data` | `Array<{label: string, value: number, color?: string}>` | `[]` | **入参即被过滤**：`.filter(d => (Number(d.value) || 0) > 0)`，零值分类不渲染 |
| `width` / `height` | number | `180` / `180` | — |
| `innerRatio` | number | `0.6` | 内径 / 外径比，控制环的粗细 |
| `centerText` | string | `fmt(total)` | 圆心文字。不传时显示合计值 |

两条分支：

- **单分类**（过滤后只剩 1 项）：画一个整圆环，`stroke-width = r - inner`。避免 arc 路径在 360° 时退化。
- **多分类**：从 `-Math.PI / 2`（12 点方向）开始顺时针累加角度，每段调用 `arcPath()` 生成环形扇区路径。

扇区描边 `stroke="var(--bg-card)" stroke-width="1.5"` —— 用卡片背景色描边做分割线，因此**在半透明背景外观（Liquid Glass）下分割线颜色可能与卡片实际背景不一致**，属于已知视觉瑕疵。

`color` 取值优先级：`d.color`（后端下发的 `color` 字段）> `colorAt(i)`（色板按索引）。首页项目阶段分布与财务分类饼都依赖后端 `color` 字段。

### 5.6 `lineChart(opts)` — 折线图

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `data` | `Array<{label: string, value: number}>` | `[]` | — |
| `width` / `height` | number | `320` / `160` | — |
| `color` | string | `var(--color-primary)` | 折线与数据点颜色 |

渲染四层：基线 → 面积多边形（`fill-opacity="0.12"`）→ 折线（`polyline`，`stroke-width="2"`）→ 数据点（`circle r="2.6"`）→ X 轴文字。

Y 轴映射用 `min` 而非固定 0 起点：`span = (max - min) || 1`，`y = p.top + chartH - ((v - min) / span) * chartH`。**这会让微小波动被放大成剧烈起伏**（例如值域 [9.8, 10.2] 会被拉伸到整个绘图高度），阅读时需注意 Y 轴并非从 0 起。

数据点为 1 个时，`x` 取 `chartW / 2`（居中），`slot` 计算用 `Math.max(n - 1, 1)` 避免除零。

> **当前状态：已实现但四个挂载页面均未使用。** 全文检索 `frontend/js/modules/*.js`，`C.lineChart` 零命中。保留原因：为后续趋势类图表预留。

### 5.7 `stackedBarChart(opts)` — 堆叠柱状图

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `data` | `Array<{label: string, values: Object<string, number>}>` | `[]` | 每项一个 `values` 字典 |
| `series` | `Array<{key: string, label: string, color?: string}>` | `[]` | 堆叠层定义，顺序即自下而上的绘制顺序 |
| `width` / `height` | number | `340` / `180` | — |

计算逻辑：

1. 先求所有 `data` 项的 `values` 合计最大值 `maxTotal`（对应后端保证 `data[].values` 含全部方向键）。
2. 每根柱内自底向上游标 `yCursor`，逐层累减 `segH = (v / maxTotal) * chartH`。
3. **`if (v <= 0) return;` 跳过零值层** —— 零值不占高度也不绘制。
4. `color` 取值：`ser.color || colorAt(series.indexOf(ser))`。

与后端 `study.directionStacked` 的契约严格对应：`series[].key` ↔ `data[].values` 的键。

### 5.8 `timelineChart(opts)` — 时间线

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `items` | `Array<{label: string, date?: string, done?: boolean, color?: string}>` | `[]` | 里程碑序列 |
| `width` / `height` | number | `360` / `120` | — |

渲染：一条水平轴（`stroke-width="1.5"`） + 每节点一个 `circle r="6"` + 上方名称（`truncate(label, 8)`）+ 下方日期（`it.date` 存在时渲染）。

`done` 的视觉语义：完成时 `fill = color`（实心），未完成时 `fill = var(--bg-card)` + `stroke = color`（空心）。因此**未完成节点在半透明背景外观下会「透」出底层内容**，与 donut 描边是同一类问题。

节点间距为**等距**（`slot = chartW / n`），**不按真实日期比例分布**。里程碑之间相隔 1 天还是 3 个月，在图上间距相同。这是刻意的简化，但读图时不能据此推断工期。

### 5.9 `legend(items)` — 图例

```js
legend([{ label: '文章', color: '#5B8DEF' }])
// => '<div class="htd-chart-legend"><span class="htd-chart-legend__item">…</span></div>'
```

- 入参空数组返回空串 `''`（模板中 `v-html` 注入空串安全）。
- `color` 缺失时回落 `colorAt(0)`。
- `label` 经 `escapeHtml()` 转义。

### 5.10 空数据与转义

**空数据占位**：所有图表函数在 `data.length === 0`（或 `stackedBarChart` 的 `series.length === 0`）时，返回 `emptySvg(W, H, text)`，即一张居中显示占位文字的 SVG。占位文案各图表不同：

| 图表 | 空数据文案 |
| --- | --- |
| `barChart` / `donutChart` / `lineChart` / `stackedBarChart` | `暂无数据` |
| `timelineChart` | `暂无里程碑` |

**HTML 转义**：`escapeHtml()` 处理 `&` `<` `>` `"` 四个字符，应用于所有图表的文字标签（`label`、`centerText`、图例 `label`）。**数值不经过转义**（由 `fmt()` 或 `toFixed()` 产出，只能是数字与 `k` 后缀）。颜色值**不经过转义**——当前所有 `color` 均来自后端硬编码色板或固定常量，不含用户输入，因此安全；若将来开放用户自定义配色，必须先做白名单校验。

## 6. 完整渲染链路

从数据到屏幕共四段，任何一段失败都会导致图表区整块不渲染（而非报错）。

```
① 后端聚合        ② store 拉取        ③ computed 生成 SVG    ④ 模板 v-html
system.service  →  dataStore       →  Vue.computed         →  DOM 注入
getCharts()        fetchCharts()      C.barChart({...})       <div v-html="xxxSvg">
                   htdApi.get()       window.htdCharts
```

### 6.1 ① 后端聚合

`system.service.js#getCharts()` 一次性返回 `{home, study, finance}` 三类 11 个数据集。前端三个页面调用的是**同一个接口、同一份全量数据**，各自只消费自己需要的部分。这意味着：进入财务页也会把学习习惯数据一并拉回来（反之亦然）。当前数据量下可接受；若后续数据集膨胀，应按页面拆分端点或支持 `?domains=finance` 之类的裁剪。

### 6.2 ② store 拉取

`frontend/js/store/dataStore.js`：

```js
async fetchCharts() {
  return htdApi.get('/system/charts');
},

// 拉取项目详情图表（V1.5 §8.1）：里程碑时间线 + 任务速率
async fetchProjectCharts(projectId) {
  return htdApi.get('/system/project-charts', { projectId });
},
```

两个方法**不做缓存、不做状态托管**，纯粹是 API 转发；结果由调用方页面自己存在组件内的 `Vue.ref` 中。因此首页 ↔ 学习页 ↔ 财务页之间切换会**重复请求同一个 `/system/charts`**。

### 6.3 ③ computed 生成 SVG

以 `HomePage.js` 为例：

```js
const C = window.htdCharts;
const charts = Vue.ref(null);
async function loadCharts() {
  try { charts.value = await dataStore.fetchCharts(); }
  catch (e) { console.error('加载图表失败:', e); }
}
Vue.onMounted(loadCharts);

const weekTrendSvg = Vue.computed(() => {
  if (!charts.value) return '';
  const data = charts.value.home.weekCompletionTrend.map((d) => ({ label: d.label, value: d.completed }));
  return C.barChart({ data, height: 150, showValue: false });
});
```

三个稳定特征：

1. `charts` 初始为 `null`，所有 computed 首行 `if (!charts.value) return ''`，保证数据到达前注入空串。
2. 后端数据集字段 → 图表 `{label, value}` 的**映射发生在 computed 里**（如 `value: d.completed`、`value: d.value`），后端字段命名不必迁就图表库。
3. `loadCharts()` 内 `console.error` 后不抛出，`charts` 保持 `null`，模板 `v-if="charts && charts.home"` 不渲染图表区——**图表拉取失败对用户完全静默**，页面其余部分正常工作。

### 6.4 ④ 模板 v-html 注入

```html
<div v-if="charts && charts.home" class="home-charts" style="display:grid;grid-template-columns:repeat(auto-fit,minmax(320px,1fr));…">
  <div class="home-card">
    <div class="home-card__title">本周完成趋势</div>
    <div class="home-chart" v-html="weekTrendSvg"></div>
  </div>
  …
</div>
```

`v-html` 是这里唯一的注入点。`charts.js` 内部对所有文本标签做了 `escapeHtml()`，后端下发的 `label` / `date` 来自用户输入的字段（如 `habit.name`、`contractNo`、`techDirection`）都经过该函数，因此不存在 XSS 通路。**新增图表函数时必须沿用 `escapeHtml()`**，不能直接拼接未转义的用户数据。

## 9. 已知限制与后续演进

### 9.1 已知限制

| 编号 | 限制 | 说明 |
| --- | --- | --- |
| C1 | **图表零交互** | 无 tooltip、无 hover 高亮、无点击下钻。想知道具体数值只能靠 `showValue`（当前全站未开启）或圆心文字 |

| C10 | **静默失败** | 图表拉取失败仅 `console.error`，用户无任何提示，图表区直接消失 |
| C11 | **`monthlyIncomeExpense` 丢弃窗口外数据** | 早于 6 个月前的记录不进图表，与「趋势」语义一致但易被误解为数据丢失 |
