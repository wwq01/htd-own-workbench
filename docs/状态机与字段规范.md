# 状态机与字段规范（V1.3）

> **适用范围**：V1.3 落地的三套状态机（任务 5 态 / 项目 6 阶段 / 复盘 3 态）+ 通用状态机工厂。
> **定位**：本文件是「换 AI 也能接手」的宪法级文档之一。凡是新增/修改状态迁移，必须先改本文件对应的迁移表，再改代码，再补测试。
>
> 字段规范（每个业务模块的字段、枚举、Zod 校验）以 `backend/src/common/constants/enums.js` 与 `backend/src/modules/<module>/*.schema.js` 为唯一事实来源；本文件只描述「状态迁移」维度。

## 1. 通用状态机工厂

落地文件：`backend/src/lib/stateMachine.js`（V1.3 正式落地，替代散落在各 service 的 if/else 校验）。

```js
import { createStateMachine } from '../common/stateMachine.js';

const sm = createStateMachine({
  name: 'TodoStatus',                 // 用于错误文案定位
  initial: 'pending',                 // 初始态（文档性，工厂不强约束首条记录初始值）
  ALLOWED_TRANSITIONS: {              // 合法迁移白名单：from -> [to, ...]
    pending: ['in_progress', 'delayed', 'cancelled', 'completed'],
    // ...
  },
  onTransition: async (from, to, payload) => {  // 可选：迁移钩子（写历程表/触发联动）
    await prisma.projectPhaseTransition.create({ data: { /* ... */ } });
  },
});

// 用法
sm.isAllowed(from, to);                       // boolean（from===to 恒为 true）
await sm.transition(from, to, payload);       // { ok:true, from, to } 或抛 BusinessError
```

### 1.1 关键语义

| 行为 | 说明 |
| --- | --- |
| **自环**：`from === to` | 工厂层恒为合法（`isAllowed` 直接 return true），**即使 `ALLOWED_TRANSITIONS[from]` 数组里没写自身**。例如项目阶段 `项目结项` 的数组是 `['需求沟通']`（无自身），但 `项目结项 → 项目结项` 在工厂层仍判合法。穷举测试时合法数会比「数组元素之和」多 1，属正常现象。 |
| **非法迁移** | 抛 `BusinessError(ErrorCodes.PARAM_ERROR)`，文案：`${name}：非法状态迁移「${from} → ${to}」`。 |
| **未知状态** | `ALLOWED_TRANSITIONS` 上没有 `from` 键时抛 `参数错误：${name}：未知状态「${from}」`。 |
| **调用方** | service 不直接手写校验分支，统一 `const sm = createStateMachine({...}); await sm.transition(...)`。 |

> 注意：错误码是 `PARAM_ERROR`（白皮书 §5.3e.4 曾设想 `DETECT.STATE_MACHINE.INVALID_TRANSITION`，实际落地为 `PARAM_ERROR`，以 `enums.js` / `error.js` 当前导出为准）。

## 2. 任务 5 态状态机（`TODO_STATUS_TRANSITIONS`）

枚举（值用英文串，兼容旧数据 `pending` 语义等同 `NOT_STARTED`）：

```js
export const TODO_STATUS = {
  NOT_STARTED: 'pending', IN_PROGRESS: 'in_progress', COMPLETED: 'completed',
  CANCELLED: 'cancelled', DELAYED: 'delayed',
};
```

### 2.1 完整迁移矩阵（5×5 = 25，合法 18 / 非法 7）

| from ↓ \ to → | pending | in_progress | delayed | completed | cancelled |
| --- | --- | --- | --- | --- | --- |
| **pending** | ✅自环 | ✅ | ✅ | ✅ | ✅ |
| **in_progress** | ✅ | ✅自环 | ✅ | ✅ | ✅ |
| **delayed** | ❌ | ✅ | ✅自环 | ✅ | ✅ |
| **completed** | ✅ | ❌ | ❌ | ✅自环 | ❌ |
| **cancelled** | ✅ | ❌ | ❌ | ❌ | ✅自环 |

`ALLOWED_TRANSITIONS` 原文：

```js
export const TODO_STATUS_TRANSITIONS = {
  pending:       ['in_progress', 'delayed', 'cancelled', 'completed'],
  in_progress:   ['completed', 'delayed', 'cancelled', 'pending'],
  delayed:       ['in_progress', 'cancelled', 'completed'],
  completed:     ['pending'],
  cancelled:     ['pending'],
};
```

> 合法数核验：数组元素之和 = 4+4+3+1+1 = 13（非自环），加 5 个自环 = **18 合法**；25 − 18 = **7 非法**。✅ 与 `todo-statemachine.test.js` 穷举断言一致。

### 2.2 延期语义（`delayTodo`）

- `pending` / `in_progress` → `delayed`：除切状态外，**顺延 `todoDate`**（指定 `toDate` 用指定值；否则 `date.tomorrow()` 顺延一天）。
- `completed` → 延期：**非法**，业务层抛「已完成的任务不能延期」。
- `delayed` → `in_progress`（或任意合法目标）：离开延期态时**清空 `delayedUntil` 字段**。
- 老数据迁移：V1.2 的 3 态 → V1.3 的 5 态，`delayedUntil` 统一置 `NULL`。

示例迁移 SQL（示意，实际以 `prisma/migrations/V1.3.0-task-5status/migration.sql` 为准）：

```sql
-- 历史任务无 delayedUntil 列，新增并默认 NULL
ALTER TABLE "Todo" ADD COLUMN "delayedUntil" TIMESTAMP(3);
UPDATE "Todo" SET "delayedUntil" = NULL WHERE "delayedUntil" IS NULL;
-- 旧 status 值 'not_started' 映射为 'pending'（如有）
UPDATE "Todo" SET "status" = 'pending' WHERE "status" = 'not_started';
```

### 2.3 测试覆盖

`backend/src/modules/todo/todo-statemachine.test.js`：
- 穷举 5×5 迁移矩阵（合法 18 / 非法 7），逐条断言 `changeStatus` 结果或抛错。
- 4 条延期用例：`pending→delayed` 顺延指定日 / `in_progress→delayed` 顺延明天 / `completed` 延期被拒 / `delayed→in_progress` 清空 `delayedUntil`。

## 3. 项目 6 阶段状态机（`PROJECT_PHASE_TRANSITIONS`）

枚举（值为中文串，与现有 `PROJECT_PHASE` 对齐）：

```js
export const PROJECT_PHASE = {
  REQUIREMENT: '需求沟通', PROPOSAL: '方案撰写', POC: 'POC演示',
  BIDDING: '投标答辩', DELIVERY: '交付跟进', CLOSED: '项目结项',
};
```

### 3.1 完整迁移表（6 阶段，含自环）

| from ↓ \ to → | 需求沟通 | 方案撰写 | POC演示 | 投标答辩 | 交付跟进 | 项目结项 |
| --- | --- | --- | --- | --- | --- | --- |
| **需求沟通** | ✅自环 | ✅ | ✅ | ❌ | ❌ | ✅ |
| **方案撰写** | ❌ | ✅自环 | ✅ | ✅ | ❌ | ✅ |
| **POC演示** | ❌ | ❌ | ✅自环 | ✅ | ✅ | ✅ |
| **投标答辩** | ❌ | ❌ | ❌ | ✅自环 | ✅ | ✅ |
| **交付跟进** | ❌ | ❌ | ❌ | ❌ | ✅自环 | ✅ |
| **项目结项** | ✅ | ❌ | ❌ | ❌ | ❌ | ❌（工厂自环仍合法） |

`ALLOWED_TRANSITIONS` 原文：

```js
export const PROJECT_PHASE_TRANSITIONS = {
  '需求沟通': ['方案撰写', 'POC演示', '项目结项', '需求沟通'],
  '方案撰写': ['POC演示', '投标答辩', '项目结项', '方案撰写'],
  'POC演示':  ['投标答辩', '交付跟进', '项目结项', 'POC演示'],
  '投标答辩': ['交付跟进', '项目结项', '投标答辩'],
  '交付跟进': ['项目结项', '交付跟进'],
  '项目结项': ['需求沟通'],          // 结项后可「重开」回需求沟通
};
```

> 合法数核验：数组元素之和 = 4+4+4+3+2+1 = 18（其中含 5 个显式自环）；外加 `项目结项→项目结项` 由工厂隐式允许 = **19 合法**；36 − 19 = **17 非法**。✅ 与 `project-statemachine.test.js` 断言完全一致。

### 3.2 硬约束：`onTransition` 必写阶段历程

每次阶段切换（`changePhase(id, to, reason)`）**必须**写一条 `ProjectPhaseTransition` 记录（`id / projectId / fromPhase / toPhase / reason / createdAt / createdBy`）。非法迁移在状态机层即被拦截，**不会产生历程记录**。

### 3.3 结项钩子

`交付跟进 → 项目结项` 成功时，`onTransition` 调用 `ReviewService.autoGenerateFromProject(projectId)` 自动生成一条 `type='project'` 的复盘草稿（DRAFT）。

### 3.4 测试覆盖

`backend/src/modules/project/project-statemachine.test.js`：
- 穷举 6×6 矩阵（合法 19 / 非法 17）。
- 13 条合法非自环迁移：断言 `phase` 更新 + `ProjectPhaseTransition` 记录存在且 `reason` 正确。
- 结项钩子：`交付跟进 → 项目结项` 后 `review` 表新增一条 `type='project'`。
- 17 条非法迁移：逐条 `changePhase` 抛错。

## 4. 复盘 3 态状态机（`REVIEW_STATUS_TRANSITIONS`）

枚举：

```js
export const REVIEW_STATUS = { DRAFT: 'draft', SUBMITTED: 'submitted', PRECIPITATED: 'precipitated' };
```

### 4.1 迁移表（线性不可逆）

| from ↓ \ to → | draft | submitted | precipitated |
| --- | --- | --- | --- |
| **draft** | ✅自环 | ✅ | ❌ |
| **submitted** | ❌ | ✅自环 | ✅ |
| **precipitated** | ❌ | ❌（回退非法） | ✅自环 |

```js
export const REVIEW_STATUS_TRANSITIONS = {
  draft:       ['submitted'],
  submitted:   ['precipitated'],
  precipitated: [],
};
```

> 合法非自环只有 **2 条**：`draft→submitted`、`submitted→precipitated`。跳步（`draft→precipitated`）与回退（`precipitated→submitted`）均非法。

### 4.2 操作流（服务只暴露两个固定目标动作）

| 动作 | 入口 | 迁移 | 联动 |
| --- | --- | --- | --- |
| **提交** `submit(id)` | 复盘页「提交」按钮 | `draft → submitted` | 自动调 `VaultService.autoCreateFromReview({ sourceType, reviewId, ... })` 生成 Vault DRAFT 草稿（幂等，已存在则跳过） |
| **生成沉淀** `precipitate(id)` | 提交后「生成沉淀」 | `submitted → precipitated` | 调 `VaultService.markPrecipitatedBySource(sourceType, reviewId)` 将关联 Vault 置 `PRECIPITATED` |

> 服务**不**提供 `transition(status, to)` 任意目标接口——只暴露 `submit` / `precipitate` 两步固定动作，从调用层面杜绝跳步。

### 4.3 测试覆盖

`backend/src/modules/review/review-statemachine.test.js`：
- `submit`：`draft→submitted` 成功，且 `vaultItem` 新增一条 `status='DRAFT'`、`sourceId=reviewId`。
- `precipitate`：`submitted→precipitated` 成功，关联 Vault 置 `PRECIPITATED`。
- 非法：`precipitated` 再 `submit` 被拒；`draft` 直接 `precipitate` 被拒。
- 穷举 3×3 矩阵与 `REVIEW_STATUS_TRANSITIONS` 定义对齐。

## 5. 新建状态机标准步骤（含测试模板）

新增一套状态机（如「漏洞跟踪状态」）必须走完以下步骤，缺一视为未完成：

1. **写枚举**：在 `backend/src/common/constants/enums.js` 增加 `XXX_STATUS` 常量（值用英文串）。
2. **写 `ALLOWED_TRANSITIONS`**：同一文件增加 `XXX_STATUS_TRANSITIONS`（from → [to,...]）。自环无需写进数组（工厂隐式允许）。
3. **注册 service**：在对应 `*.service.js` 内 `createStateMachine({ name, ALLOWED_TRANSITIONS, onTransition })`，所有状态变更统一经 `sm.transition(...)`；非法迁移由工厂抛 `PARAM_ERROR`，service 不再手写分支。
4. **写迁移测试**：
   - 至少 **2 条合法迁移**（含一条带 `onTransition` 副作用断言）；
   - 至少 **1 条非法迁移**（`rejects.toThrow()`）；
   - 推荐额外做「穷举矩阵」断言（如 `validCount === N && invalidCount === M`），防止后续有人改错白名单。
5. **登记文档**：在本文件 §2~§4 对应位置追加新状态机的迁移矩阵表。

### 5.1 测试模板（Vitest + 测试库隔离）

```js
import { createStateMachine } from '../../lib/stateMachine.js';
import { XXX_STATUS_TRANSITIONS } from '../../common/constants/enums.js';

it('穷举矩阵：合法 N / 非法 M', () => {
  const sm = createStateMachine({ name: 'XxxStatus', ALLOWED_TRANSITIONS: XXX_STATUS_TRANSITIONS });
  let valid = 0, invalid = 0;
  for (const from of Object.keys(XXX_STATUS_TRANSITIONS)) {
    for (const to of Object.keys(XXX_STATUS_TRANSITIONS)) {
      if (sm.isAllowed(from, to)) valid++; else invalid++;
    }
  }
  expect(valid).toBe(N); expect(invalid).toBe(M);
});

it('合法迁移带钩子', async () => {
  const sm = createStateMachine({ name: 'XxxStatus', ALLOWED_TRANSITIONS: XXX_STATUS_TRANSITIONS,
    onTransition: async (f, t) => { /* 写历程/触发联动 */ } });
  const r = await sm.transition('a', 'b');
  expect(r.ok).toBe(true);
});

it('非法迁移抛 PARAM_ERROR', async () => {
  const sm = createStateMachine({ name: 'XxxStatus', ALLOWED_TRANSITIONS: XXX_STATUS_TRANSITIONS });
  await expect(sm.transition('a', 'z')).rejects.toThrow();
});
```
