### 0.2 最严重问题 Top 5（按影响排序）

1. **两套外观的"材质差"未真正发生**（§2，最高优先级）：`notion-flat` 仅重映射 `--glass-*` 令牌，而 **`--bg-card` 未被重映射**。全站几乎所有卡片/外壳/列表/弹窗用的是 `--bg-card`（半透明白），在 `notion-flat` 下仍是玻璃态 → Notion 极简外观 ≈ Liquid Glass 去掉模糊，视觉目标未达成。
2. **三套主蓝不统一**（§1.2/§5.2）：`#5B8DEF`（默认主色）/ `#3B82F6`（Logo·工作组·投标·进行中态）/ `#3D6EFF`（下拉勾选图标），外加图表调色板 `#60A5FA` 等，品牌色已断裂。
3. **图表配色暗色失效（P0-2）**（§5.1）：`charts.js` 调色板为硬编码 hex，调用方用裸 hex 覆盖 `var(--color-primary)` 默认值，导致暗色/多外观下图表不跟随主题。
4. **硬编码色值逃逸弥散**（§1.4）：主蓝阴影、玻璃白、标签文字色、选中勾选色等以裸值散落，违背宪法 §3.1「令牌驱动」硬规则。
5. **三套并行图标定义**（§4.2 / P2-3）：`icons.js` / `NAV_ITEMS` 内联 path / `HtpCommandPalette` 私有 `ICON`（搜索图标一处定义三次）。命令面板缺失 10 个模块入口。

## 2. 两套外观一致性审计（Liquid Glass vs Notion 极简平铺）

### 2.1 三维主题模型回顾

`theme-manager.js` 仅切换 `<html>` 三属性：`data-appearance`(liquid-glass\|notion-flat) × `data-theme`(dark\|light) × `data-decoration`(on\|off)。组件 CSS 零改动，靠 `global.css` 的令牌覆盖层自动生效。理念正确（ADR-v14-01：外观是表面材质差异而非配色差异）。

### 2.2 核心缺陷：外观切换的「材质差」未真正发生

`notion-flat` 暗色覆盖层（global.css:582-609）仅重映射了 **`--glass-*` 系列**与 `--bg-spot*/--bg-gradient/--bg-deepest/--radius-*/--spacing-base/--shadow-modal/dropdown`。**它遗漏了 `--bg-card`、`--bg-page`、`--bg-hover`、`--bg-tertiary`**——而全站绝大多数表面正是用 `--bg-card`。

逐组件核对（`notion-flat` 下实际值）：

| 组件 | 使用令牌 | notion-flat 暗色下实际值 | 是否变实色 |
|---|---|---|---|
| `.htp-card` | `--bg-card`(rgba白0.10) | **仍半透明白玻璃** | ✗ |
| `.htp-modal` | `--bg-card` | 仍玻璃 | ✗ |
| `.htp-filter-bar` / `.htp-tabs` | `--bg-card` | 仍玻璃 | ✗ |
| `.cmd-palette` | `--bg-card` | 仍玻璃 | ✗ |
| `.app-sidebar` / `.app-main` / `.app-topbar` | `--bg-card` + 硬编码 `rgba(255,255,255,0.04)` | 仍玻璃（顶栏硬编码白底不变） | ✗ |
| `.stat-card`/`.home-card`/`.project-card`/`.review-card`/`.secret-card`/`.deploy-card`/`.todo-list-item`/`.list-container`/`.htd-chart-card`/`.data-stat-card`/`.backup-list__item`/`.htd-pagination__btn` | `--bg-card` | **全部仍玻璃** | ✗ |
| `.htp-input` / `.htp-select__trigger` | 硬编码 `rgba(255,255,255,…)` | 仍玻璃 | ✗ |
| `.htp-btn--secondary` | `--glass-bg`(已重映射 #1E293B) | 实色 ✓ | ✓（唯一真正切换的） |

**结论**：`notion-flat` 当前几乎只做了「关模糊 + 背景墙改实色 + 圆角收敛」，而占屏幕绝大多数的**卡片/外壳表面仍是半透明白玻璃**，视觉上 ≈ Liquid Glass 去掉 backdrop-filter。Notion 极简的「实色平铺」目标**未达成**，两套外观的差异度被严重低估。

### 2.3 输入/选择控件在 notion-flat 下仍玻璃

`.htp-input`、`.htp-textarea`、`.htp-select__trigger` 的底/边是硬编码 `rgba(255,255,255,…)`，连 `--glass-*` 都没用，故 `notion-flat` 完全无法接管 → 输入框在极简外观下仍是白玻璃描边，与实色面板格格不入。

### 2.4 顶部栏硬编码白底

`pages.css:145` `.app-topbar { background-color: rgba(255,255,255,0.04) }` 硬编码，暗/亮/两外观下均不变，且 `notion-flat` 下与实色外壳产生违和。

### 2.5 修复方向（详见 §7.2）

将 `--bg-card`（及 `--bg-page/--bg-hover/--bg-tertiary`）与 `--glass-bg` **收口为单一语义表面令牌 `--surface` / `--surface-raised`**；`notion-flat` 仅需重映射这一层即可让所有表面同时转实色。同时新增 `--field-bg`/`--field-border` 供输入控件接管。

### 5.1 图表配色暗色失效（P0-2）— 确认根因

## 6. V2.0 视觉新需求设计语言草案

> 前提（《V2.0-重构方向.md》D1 已裁定）：知识图谱 1k 节点流畅 = 硬需求 → 方向 B（Vite 构建化）必须执行；图表机制从「SVG 字符串 + `v-html`」改为「真实 Vue 组件 + 响应式 SVG/Canvas + d3-force」。**以下设计语言均面向该机制，且全部走 design token，零硬编码色**。

### 6.1 知识图谱（力导向 / 关系图）

- **渲染**：Vue 组件 + `d3-force` 计算布局，节点/边以响应式 SVG `<g>`（≤150 节点）或 Canvas（≥150 / 1k 节点）绘制；避免每帧重拼字符串。性能门槛：中间 ≥30fps、验收 ≥60fps（先做 demo 验证再上业务）。
- **节点 token 草案**：
  - `--graph-node-fill: var(--surface-raised)`、`--graph-node-stroke: var(--border-default)`
  - `--graph-node-label: var(--text-secondary)`、`--graph-node-radius: var(--radius-full)`
  - 类型色：`--graph-node-type-entity/--graph-node-type-tag/--graph-node-type-ref`（复用 `--tag-*` 语义，暗/亮各一套）
  - 选中/ hover：`--graph-node-active-stroke: var(--color-primary)`、`--graph-node-active-glow: var(--focus-ring)`
- **边 token**：`--graph-edge: var(--border-default)`、`--graph-edge-active: var(--color-primary)`、`--graph-edge-width: 1px`（Canvas 下用等同 px）。
- **布局/交互**：力导向初算后用 `transform` 平移（不重排）；hover 高亮邻接（边/节点加 `--graph-*-active`）；点击聚焦节点并侧栏展示详情（复用 `htp-card`）；缩放/平移用 `wheel` + `drag`，动效遵循 `var(--transition-base)` 与 reduced-motion 降级；空图（无关系）走 `.htp-empty` 范式。
- **暗/亮适配**：节点填充取 `--surface` 系（暗色深、亮色浅），标签取 `--text-*`，保证对比度 ≥4.5:1；不引入新裸色。

### 6.2 本地 Agent 协作界面（inbox / 任务流）

- **inbox（收件箱）**：单列时间线卡片流，复用 `htp-card` + `.list-container` 范式；每条含「来源（agent 名 + 头像占位）→ 意图摘要 → 操作（采纳/拒绝/追问）」；状态点复用 `StatusDot`（pending/in_progress/done）；空态走 `.htp-empty`。
- **任务流（task-flow）**：步骤条用横向 `htp-progress` 派生或新增 `--agent-step-*` 令牌（圆点 + 连线 + 当前高亮 `var(--color-primary)`）；长任务进度复用 `--htp-progress__bar`（主色填充 + 阴影）。
- **视觉纪律**：Agent 内容区与人工内容区用**发丝边框 + 微弱 `--color-primary` 左侧条**区分（避免「侧条纹边框」禁令——此处为语义区分且 ≤1px、非装饰强调，合规）；不引入独立于既有令牌的新配色。

### 6.3 Tauri 原生壳视觉衔接（窗口 / 托盘 / 通知）

- **窗口**：WebView 指向 `127.0.0.1:17388`（方案 a，业务代码 0 改动），外壳 chrome 由 Tauri 绘制；窗口圆角/标题栏色取 `--bg-deepest` 系，使 WebView 内容与系统标题栏无缝。
- **托盘（tray）**：图标走 `icons.js` 的 `app`/`tray` 键（单色 SVG，Tauri 转 PNG/模板图）；菜单项 styling 跟随系统，但强调色对齐 `--color-primary`。
- **通知（notification）**：原生通知无法用 CSS，但**品牌色与图标**沿用 `--color-primary` 与 `icons.js` 键；应用内 Toast（`.htd-toast`）已令牌化，原生壳下保持一致语义色（success/danger/warning）。
- **离线/本地优先**：所有视觉资源内联或随 `dist/` 分发，无外链字体（沿用 Sarasa 本地托管）。

5. 增加 `scripts/validate-theme.js`（宪法 §3.2）：校验 `notion-flat` 下「所有 surface 令牌均为不透明实色」「无 `rgba(255,255,255` 裸值残留」。

## 结论

当前视觉系统**红线层面健康**（无 emoji 图标、无紫粉渐变、无弹跳缓动、无 AI 模板味），且三维主题模型与令牌基建方向正确。但存在两类必须修复的系统性债：

1. **令牌未贯穿到底**：组件层大量裸 `rgba(91,141,239)` / `rgba(255,255,255)` / 裸 hex 逃逸，导致双主题不对称、三蓝断裂、图表暗色失效。需通过「基础/语义/组件三层 + 单一 surface 令牌 + 图表色令牌」彻底收口。
2. **两套外观名不副实**：`notion-flat` 因 `--bg-card` 未重映射，仅去掉模糊而未转实色，与 Liquid Glass 视觉差被严重低估。修复成本极低（重映射 `--color-surface*` 一层），但价值高（真正达成「表面材质差异」的设计意图）。

V2.0 的知识图谱 / 本地 Agent / Tauri 原生壳三块新需求，应在上述令牌地基之上定义设计语言（节点/边/表面/强调全部走 token），避免在新机制上重复堆积硬编码色。
